## Requirement

- **Statement:** When a follow-up request asks for a design change, the system changes the size, the spacing and the position of what the request names on the slides in scope, and uses colours and fonts only from the theme of the deck. Each changed slide keeps its information, figures and meaning, and the slide count and order stay as they were unless the request asks otherwise. For a colour or a font the theme does not hold, the system uses nothing new, says so and names the ones the theme holds.
- **Status:** confirmed
- **Why:** DEC-005: the model changes the deck source within the template and the theme, so a free design change works and the deck stays inside its design system.

## Notes

- Rewritten from legacy FR-107, where the model changed the design directly with no bound on colours and fonts, and a visual style was a second source of design rules (visual style: reviewed with legacy UC-017).
- Legacy FR-108 (a design that cannot fit the content) is merged here: a design change removes no content to make it fit; a slide that does not fit stays unfinished (FR-092).
