## Requirement

- **Statement:** When a follow-up request asks for a design change, the system changes the size, the spacing, the position or the layout of what the request names on the slides in scope, with a layout of the template or a new one when none fits, and takes each colour and font it chooses itself from the theme of the deck. Each changed slide keeps its information, figures and meaning, and the slide count and order stay as they were unless the request asks otherwise. For a colour or a font the theme does not hold, the system makes the rest of the change and asks whether to use it only where the request names it or to put it in the theme of the deck in place of the theme value whose role it fits best, naming that role, with both as suggested answers.
- **Status:** confirmed
- **Why:** DEC-005 and DEC-007: the model changes the deck source from the template and the theme, so a free design change works, the deck keeps its design system, and the choice of the user wins.

## Notes

- Rewritten from legacy FR-107, where the model changed the design directly with no bound on colours and fonts, and a visual style was a second source of design rules (visual style dropped in the legacy UC-017 review, 05-11-2026). A request that asks slides not to follow a rule in words of the design system is FR-136.
- Legacy FR-108 (a design that cannot fit the content) is merged here: a design change removes no content to make it fit; a slide that does not fit stays unfinished (FR-092).
- Owner rulings of 05-11-2026 ([DEC-007](../../../decisions/DEC-007-how-a-design-system-bounds-the-deck.md)): a request is allowed to ask for another layout of a slide; a colour or a font the user asks for is never refused (2C); one put in the theme of the deck changes no design system (a design system is changed in UC-010).
- Owner ruling of 05-11-2026 (legacy UC-017 review, 7A): a colour or a font put in the theme of the deck takes the place of a theme value with a role, such as the accent colour; it never stands beside them with no role, so the model always knows what each value of the theme is for.
