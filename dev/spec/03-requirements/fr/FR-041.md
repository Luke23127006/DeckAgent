id: FR-041
title: "Save a provider configuration after the provider accepts its key"
updated: 05-11-2026
---

## Requirement

- **Statement:** The system checks the connection and the key with the provider, and saves the provider configuration only when the provider accepts the key. When the provider refuses the key or does not answer, the system saves nothing, says which, and why when it knows, and keeps the rest of what the user gave. Each provider ID has at most one saved provider configuration and never changes after saving; a save with a provider ID that a saved provider configuration or a built-in provider has saves nothing and says which one has it [BR-008].
- **Status:** confirmed

## Notes

- Changed vs legacy: the legacy spec checked the key at save only sometimes; the owner ruled on 05-11-2026 that the key is always checked before saving. A provider that does not answer is treated as a refusal, so no provider configuration is saved without a connection (orchestrator check, 05-11-2026).
- Legacy FR-057 (display name apart from the provider ID) and FR-061 (one provider configuration per provider ID that never changes it) are merged here. Display-name rules are dropped.
