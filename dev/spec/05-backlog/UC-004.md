## What it is

The user wants a deck outside DeckAgent: its source, to keep working on it in their own
tools, or fixed pages or images to keep, send, print or present. The deck in the chat
stays as it is.

Requirements only this use case would cite, from the legacy spec:

- FR-118, export the source: one archive [BR-012] with the source of the deck, its assets
  and what is needed to use it outside DeckAgent, with no working record of DeckAgent and
  no saved credential [NFR-006].
- FR-119, export the slides as static files: PDF with one page per finished slide, or one
  PNG or JPEG image per slide; no presenter notes; animations do not work.
- FR-120, keep content and layout: the export changes no slide and names each limit of
  the chosen output before it gives a file; an output that loses important information
  gives no file.
- FR-121, export a stable state: only when no request is active and at least one slide
  is finished; the whole deck in its last finished version, a partial deck named as
  partial.
- FR-122, a failed export: no incomplete file, no change of the deck, a new attempt from
  the state at its start; an export calls no model.
- BR-012, output kinds: ZIP for the source; PDF, PNG and JPEG for static files.
- NFR-015, visual fidelity: each page or image keeps the content, order and layout of its
  slide as the deck canvas shows it, with no text cut off and no image missing.
- The destination the user chooses is FR-085, shared with UC-016.

Legacy flows: a request is active; export fails; reload or come back; some content is not
kept; the file name is taken; no destination chosen; a partial first draft; no finished
slide; a partially edited deck; retry after a failed export.

## Belongs to

None.

## Why parked

The PO does not build export now, and keeps it for later instead of dropping it. What
each generation format supports for export and for changes by hand is not decided.

## Reconsider when

## Findings

- PO ruling of 05-11-2026: each generation format states what it supports; export gives
  the source, PDF or images and never changes the format. A change of format is a new
  deck in a new chat (UC-001), and the interview says what the format gains and loses.
  The plan was to record this as DEC-008 in this review.
- [DEC-006](../../decisions/DEC-006-where-chat-work-is-kept.md) keeps the deck source in
  DeckAgent's own data (ruling A). Its option C, a copy of the deck source into the project
  folder on request, is a kind of export.
- Earlier states of a deck (UC-008 in the backlog) and exported files are both copies of
  the deck source; say how they relate.
- The path "a second deck from my deck" (legacy UC-011, retired) attaches an exported file
  as material. `BR-001` accepts ZIP but no HTML, so an HTML deck is attachable only as a
  ZIP.
- Carrying on with an exported deck is in the backlog (UC-019); read it together.
- Questions for the TA: which generation formats come first; whether PPTX editable in
  PowerPoint is needed or PDF is enough.

## Decided

PO, 05-11-2026, in the check of legacy UC-008: export and changes by hand go to the
backlog.
