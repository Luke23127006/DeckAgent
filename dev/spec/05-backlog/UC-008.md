## What it is

The user changed the deck and likes the result less than before. They see the earlier
states of the deck, look at one without changing the current deck, and make it the
current deck again, in the same chat. A state is the deck as it was at one moment.

Legacy flows: no earlier state; compare a state with the current deck; keep the current
deck; a state that cannot be shown. The legacy file cites no FR; every response was `FR-?`,
and when a state is kept was `BR-?`.

## Belongs to

None.

## Why parked

The PO does not build going back to an earlier state now, and keeps it for later instead
of dropping it.

## Reconsider when

Not set by the PO.

## Findings

- The legacy Note 5 says a finished request is not undone, yet going back to the state
  before a request takes that request back. The two must be settled together.
- OpenCode undo removes the last user message, every later response and their file
  changes, and redo restores them. The legacy flow kept every message instead. See the
  research item.
- open-design documents no current way to see or restore an earlier version.
- Questions the review left open, each with the agent's proposal (not decided):
  - When is a state kept? Proposal: after each request that changed the deck, also one
    that stopped or failed after a slide changed, and after each going back.
  - What happens to later states and to the conversation? Proposal: going back makes a
    new state; later states and every message stay; the conversation says which state
    the deck went back to.
  - Compare with the current deck? Proposal: name the slides changed, added or removed,
    with no model call.
  - What goes back? Proposal: the whole deck with its presenter notes and theme; the
    confirmed outline, the conversation and the generation format stay.
  - While a request is active? Proposal: looking at a state is allowed, going back is not.
  - A request that asks in words to go back? Proposal: no slide changes; the response names
    the matching state.
  - Does a change by hand (legacy UC-007) make a state, and is its undo the same behavior?
  - Where states are kept follows [DEC-006](../../decisions/DEC-006-where-chat-work-is-kept.md);
    whether OpenCode snapshots serve is runtime research.
