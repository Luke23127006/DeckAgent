## Rule

- **Statement:** The rule sets which built-in providers a provider configuration connects to, which API protocols a custom model API uses, which models the user adds, and which added models are selectable models. The provider ID of a built-in provider is the same in every release.
- **Status:** confirmed

## Values

### V-1 · Built-in providers offered

- **Value:** Closed list: OpenAI, Anthropic, Google Gemini, DeepSeek.

### V-2 · Models the user adds

- **Value:** Open list: each model in the model catalog of the provider, and each model ID the user gives by hand, also one the catalog does not hold.

### V-3 · Selectable models

- **Value:** Each added model of each saved provider configuration.

### V-4 · API protocols of a custom model API

- **Value:** Closed list: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google Gemini.

### V-6 · Provider ID of each built-in provider

- **Value:** OpenAI `openai`, Anthropic `anthropic`, Google Gemini `google`, DeepSeek `deepseek`.

## Notes

- V-5 (default models of a built-in provider) is retired with the restore flow; V-5, V-7 and V-8 are not reused.
- A model service on the user's computer works as a custom model API; it is not a built-in provider.
