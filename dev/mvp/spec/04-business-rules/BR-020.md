---
id: BR-020
title: "Names refused for a workspace"
---

## Rule

- **Statement:** The **names that the system refuses for a workspace**, compared **after the name is normalized to NFC** and, for a name the user gives, **after the whitespace at both ends is dropped** (V-3).
- **Status:** confirmed
- **Why:** A name with **no character** cannot be **told apart in the list**; a **very long name** breaks the list.

## Values

### V-1 · Empty name

- **Value:** a name with **no character** once the whitespace at both ends is dropped (V-3).

### V-2 · Longest name

- **Value:** **at most 100 characters**, inclusive; a **longer name is refused**. A character is **one Unicode code point** after **NFC normalization**, so "Việt" is **4 characters**. The name is **normalized to NFC before** its characters are counted, the longest name is applied and the name is stored; this holds for a name **taken from a folder** and for a name **the user gives**, and the **folder keeps its own name**.

### V-3 · Whitespace

- **Value:** the characters that JavaScript `String.prototype.trim()` drops from both ends of a name, such as the space, the tab, the no-break space (U+00A0) and the ideographic space (U+3000). The system drops them from a name **the user gives**; it **drops none** from a name **taken from a folder**.
