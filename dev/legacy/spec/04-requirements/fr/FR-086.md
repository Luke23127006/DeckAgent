---
id: FR-086
title: "Report material that stops being readable during a request"
---

## Requirement

- **Statement:** When material that a request needs stops being readable while the system works on it, for example because its project folder was moved away, the system reads no other file in its place and never says that it read what it cannot read. It says which material it cannot read, when it knows it. It keeps the material the request already read, and uses that where it is enough. When the missing material is needed for the result, the system asks the user for material it can read, or for a change to the request, and waits within the request. When the request cannot finish that way, the system says that the work did not finish. The system starts no request again by itself when the material becomes readable again.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Material the request already read is kept

- **Given:** The request reads "report.pdf" from the project folder and finishes reading it. The folder is then moved away outside DeckAgent.
- **When:** The work continues on the request.
- **Then:**
  - The system uses the content of "report.pdf" it already read, where the request needs it.
  - The system does not read "report.pdf" again, and does not say that it read it again.
- **Check:** deterministic

### AC-2 · No other file is read in its place

- **Given:** The request needs "report.pdf". A second file with other content sits in the project folder.
- **When:** "report.pdf" stops being readable and the work continues.
- **Then:**
  - The system reads no other file of the folder in place of "report.pdf".
  - The system uses no content of the second file in place of the content of "report.pdf".
- **Check:** deterministic

### AC-3 · Other material allows the work to finish, with an honest report

- **Given:** The request "a talk from these notes" names three files of the project folder. The first two are read in full. The third stops being readable, and the content of the first two is enough for the talk.
- **When:** The work finishes.
- **Then:**
  - The deck is built from the two files the system read.
  - The conversation says which file cannot be read.
  - The conversation does not say that the file was used.
- **Check:** judged

### AC-4 · Needed material means a question or a clear failure

- **Given:** The request needs "chapter-3.pdf" from the project folder, and that file becomes unreadable while the work runs. The content the system already read is not enough.
- **When:** The system cannot go on without that material.
- **Then:**
  - The system does not invent content in its place.
  - The system either asks the user for material it can read or for a change to the request, and waits within the request, or says that the work did not finish.
  - When it cannot finish, it does not present slides as a finished result for that part.
- **Check:** judged

### AC-5 · Material that comes back starts no request again

- **Given:** The work ended because material of the project folder cannot be read. The folder is then readable again.
- **When:** The user takes no action.
- **Then:**
  - No request starts again, and the system sends nothing to a model.
  - The user can send a new request in the chat.
- **Check:** deterministic

### AC-6 · The files of the user are not changed

- **Given:** A request that reads material of the project folder while parts of it stop being readable.
- **When:** The request ends, in one run by finishing and in another run by failing.
- **Then:**
  - Each entry of the project folder is the same as before the request, and no entry appears in it.
  - No file the user gave as an attachment changed.
- **Check:** deterministic

## Notes

- Material that a request uses only in part, without losing it during the run, is FR-067. A folder that a workspace reports as unreadable while no request runs is FR-074.
- The files of the user stay as they are, whatever the work does (FR-084). Finished slides stay after a stop or a failure (FR-025).
- How the system learns that material stopped being readable is an architecture matter.
