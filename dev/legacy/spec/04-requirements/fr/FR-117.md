---
id: FR-117
title: "Report available native generation targets"
---

## Requirement

- **Statement:** The system offers as available only generation formats it can build now [BR-011]. What counts is the selected model together with the tools, permissions and integrations the system has now. A format the model cannot write by itself is available when that set can build its native output as promised. A format is unavailable only when that set cannot. It names each material limitation and each missing tool or permission. A native format is offered only when its result can be changed in the named tool. The system never changes the selected model, and never uses an outside service that is not approved, to make a format available [NFR-007].
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · Only real capability counts

- **Given:** The system can build HTML and Marp now. It has no approved access to Google Slides.
- **When:** The system shows the available generation formats.
- **Then:**
  - HTML and Marp are shown as available.
  - Google Slides is not shown as available.
- **Check:** deterministic

### AC-2 · The missing capability is named

- **Given:** The state of AC-1. The request asks for Google Slides.
- **When:** The system responds.
- **Then:**
  - The system says that it cannot build Google Slides now.
  - The system names what is missing, such as an approved access.
- **Check:** judged

### AC-3 · No image-only deck as a native format

- **Given:** The system can make a PPTX file only with one picture for each slide.
- **When:** The system shows the available generation formats.
- **Then:**
  - PPTX is not offered as a PowerPoint-native format.
- **Check:** deterministic

### AC-4 · Capability is the whole set, with no silent change of model or service

- **Given:** Two formats that the selected model cannot write by itself. The system has approved tools that build the native output of the first one. No approved tool, permission or integration builds the native output of the second one, but an outside service that is not approved could.
- **When:** The system works out which formats are available.
- **Then:**
  - The first format is shown as available.
  - The second format is not shown as available.
  - The selected model of the chat is the same as before.
  - No user content goes to an outside service that is not approved [NFR-007].
- **Check:** deterministic

### AC-5 · Partial capability is named before the confirmation

- **Given:** The system can build Reveal.js now, but it cannot embed the video that the request asks for.
- **When:** The system shows Reveal.js as an available generation format.
- **Then:**
  - Before the user confirms, the system says that Reveal.js keeps the text and images but not the embedded video.
  - The system does not say that Reveal.js meets every need of the request.
- **Check:** judged

## Notes

- The categories and the default are values of BR-011. The list of available formats is worked out in each context and is not a value of a rule.
