---
id: FR-030
title: "Change no slide while a change to the deck is unclear"
---

## Requirement

- **Statement:** While it waits for an answer about a change to the deck, the system changes and builds no slide. A reply that leaves the change unclear changes no slide. The system makes the change only once a reply makes it clear.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Unclear scope changes nothing

- **Given:** A deck of five slides. The user sent "make it more formal". The system asked which slides the change reaches, and waits for the answer.
- **When:** The user has not replied yet.
- **Then:**
  - Every slide is the same as before the request.
  - The deck has five slides.
- **Check:** deterministic

### AC-2 · Unclear feedback changes nothing

- **Given:** A deck of five slides. The user sent "Slide 3 doesn't look right". The system offered directions to improve slide 3, and waits for the answer.
- **When:** The user has not replied yet.
- **Then:**
  - Every slide is the same as before the request.
  - The deck has five slides.
- **Check:** deterministic

### AC-3 · Reply that settles nothing changes nothing

- **Given:** The state of AC-2.
- **When:** The user replies "not sure".
- **Then:**
  - Every slide is the same as before the request.
  - The deck has five slides.
- **Check:** deterministic

### AC-4 · Clear reply leads to the change

- **Given:** The state of AC-2.
- **When:** The user replies "make it shorter".
- **Then:**
  - Slide 3 changes.
  - Slides 1, 2, 4 and 5 are the same as before the request.
- **Check:** deterministic

## Notes

- The wait, the replies and a reply that settles nothing are shared request behavior. FR-020 covers them. This requirement adds only what happens to the deck.
- What the system asks is covered by FR-031 and FR-035.
