---
id: FR-069
title: "Review the outline as an overview and in detail"
---

## Requirement

- **Statement:** When the system shows an outline in the conversation, it shows a concise overview of the planned slides. It also shows the planned content of each planned slide. The user can read the detail of one planned slide, or of all planned slides, and hide it again. These are viewing actions: they change no outline, confirm nothing and send no request. The user has the same viewing actions on the confirmed outline. The confirmed outline stays read-only.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Overview shows every planned slide

- **Given:** The system has drafted an outline proposal of four planned slides.
- **When:** The system shows the outline proposal.
- **Then:**
  - The overview shows the four planned slides.
  - Each planned slide shows its title and a short summary of its planned content.
- **Check:** deterministic
- **Why:** The statement fixes a concise overview, not what each entry of it holds. A title alone brings back the problem the overview solves. The Napkin AI research shows a title and a one-line subtitle for each planned slide. Trade-off: the overview takes more space than a list of titles.

### AC-2 · Reading the detail of one planned slide

- **Given:** The state of AC-1. The planned slide on the results plans three findings: fewer errors, faster handover and lower cost.
- **When:** The user reads the detail of that one planned slide.
- **Then:**
  - The system shows the planned content of that slide, including the three findings.
- **Check:** judged

### AC-3 · Reading the detail of all planned slides

- **Given:** The state of AC-1.
- **When:** The user reads the detail of all planned slides.
- **Then:**
  - The system shows the planned content of each planned slide.
  - The user can hide the detail again, so the overview shows as before.
- **Check:** deterministic

### AC-4 · Viewing changes nothing and starts no work

- **Given:** The state of AC-1. The outline is the current outline and is not confirmed.
- **When:** The user reads or hides the detail of one planned slide, or of all planned slides.
- **Then:**
  - Only the detail that is visible changes.
  - The current outline is the same as before.
  - No new outline response appears.
  - No outline proposal is confirmed. The offer to confirm stays as it was.
  - No request starts.
  - No slide is built. The deck has no slide.
- **Check:** deterministic

### AC-5 · The confirmed outline keeps its detail

- **Given:** The user confirmed the current outline. The system is building the slides.
- **When:** The user reads or hides the detail of the confirmed outline.
- **Then:**
  - The confirmed outline is the same as at the confirmation.
  - The detail shows and hides again.
  - No new outline response appears.
  - No request starts.
  - The build of the slides carries on.
- **Check:** deterministic

## Notes

- The content the detail shows is covered by FR-008. This requirement covers only the overview and the viewing actions.
- The concrete control for opening and closing the detail is UI design. The requirement names the behavior, not the interface.
- A confirmed outline stays in the conversation. FR-003 keeps it fixed.
