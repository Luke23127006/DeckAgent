---
id: FR-064
title: "Keep a provider configuration that an active request uses"
---

## Requirement

- **Statement:** The user cannot delete a provider configuration while an active request uses it. A request uses the provider configuration of the model it started with. A request that waits for the user's answer is active. The system keeps the provider configuration with its settings and its added models. It says that an active request uses it. It does not stop the request, start it again, or move it to another model. Once the request finished, stopped or failed, the user can delete it. A provider configuration that no active request uses can still be deleted.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Not deleted while the system works

- **Given:** "Work AI" connects to provider P and has the added model M1. "Lab" is a custom model API with the added model M2. Request R1 in chat X started with M1 of "Work AI", and the system works on it. A test account with P records each request it receives.
- **When:** The user tries to delete "Work AI".
- **Then:**
  - The model setup still shows "Work AI" with provider P and the added model M1.
  - R1 is still active, and the system still shows that it works on R1.
  - Every request P receives for R1 is for model M1.
  - No other request starts.
- **Check:** deterministic

### AC-2 · Not deleted while the system waits for an answer

- **Given:** The state of AC-1 before the user acts. The system asked a question for R1 and waits for the user's answer.
- **When:** The user tries to delete "Work AI". The user then answers the question.
- **Then:**
  - The model setup still shows "Work AI" with provider P and the added model M1.
  - The answer is part of R1, and P receives it for model M1.
- **Check:** deterministic

### AC-3 · The reason is given

- **Given:** The state after AC-1.
- **When:** The user reads the response.
- **Then:**
  - The response says that an active request uses "Work AI", so it cannot be deleted now.
- **Check:** judged

### AC-4 · Deletion after the request ends

- **Given:** The state of AC-1 before the user acts. R1 ends, in three separate runs. The system finished it. The user stopped it. It failed.
- **When:** In each run, the user deletes "Work AI".
- **Then:**
  - In each run, the model setup no longer shows "Work AI" as saved.
- **Check:** deterministic

### AC-5 · Another provider configuration can be deleted

- **Given:** The state of AC-1 before the user acts. While R1 runs, the user chose M2 of "Lab" in chat X.
- **When:** The user deletes "Lab".
- **Then:**
  - The model setup no longer shows "Lab" as saved.
  - R1 is still active, and every request P receives for R1 is for model M1.
  - Chat X has no selected model. The system selected no other model.
- **Check:** deterministic

## Notes

- Deleting a provider configuration is covered by FR-063. Which model an active request uses is covered by FR-042.
