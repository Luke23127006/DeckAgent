---
id: FR-073
title: "Remove a workspace"
---

## Requirement

- **Statement:** The user can remove a workspace other than the default workspace from the workspaces that are set up. Removal takes the workspace out of the workspaces that are set up; it deletes no chat. The system says what removal does before it happens: the workspace is no longer set up and is no longer the workspace in use, and it removes nothing else. It says that the project folder and every chat of the workspace stay as they are. It removes only after the user confirms. Removing changes no folder and no file of the user on the computer. The work DeckAgent saved for that workspace, with the conversation and the deck of each of its chats, stays readable. After the removal, every chat of the removed workspace is reachable among the ungrouped chats, as FR-048 describes the chats the user can open. It belongs to no workspace, and it does not become a chat of the default workspace. Each of those chats keeps its saved work, its selected model and every permission the user gave it that lasts. The folder of the removed workspace is no longer inside the permission of those chats: the system gives no chat a reach into it by itself, and a step that reads there needs the approval of the user (FR-076, FR-077). While a request in a chat of the workspace is active, also one that waits for the user's answer, the system removes nothing and says that the request must end first. It stops no request and moves no chat.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Removal needs a confirmation and removes the setup only

- **Given:** The workspace "Alpha" for the folder "C:\ projects\alpha" is the workspace in use and holds two chats. The folder holds three files.
- **When:** The user chooses to remove "Alpha".
- **Then:**
  - The response says that the workspace will no longer be set up and will no longer be the workspace in use, and that it removes nothing else.
  - The response says that the folder and the two chats stay as they are, and that the chats are found among the ungrouped chats.
  - The system removes nothing before the user confirms.
- **Check:** deterministic

### AC-2 · After a confirmed removal, chats and files stay

- **Given:** The state after AC-1.
- **When:** The user confirms the removal.
- **Then:**
  - The workspace "Alpha" is no longer set up and is no longer the workspace in use.
  - The folder still holds the same three files, unchanged, and no other file appears in it.
  - The two chats of "Alpha" stay reachable among the ungrouped chats, each with its conversation and its deck.
  - Neither chat counts as a chat of the default workspace.
- **Check:** deterministic

### AC-3 · A cancelled removal changes nothing

- **Given:** The state after AC-1.
- **When:** The user chooses to remove "Alpha" and does not confirm.
- **Then:**
  - The workspace "Alpha" is still set up and is the workspace in use, with its chats.
- **Check:** deterministic

### AC-4 · Another workspace is untouched

- **Given:** The state after AC-2. A second workspace "Beta" with one chat is set up. The user is in the default workspace.
- **When:** The user opens the chats the user can open.
- **Then:**
  - The chat of "Beta" is reachable, and "Beta" is still set up.
- **Check:** deterministic

### AC-5 · A removed workspace is not rebuilt from its folder

- **Given:** The state after AC-2. "Alpha" held two chats, which are now among the ungrouped chats.
- **When:** The user adds a workspace and chooses the folder "C:\ projects\alpha" again.
- **Then:**
  - A new workspace is set up for that folder, with no chat of its own.
  - The two chats of the removed "Alpha" are still among the ungrouped chats, with their conversations and their decks.
  - Neither chat becomes a chat of the new workspace.
- **Check:** deterministic

### AC-6 · Removal waits while a request runs

- **Given:** The workspace "Alpha" holds one chat. A request in that chat is active; in one run the system works on it, in another run it waits for the user's answer.
- **When:** The user chooses to remove "Alpha".
- **Then:**
  - Nothing is removed, and "Alpha" stays set up and stays the workspace in use.
  - The response says that the request must end before the workspace can be removed.
  - In each run, the request keeps running or keeps waiting, and the system moves no chat.
- **Check:** deterministic

### AC-7 · A chat of a removed workspace keeps its work and loses the folder

- **Given:** The workspace "Alpha" for the folder "C:\ projects\alpha" holds one chat. That chat has a deck of five slides, the selected model "M1", and a permission that lasts, which the user confirmed for the folder "C:\ projects\shared". The folder "C:\ projects\alpha" holds "report.pdf".
- **When:** The user confirms the removal of "Alpha", opens that chat among the ungrouped chats, and sends a request whose text names "report.pdf" by its place on the computer.
- **Then:**
  - The chat shows its conversation and its five slides, and its selected model is still "M1".
  - The permission that lasts for "C:\ projects\shared" still holds.
  - The work asks the user before it reads "report.pdf", and reads nothing of "C:\ projects\alpha" without an approval (FR-076).
  - The folder "C:\ projects\alpha" holds the same files as before.
- **Check:** deterministic

## Notes

- The chats of a removed workspace are found among the ungrouped chats. Adding the same folder again sets up a new workspace and binds none of those chats (AC-5, FR-071).
- Chats of a removed workspace stay reachable: BR-004 sets which chats stay reachable and that no time limit deletes them.
- That switching the workspace in use stays allowed while a request runs is FR-054. This requirement limits removal only.
- A chat of no workspace holds no project folder, so its permission covers the data of its requests and the permissions the user gave it that last. That boundary is FR-077, and an approval for a step beyond it is FR-076.
- A chat of the removed workspace keeps the references it holds. One the user did not send stays in its request area, in a state that says it cannot be read, and one the user sent stays in its conversation (FR-082).
