---
id: FR-085
title: "Export a file to a destination the user chooses"
---

## Requirement

- **Statement:** When the user exports a deck, a conversation or a session archive, the system writes the file only to a destination the user chooses for that export. A project folder can be that destination, but a workspace being set up chooses no destination. When the destination already holds a file of that name, the system replaces nothing: it keeps the existing file as it was, says that the name is taken, and lets the user choose another destination. When the user chooses no destination, or cancels the choice, the system writes no file and changes no deck and no chat. The file holds what the export promises and no other material of DeckAgent's own work. When an export cannot write its file, the system gives no finished file, says that the export failed, and says why when it knows the reason.
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · The file appears at the destination the user chose

- **Given:** A chat with a deck of five slides. The user chooses deck export and an empty folder named "Deliver".
- **When:** The export finishes.
- **Then:**
  - One file of the kind the user chose is in "Deliver".
  - The response says where the file is.
  - The folder holds no second file from that export.
- **Check:** deterministic

### AC-2 · A project folder is not a destination by itself

- **Given:** A chat with a deck of five slides, in a workspace whose project folder is "C:\ projects\alpha". "C:\ projects\alpha" holds "report.pdf". The user starts a deck export.
- **When:** The user chooses the empty folder "C:\ deliver" as the destination, and chooses no file in "C:\ projects\alpha".
- **Then:**
  - No file appears in "C:\ projects\alpha", and "report.pdf" is unchanged.
  - One file of the kind the user chose is in "C:\ deliver", and no other file appears there.
  - The response says where the file is, and names "C:\ deliver".
- **Check:** deterministic

### AC-3 · An occupied destination keeps the existing file

- **Given:** The destination the user chose holds the file "deck.pdf" with content the user put there.
- **When:** The user exports a deck that would take the same name there.
- **Then:**
  - "deck.pdf" holds the content the user put there, unchanged.
  - The response says that the name is taken there, and lets the user choose another destination.
  - No file with another name appears there unless the user chooses that name.
  - After the user chooses another destination, the file appears there.
- **Check:** deterministic

### AC-4 · A cancelled choice writes nothing

- **Given:** A chat with a deck of five slides and a conversation. The user starts a deck export, then starts a conversation export.
- **When:** The user cancels the choice of destination in each run.
- **Then:**
  - No file is written in either run.
  - The deck holds the same five slides, and the conversation shows the same messages.
  - The user can start the export again.
- **Check:** deterministic

### AC-5 · The exported file holds no other work of the system

- **Given:** A chat with a deck of five slides, two attachments, an outline and a confirmed outline. The export produces the file the user chose.
- **When:** The user opens the exported file.
- **Then:**
  - The file holds the content the chosen kind of export promises.
  - The file holds no other material that only served the system to make the slides.
  - The file holds no credential that DeckAgent keeps [NFR-006].
- **Check:** judged

### AC-6 · A deliverable needs no project folder

- **Given:** A chat with a deck of five slides, in a workspace whose project folder was deleted outside DeckAgent. The deck stays readable.
- **When:** The user exports the deck to a destination outside that folder.
- **Then:**
  - The export gives its file, and the response says where it is.
  - The export names no file of the project folder as needed.
- **Check:** deterministic

### AC-7 · A failed export gives no finished file

- **Given:** The destination the user chose cannot take the file, for example it is full.
- **When:** The user exports.
- **Then:**
  - No finished file is written at that destination.
  - The response says that the export failed, and why when the reason is known.
  - The deck and the chat are unchanged, and the user can start the export again.
- **Check:** deterministic

## Notes

- What the deck export holds belongs to the deck export and to the kind of file the user chooses. What an exported session holds is FR-080. Both write their file through this requirement.
- A source archive of a deck, such as "deck.zip", holds the native slide source and its assets. That is what the deck export promises. It is not material of DeckAgent's own work. Working records that only served the system stay out of it, as AC-5 says.
- That a deck export gives a complete file or no file, and how a new attempt starts, is FR-122.
- A file that the user names as a destination is a choice the user makes. A destination named in the request text, an attachment or a file of the project folder is no such choice.
- That the work creates no file of the user on its own is FR-084.
