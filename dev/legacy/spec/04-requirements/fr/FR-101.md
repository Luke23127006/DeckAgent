---
id: FR-101
title: "Save and revise a custom visual style"
---

## Requirement

- **Statement:** The system saves a custom visual style under the name the user gives, and adds it to the visual styles the user can choose. It can change a saved custom visual style. Saving or changing one changes no deck, no design system and no other visual style.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A new custom visual style is saved

- **Given:** The user reviewed a custom visual style proposal named "Report". A chat holds a deck of five slides.
- **When:** The user saves "Report".
- **Then:**
  - "Report" is among the visual styles the user can choose.
  - Every slide of the deck is as it was.
  - No design system changed.
- **Check:** deterministic

### AC-2 · A changed custom visual style keeps its name

- **Given:** "Report" is saved. A deck of five slides was built with "Report".
- **When:** The user changes the density rules of "Report" and saves under the same name.
- **Then:**
  - "Report" shows the changed density rules.
  - Every slide of the deck is as it was.
- **Check:** deterministic

### AC-3 · Another visual style stays as it was

- **Given:** "Report" and "Editorial" are saved. "Editorial" is a built-in visual style.
- **When:** The user changes the heading treatment of "Report" and saves.
- **Then:**
  - "Editorial" holds the same rules as before.
  - "Report" and "Editorial" remain among the visual styles the user can choose.
- **Check:** deterministic
