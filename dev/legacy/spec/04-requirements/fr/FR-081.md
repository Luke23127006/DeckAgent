---
id: FR-081
title: "Change the model settings of an added model"
---

## Requirement

- **Statement:** The user can change the model settings of one added model in its provider configuration: its display name within the provider configuration, its context window, its highest output, the kinds of input it takes and its reasoning levels [BR-005]. Until the user saves, the saved settings stay as they were. Cancel or leaving saves nothing, as FR-044 says for every unsaved change. When the user saves, the system keeps the settings the user gave, keeps a setting the user emptied as unset, and fills in no value the user or the provider did not give. A value that the model or its provider cannot hold, as far as the system knows it, is not saved: the system says what is invalid and keeps what the user gave, so the user can correct it. A failed or cancelled save changes no saved model and no selected model. A request that runs keeps the model settings it started with, also its reasoning level; a saved change applies from the next request (FR-042).

## Acceptance conditions

### AC-1 · A saved change is kept on that model only

- **Given:** The provider configuration "Work AI" has the added models M1 and M3. M1 holds the context window W1. Chat X has M1 as its selected model.
- **When:** The user changes the context window of M1 to W2, leaves the settings of M3 as they are, and saves.
- **Then:**
  - M1 of "Work AI" holds the context window W2. M3 holds its settings unchanged.
  - No added model of another provider configuration holds a changed setting.
- **Check:** deterministic

### AC-2 · Leaving without saving changes nothing

- **Given:** The state after AC-1. M1 holds the context window W2.
- **When:** The user changes the context window of M1 to W3, then leaves the model setup without saving.
- **Then:**
  - M1 holds the context window W2. No later request uses W3 (FR-044).
- **Check:** deterministic

### AC-3 · An emptied setting stays unset

- **Given:** The state after AC-1. M1 holds the reasoning levels L1 and L2 [BR-005] [BR-?: reasoning levels].
- **When:** The user removes the reasoning levels of M1 and saves.
- **Then:**
  - M1 holds no reasoning levels, shown as unset. The system fills in no level by itself.
  - The selected model of a chat that chose a level of M1 shows no chosen level (FR-055).
- **Check:** deterministic

### AC-4 · A value the model or provider cannot hold is refused with a reason

- **Given:** The state after AC-1. The provider reports a bound on the context window of M1 that W3 exceeds.
- **When:** The user gives the context window W3 for M1 and saves.
- **Then:**
  - M1 keeps the context window W2.
  - The response names the value that is invalid and why.
  - The value W3 is kept as given, so the user can correct it.
- **Check:** deterministic

### AC-5 · A running request keeps its started settings

- **Given:** The state after AC-1. A request of chat X with M1 and the context window W2 still runs.
- **When:** The user saves the context window W2b for M1 while that request runs.
- **Then:**
  - The running request continues with W2. The system did not stop it or start it again (FR-042).
  - A later request in chat X runs with W2b.
- **Check:** deterministic

## Notes

- The values each model actually holds for these settings, and which providers report them, wait for evidence (design backlog of the ideal spec).
- Saving model settings proves nothing about the capability of the model. A set context window says how much the system gives the model, not what the provider can do [BR-005].
