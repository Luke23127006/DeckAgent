---
id: FR-106
title: "Preserve existing decks after definition changes"
---

## Requirement

- **Statement:** Editing, renaming or removing a saved design system or a saved custom visual style changes no deck made earlier. Each such deck keeps the design it was made with and stays viewable and editable, also when a definition it used no longer exists.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A changed design system leaves earlier decks as they were

- **Given:** A deck of five slides was built with the design system "Acme".
- **When:** The user changes the brand colour of "Acme" and saves it.
- **Then:**
  - Every slide of the deck is as it was before the change.
  - The deck keeps the earlier brand colour.
- **Check:** deterministic

### AC-2 · A changed custom visual style leaves earlier decks as they were

- **Given:** A deck of five slides was built with the custom visual style "Report".
- **When:** The user changes the density rules of "Report" and saves it.
- **Then:**
  - Every slide of the deck is as it was before the change.
  - The deck keeps the earlier density.
- **Check:** deterministic

### AC-3 · A removed visual style leaves its decks editable

- **Given:** A deck of five slides was built with the custom visual style "Report". "Report" was then removed.
- **When:** The user asks to change the heading of slide 3.
- **Then:**
  - The deck still contains five slides in the same order.
  - The system changes the heading of slide 3.
  - Slide 3 remains editable without the removed visual style.
  - Slides 1, 2, 4 and 5 remain unchanged.
- **Check:** deterministic

### AC-4 · A removed design system leaves its decks viewable

- **Given:** A deck of five slides was built with the design system "Acme". "Acme" was then removed.
- **When:** The user opens the deck.
- **Then:**
  - The deck canvas shows the same five slides as before the removal.
  - The system reports no failure to show the deck.
- **Check:** deterministic
