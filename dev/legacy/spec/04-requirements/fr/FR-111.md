---
id: FR-111
title: "Keep the pending request during design setup"
---

## Requirement

- **Statement:** When the user opens the design-rule setup while preparing a request, the system keeps the conversation, the request text and the attachments as they were. The setup adds nothing to the request text and sends nothing. The request can still be sent after the user comes back.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Opening the setup changes nothing in the chat

- **Given:** A chat has no active request. The request area holds the request text "a talk on our pilot results" and the attachment "notes.docx".
- **When:** The user opens the design system setup.
- **Then:**
  - The request text is still "a talk on our pilot results".
  - "notes.docx" is still in the request area, unchanged.
  - The conversation shows no new message.
  - No request starts.
- **Check:** deterministic

### AC-2 · Back to the chat after saving a visual style

- **Given:** A chat has no active request. The request area holds "a talk on our pilot results" and the attachment "notes.docx". The user opens Custom Visual Style setup and reviews a new style named "Report".
- **When:** The user saves "Report" and returns to the chat.
- **Then:**
  - "Report" is among the saved Custom Visual Styles.
  - The conversation is unchanged.
  - The request text is unchanged.
  - "notes.docx" remains in the request area unchanged.
  - The user can still send the original request.
  - No request starts before the user sends it.
- **Check:** deterministic

### AC-3 · Back to the chat without saving

- **Given:** The state of AC-1.
- **When:** The user leaves the design system setup without saving and goes back to the chat.
- **Then:**
  - The conversation, the request text and "notes.docx" are as they were.
  - The user can still send the request, and the request starts.
- **Check:** deterministic

## Notes

- This requirement covers the design-rule setup that a request opens before it is sent. FR-038 keeps the chat for the places it names that a user opens from the conversation. What the design-rule setup itself saves or drops is covered by FR-096, FR-097, FR-100, FR-101 and FR-109.
