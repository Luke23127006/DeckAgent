## Goal

The user has a deck and needs to understand it or trust it before they use it: where a figure comes from, whether two slides disagree, what the deck leaves out, or what a passage means. The user wants an answer and does not want the deck changed.

## Preconditions

- **Trigger:** The user sends a question about the deck in a chat whose deck has slides.
- **Preconditions:** The deck has at least one slide. The chat has no active request: no request the system works on or waits an answer in. A request in another chat does not block this one (FR-014).

## Interactions

How to read the interactions:

- S1 to S3 run the main flow of UC-003 (`includes` UC-003). The question is prepared and sent there, and the system works there. S4 ends the request, as UC-003 S4 says, and gives the answer.
- The answer rests on the deck and on the material the user gave in this chat. It is not a full check of the facts (Note 3).
- The system changes no slide in any flow of this use case.

## Behavior constraints

- No slide changes in any flow, including a failure or a stop at S3 (UC-003 A11, A18, A19, A31; Note 4).
- This use case is not UC-002: here the system answers and changes no slide; in UC-002 the system changes the deck (Note 1). It is not UC-001: UC-001 tells the sources and assumptions once, in the closing message of the first draft (Note 2).
- Naming a source, finding a conflict and checking a fact are three different things. This use case names sources and finds conflicts; it does not promise that a claim is true (Note 3).

- **Postconditions:**
  - The conversation holds the question and the answer.
  - Every slide is as it was before the question.
- **Minimal guarantee:** Whatever branch fails or is interrupted:
  - No slide changes.
  - The question is kept in the conversation.

## Notes

1. This use case is not UC-002. Here the system answers and changes no slide. In UC-002 the system changes the deck. Both send a request through UC-003, so they share a trigger. They do not share a result.
2. This use case is not UC-001. UC-001 tells the sources and assumptions once, in the closing message of the first draft (S6). Here the user asks at any time after.
3. Naming a source, finding a conflict and checking a fact are three different things. This use case names sources and finds conflicts. It does not promise that a claim is true.
4. A failure or a stop at S3 runs the flow of UC-003 for it: A11, A18, A19 or A31. No slide changes in any of them.
5. One use case, not one per kind of question. The kinds share the trigger, the steps and the result. A3 to A5 add only what differs in the answer.
