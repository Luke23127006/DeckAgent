---
id: BR-005
title: "Providers, added models and selectable models"
---

## Rule

- **Statement:** The rule sets which built-in providers a provider configuration can connect to. It sets which API protocols a custom model API can use. It sets which models the user can add to a provider configuration, which model settings each added model holds, and which default models a built-in provider has. It also sets which added models count as selectable models, and which reasoning levels an added model has. DeckAgent sets the default models of a built-in provider with each DeckAgent release. They can differ between two releases. The model catalog of a provider is not one of these values, and does not set the default models. The provider ID of a built-in provider stays the same in every release.
- **Updated at:** 27-10-2026

## Values

### V-1 · Built-in providers offered

- **Value:** Closed list: OpenAI, Anthropic, Google Gemini and DeepSeek. Each has its own provider ID (V-6).

### V-2 · Models the user can add

- **Value:** Each model in the model catalog of the provider, and each model ID the user gives by hand. Open list. A model ID need not be in the model catalog.

### V-3 · Selectable models

- **Value:** Each added model of each saved provider configuration. A model the user removed is not an added model. Nor is a model of a deleted provider configuration, or one that a restore of default models removed.

### V-4 · API protocols of a custom model API

- **Value:** Closed list: OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and Google Gemini.

### V-5 · Default models of a built-in provider

- **Value:** not set
- **Why:** A selected flow restores the default models of a built-in provider. DeckAgent sets them with each release, and not from the model catalog. No decision says which built-in providers have default models, or which model IDs they hold. The question is kept in the design backlog of the ideal spec. A custom model API has none unless a decision gives it some.

### V-6 · Provider ID of each built-in provider

- **Value:** OpenAI uses `openai`. Anthropic uses `anthropic`. Google Gemini uses `google`. DeepSeek uses `deepseek`. These IDs are fixed for built-in providers.

## Notes

- The model settings of an added model, and the reasoning levels an added model has with the API value each level uses per provider, have no value list here yet. What is decided is the behavior: each added model can hold its own model settings [BR-005], and a setting the user does not give and the provider does not report stays unset. The values per provider and model wait for evidence. They are kept as open questions in the design backlog of the ideal spec, outside `docs/spec/`. The value IDs V-7 and V-8 that once carried these two lines are retired and not reused.
- How DeckAgent keeps its lists of default models, and in which format, is an architecture matter. It is not a value of this rule.
- The offer of a model that runs on the user's computer is not a value of this rule. A compatible model service on the user's computer can work as a custom model API. It is not a built-in provider and not a feature of its own.
