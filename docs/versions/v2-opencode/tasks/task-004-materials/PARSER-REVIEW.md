## Implemented safety and observed evidence

Parser workers have no inherited environment credentials, discard stdout/stderr, use a 15-second timeout and a 96 MiB JS heap setting.
Termination is awaited on abort. The heap setting is not a cap on all process/native/buffer memory and is not an OS sandbox.
Technical bounds: extracted UTF-8 1 MiB, XML part 4 MiB, expanded archive 32 MiB, 1,000 archive entries,
100 PDF pages/PPTX slides, image decode 16 megapixels. Uploads allow at most two active preparations per Host.
ZIP central directory, local headers, entry lengths and actual CRC are checked; no entries are written to disk.
External XML entities/DOCTYPE are rejected, external slide relationships are rejected, and macros/scripts are never executed.
Known partial coverage is returned as warnings; blank PDF and empty text report no usable text explicitly.

The protected PDF fixture is a synthetic blank document generated locally with pypdf 6.16.1 and test-only encryption.
It contains no user content or real credentials. pypdf is not an application dependency.
Other fixtures are generated by `tests/fixtures/material-documents.mjs` with independent marker/order/color assertions.
Minimal Office fixtures qualify extraction behavior; they do not establish editable Office import or layout fidelity.

Actual pinned CLI wire evidence matches both PNG/JPEG payload hashes and only the granted MCP tool declaration.
Live Gemini qualification includes source-to-outline/slides in Vietnamese and English, and image interpretation with neutral filenames.
The later live test also keeps the expected source identifier out of the prompt; see evidence.json for final verdict and chronology.

Twenty synthetic benchmark cases measure per-upload wall time and sampled process RSS, including ten new files in one request.
The 20 MiB TXT is rejected by the independent extracted-text bound; accepting its upload size does not promise full parsing.
The earlier measurement peaked near 218 MiB RSS for that rejected case. Final measurements and exact hashes are in evidence.json.
These minimal fixtures are insufficient to approve 10/request or 20 MiB/file as product defaults. Intake remains explicitly configured.

## Required fixture matrix

| Format | Known-content case | Negative/partial cases |
| --- | --- | --- |
| TXT | Vietnamese/English UTF-8 with exact marker | Invalid encoding, binary content under text extension, empty valid text, oversized input |
| MD | Headings, Unicode and exact source facts | Embedded instructions remain quoted data; no link fetching or HTML/script execution |
| PDF | Known facts on separate pages with page provenance | Protected, truncated, scanned/no usable text, invalid structure, page/text/time bounds |
| DOCX | Paragraphs, lists and table facts in document order | Bad ZIP/XML, encrypted Office container, macro/embedded/external content, expansion limits |
| PPTX | Facts and titles from multiple slides in presentation order | Nonsequential slide file names, notes/unsupported content warnings, malformed relationships, expansion limits |
| PNG | Visible test facts and valid image bytes | Truncation, spoofed type, invalid CRC/decode, excessive dimensions, text-only/unknown selected model |
| JPEG | Visible test facts and valid image bytes | Broken markers/decode, spoofed extension, excessive dimensions, text-only/unknown selected model |

Image dimensions or magic bytes alone do not prove decode integrity or visual interpretation.
The CLI `--file` flag is confirmed locally; actual model image parts and live fact extraction are unverified.
Do not enable native filesystem tools to make image attachment work.
