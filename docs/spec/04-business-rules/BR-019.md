---
id: BR-019
title: "Folders that cannot be a project folder"
---

## Rule

- **Statement:** The **folders that the system refuses as a project folder**, compared after **links are followed**. A folder **refused by one value** is refused **whatever the other values say**.
- **Status:** confirmed
- **Why:** The agent **reads every file of the project folder** and **sends it to a provider**; a **folder too wide** or **holding keys** would send **files the user never meant to share**. DeckAgent **writes nothing in a project folder**, so a **folder holding DeckAgent's own data** cannot be one.

## Values

### V-1 · Drive roots

- **Value:** the **root of every drive**, such as `C:\` and `D:\`.

### V-2 · System folders

- **Value:** `C:\Windows`, `C:\Program Files` and `C:\Program Files (x86)`, **every folder inside them**, and **every folder that holds one of them**. Closed list.

### V-3 · User folder

- **Value:** the **user's own folder** (such as `C:\Users\<name>`) **itself only**; a folder **inside it** is **not refused by this value**.

### V-4 · Key folders

- **Value:** `.ssh`, `.aws`, `.gnupg`, `.kube` and `.docker` in the **user's own folder**, and **every folder inside them**. Closed list.

### V-5 · DeckAgent data

- **Value:** the **folder of DeckAgent's own data**, **every folder inside it**, and **every folder that holds it**.

## Notes

- V-1 to V-5 follow **open-design**, which refuses the **same folders** except **a folder that holds its data**.
