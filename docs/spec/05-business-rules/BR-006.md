id: BR-006
title: "What each provider needs for setup"
---

## Rule

- **Statement:** The rule sets what the user gives for a provider configuration before its models can run, such as a key. It sets this for each built-in provider and for a custom model API. It also sets which settings of a saved provider configuration the user can change.
- **Status:** confirmed
- **Source:** use case flow; owner decision, 2026-10-12: a custom model API has a provider ID, a base URL and an API protocol, and a key only when it needs one; the user can change the key, the base URL and the display name of a saved provider configuration, but not its provider ID
- **Updated at:** 12-10-2026

## Values

### V-1 · What each built-in provider needs

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** Selected flows say what a built-in provider needs and refuse a setup that lacks it. No decision says what each built-in provider needs besides a key. No decision says which of its settings the user can change from its defaults, such as its base URL.

### V-2 · What a custom model API needs

- **Value:** Open list. It holds a provider ID, a base URL and an API protocol. It holds a key or other authentication information only when the model service needs it.
- **Source:** owner decision, 2026-10-12: the user gives a custom model API a unique provider ID, a base URL, an offered API protocol and, when needed, authentication information

### V-3 · Settings the user can change after saving

- **Value:** Open list. It holds the key or other authentication information, the base URL and the display name. It never holds the provider ID.
- **Source:** owner decision, 2026-10-12: the user can edit the key or other authentication information, the base URL and the display name of a saved provider configuration; its provider ID is fixed

## Not specified

- How the system knows that a custom model API needs a key. Pending owner decision.
- Whether the user can change the API protocol of a saved custom model API. Pending owner decision.

## Notes

- Until 2026-10-12, V-1 was "What each provider needs". The owner decision of 2026-10-12 on custom model APIs split the custom part into V-2.
- Added models are not a setting of this rule. Which models the user can add is a value of another rule.
