---
id: BR-008
title: "Provider IDs and display names of provider configurations"
---

## Rule

- **Statement:** The rule sets how many saved provider configurations can have the same provider ID. It sets which provider IDs a custom model API cannot take. It also sets which display names a provider configuration can have. It sets no total number of provider configurations.
- **Updated at:** 25-10-2026

## Values

### V-1 · Provider configurations per provider ID

- **Value:** At most one saved provider configuration for each provider ID. This holds for the provider ID of a built-in provider. It also holds for one the user gives to a custom model API. The base URL and the API protocol do not count: two provider configurations with different provider IDs can share them.

### V-2 · Valid display name

- **Value:** A display name that is not empty, and that no other saved provider configuration has.
  - A display name of whitespace only is empty.
  - Two display names are the same when they differ only in capital letters. The same holds for whitespace at the start or the end. Example: "Work AI" and " work ai " are the same. "Work AI" and "WorkAI" are not.

### V-3 · Provider IDs reserved for built-in providers

- **Value:** Closed list: the provider ID of each built-in provider. A custom model API never takes one of them. This holds also while that built-in provider has no saved provider configuration.

## Notes

- A deleted provider configuration no longer counts. Its provider ID can have a saved provider configuration again.
- This rule is not the retired rule on the number of provider configurations. It sets no total number.
- The provider ID of each built-in provider is a value of another rule. It is still pending there.
- This rule covers a display name of a provider configuration only. It does not set the display name of a workspace, or of an added model. The display name the model settings of an added model hold is a value of the rule on providers, added models and selectable models.
