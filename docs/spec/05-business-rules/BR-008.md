id: BR-008
title: "Provider IDs and display names of provider configurations"
---

## Rule

- **Statement:** The rule sets how many saved provider configurations can have the same provider ID. It also sets which display names a provider configuration can have. It sets no total number of provider configurations.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-12: each provider ID has at most one saved provider configuration; a display name is not empty and is unique among saved provider configurations
- **Updated at:** 12-10-2026

## Values

### V-1 · Provider configurations per provider ID

- **Value:** At most one saved provider configuration for each provider ID. This holds for the provider ID of a built-in provider. It also holds for one the user gives to a custom model API. The base URL and the API protocol do not count: two provider configurations with different provider IDs can share them.

### V-2 · Valid display name

- **Value:** A display name that is not empty, and that no other saved provider configuration has.

## Not specified

- Whether two display names that differ only in capital letters or in spaces count as the same. Pending owner decision.
- Whether a display name of spaces only counts as empty. Pending owner decision.
- Whether a custom model API can take the provider ID of a built-in provider that has no saved provider configuration. Pending owner decision.

## Notes

- A deleted provider configuration no longer counts. Its provider ID can have a saved provider configuration again.
- This rule is not the retired rule on the number of provider configurations. It sets no total number.
