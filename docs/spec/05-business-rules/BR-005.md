---
id: BR-005
title: "Providers, added models and selectable models"
---

## Rule

- **Statement:** The rule sets which built-in providers a provider configuration can connect to. It sets which API protocols a custom model API can use. It sets which models the user can add to a provider configuration, which model settings each added model holds, and which default models a built-in provider has. It also sets which added models count as selectable models, and which reasoning levels an added model has. DeckAgent sets the default models of a built-in provider with each DeckAgent release. They can differ between two releases. The model catalog of a provider is not one of these values, and does not set the default models. The provider ID of a built-in provider stays the same in every release.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: the user adds models to each provider configuration, from the model catalog or by model ID, and chooses a selected model among the added models; owner decision, 2026-10-12: a provider configuration connects to a built-in provider or to a custom model API, keeps its provider ID, and can restore the default models of its provider; owner decision, 2026-10-12: DeckAgent gives a list of default models for each built-in provider that has them, with each release, and the model catalog of the provider does not set that list; owner decision, 2026-10-13: the default models of a built-in provider can change between releases; the provider IDs of built-in providers are stable; owner decision, 2026-10-25: each added model holds its own model settings, such as its context window, its highest output, its kinds of input and its reasoning levels, and a setting that no source gives stays unset
- **Updated at:** 25-10-2026

## Values

### V-1 · Built-in providers offered

- **Value:** Closed list: OpenAI, Anthropic, Google Gemini and DeepSeek. Each has its own provider ID (V-6).
- **Source:** owner decision, 2026-10-12: the built-in providers are OpenAI, Anthropic, Google Gemini and DeepSeek

### V-2 · Models the user can add

- **Value:** Each model in the model catalog of the provider, and each model ID the user gives by hand. Open list. A model ID need not be in the model catalog.
- **Source:** owner decision, 2026-10-12: the user adds models from the model catalog or by model ID, and the system does not check a model ID with the provider before saving it

### V-3 · Selectable models

- **Value:** Each added model of each saved provider configuration. A model the user removed is not an added model. Nor is a model of a deleted provider configuration, or one that a restore of default models removed.
- **Source:** owner decision, 2026-10-12: the provider ID of a provider configuration never changes; a removed model or a deleted provider configuration leaves a chat that selected it without a selectable selected model; owner decision, 2026-10-12: a confirmed restore removes each added model that is not a default model

### V-4 · API protocols of a custom model API

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** A selected flow lets the user choose the API protocol of a custom model API. No decision names the API protocols offered. Not every API protocol is offered. The owner keeps custom model APIs, so that the user can connect other model services. Naming their API protocols waits for technical research. The three API protocols that the reference product DeepSeek Harness offers are research candidates. None of them is approved for DeckAgent.

### V-5 · Default models of a built-in provider

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** A selected flow restores the default models of a built-in provider. The owner decided that DeckAgent sets them with each release, and not from the model catalog. No decision says which built-in providers have default models. No decision names their model IDs. They wait for evidence from each provider and from the implementation. A custom model API has none unless a decision gives it some.

### V-6 · Provider ID of each built-in provider

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** Each built-in provider has its own provider ID. It never changes after saving, and stays the same in every release. No decision sets the provider ID of any built-in provider in V-1. The IDs wait for implementation evidence.

### V-7 · Model settings of an added model

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** The owner decided on 2026-10-25 that each added model can hold its own model settings: its display name within the provider configuration, its context window, its highest output, the kinds of input it takes and its reasoning levels. A setting that the user does not give and the provider does not report stays unset. No evidence yet names the values for any added model, or which built-in providers report them. They wait for evidence from each provider and from the implementation.

### V-8 · Reasoning levels of an added model and their API values

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** The owner decided on 2026-10-25 that the user chooses a reasoning level of the selected model for a chat, and that not every model has the same levels. A level is turned into the value the API of its provider asks for. A level that turns reasoning off does not promise reasoning is off for an endpoint that keeps it on. No evidence yet names the levels of any added model, or which API value each level uses for each provider. They wait for evidence from each provider and from the implementation.

## Notes

- Until 2026-10-12, V-2 was "Available models of a provider configuration". Its value was every model that the saved provider configuration can use, with its provider and its current key. The owner decision of 2026-10-12 on added models replaced it.
- Until 2026-10-12, V-1 was "Providers offered". Since then, a provider that is not a built-in provider can be set up as a custom model API. It needs an offered API protocol.
- Until 2026-10-12, V-3 kept the models added before a change of provider, but not as selectable models. The owner decision of 2026-10-12 on provider IDs replaced it: a provider configuration keeps its provider ID. Two `Not specified` items on a change of provider were removed with it.
- Until 2026-10-12, V-1 named no built-in provider, and no decision said how default models are set. The owner decisions of 2026-10-12 set V-1 and the rule for default models. V-4, V-5 and V-6 stay pending.
- Until 2026-10-25, the rule held no model settings and no reasoning levels. The owner decision of 2026-10-25 added V-7 and V-8. Both stay pending.
- How DeckAgent keeps its lists of default models, and in which format, is an architecture matter. It is not a value of this rule.
- Until 2026-10-13, two open items asked about a model that runs on the user's computer, and about default models that change between releases. The owner decisions of 2026-10-13 settled both.
- The offer of a model that runs on the user's computer is not a value of this rule. A compatible model service on the user's computer can work as a custom model API. It is not a built-in provider and not a feature of its own.
