id: BR-005
title: "Providers, added models and selectable models"
---

## Rule

- **Statement:** The rule sets which built-in providers a provider configuration can connect to. It sets which API protocols a custom model API can use. It sets which models the user can add to a provider configuration, and which default models a built-in provider has. It also sets which added models count as selectable models. The model catalog of a provider is not one of these values.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: the user adds models to each provider configuration, from the model catalog or by model ID, and chooses a selected model among the added models; owner decision, 2026-10-12: a provider configuration connects to a built-in provider or to a custom model API, keeps its provider ID, and can restore the default models of its provider
- **Updated at:** 12-10-2026

## Values

### V-1 · Built-in providers offered

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** A selected flow shows the built-in providers the user can choose, each with its own provider ID. No decision names them.

### V-2 · Models the user can add

- **Value:** Each model in the model catalog of the provider, and each model ID the user gives by hand. Open list. A model ID need not be in the model catalog.
- **Source:** owner decision, 2026-10-12: the user adds models from the model catalog or by model ID, and the system does not check a model ID with the provider before saving it

### V-3 · Selectable models

- **Value:** Each added model of each saved provider configuration. A model the user removed is not an added model. Nor is a model of a deleted provider configuration.
- **Source:** owner decision, 2026-10-12: the provider ID of a provider configuration never changes; a removed model or a deleted provider configuration leaves a chat that selected it without a selectable selected model

### V-4 · API protocols of a custom model API

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** A selected flow lets the user choose the API protocol of a custom model API. No decision names the API protocols offered. Not every API protocol is offered.

### V-5 · Default models of a built-in provider

- **Value:** not set
- **Status:** pending
- **Source:** owner decision needed
- **Why:** A selected flow restores the default models of a built-in provider. No decision says which built-in providers have default models, or which ones. A custom model API has none unless a decision gives it some.

## Not specified

- Whether a model that runs on the user's computer and needs no key is offered, and through which API protocol. Pending owner decision.

## Notes

- Until 2026-10-12, V-2 was "Available models of a provider configuration". Its value was every model that the saved provider configuration can use, with its provider and its current key. The owner decision of 2026-10-12 on added models replaced it.
- Until 2026-10-12, V-1 was "Providers offered". Since then, a provider that is not a built-in provider can be set up as a custom model API. It needs an offered API protocol.
- Until 2026-10-12, V-3 kept the models added before a change of provider, but not as selectable models. The owner decision of 2026-10-12 on provider IDs replaced it: a provider configuration keeps its provider ID. Two `Not specified` items on a change of provider were removed with it.
