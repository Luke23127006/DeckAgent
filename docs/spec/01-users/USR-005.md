## Who

Professional designers and consultants who build decks for clients as a service, who judge visual quality closely, are fluent with AI tools, and answer to clients' brand rules and approval rounds. [assumed]

## Context of use

1. Works at a desktop, on several client projects at once. [assumed]
2. Starts from the client's notes and a messy draft deck, then explores directions before settling on one. [assumed]
3. Shares drafts with clients through a link and collects comments in rounds. [assumed]
4. Pays for tools personally and expects them to fit a professional workflow. [assumed]

## Pain points and workarounds today

1. Generated slides look generic, so rebuilds the layout by hand. [assumed]
2. Loses manual fine-tuning when asking an AI tool to revise something else. [assumed]
3. Sends clients exported files and loses track of which version each comment refers to. [assumed]

## Special-case hypotheses

| ID | Hypothesis | Affects | Handled by | Source |
|---|---|---|---|---|
| H-1 | Hand-set details (position, spacing, type) must survive later AI changes. The product would have to distinguish what the user fixed by hand from what is open to change, and respect it. | Scoped changes; protecting manual edits | none yet | [assumed] |
| H-2 | A designer explores many directions and compares them. The product would have to produce alternatives side by side and let the user pick or combine. | Alternatives; comparison | none yet | [assumed] |
| H-3 | A client's brand book is exact, not approximate. The product would have to apply specific colors, fonts and spacing precisely and flag deviations. | Brand constraints; precision | UC-001.A5 | [assumed] |
| H-4 | Clients review a link, not a file. The product would have to support comments and show which version each comment belongs to. | Sharing; comments; version identity | none yet | [assumed] |
| H-5 | The client's team edits the deck later in other tools. The delivered file would have to be structured as a person would build it, not flattened. | Output structure; editability | none yet | [assumed] |
| H-6 | An expert will not tolerate fixed, hidden decisions. Anything the system decides automatically would have to be visible and overridable. | Transparency; overrides | none yet | [assumed] |
| H-7 | The client's notes are incomplete or contradict each other, and the draft deck is inconsistent. The product would have to surface conflicts and gaps in the input instead of silently picking one. | Handling messy input; clarifying questions | none yet | [assumed] |
