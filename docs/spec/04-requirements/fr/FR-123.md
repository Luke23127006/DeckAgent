---
id: FR-123
title: "Use a source archive as reference for a new deck"
---

## Requirement

- **Statement:** A source archive attached to a request in a new chat is material for that request [BR-001]. The system does not import it as a deck it can change, does not restore its history and does not convert it. The new deck needs its own outline, its own confirmation of the outline and of the generation format, and its own slide generation. No code from the archive runs [NFR-004].
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · The archive is material, not a deck

- **Given:** A new chat with no deck. The user attaches a source archive of an HTML deck of six slides and asks for a Marp deck on the same content.
- **When:** The system works on the request.
- **Then:**
  - The deck canvas shows no slide before a new outline is confirmed.
  - The conversation of the earlier chat does not appear in this chat.
  - The system shows a new outline proposal drafted from the material.
- **Check:** deterministic

### AC-2 · The new deck passes both confirmations

- **Given:** The state of AC-1.
- **When:** The user confirms the outline.
- **Then:**
  - The system asks for the confirmation of the generation format.
  - The deck has no slide before that confirmation.
- **Check:** deterministic

### AC-3 · No code from the archive runs

- **Given:** A source archive that holds scripts.
- **When:** The system reads the archive as material.
- **Then:**
  - No script from the archive runs [NFR-004].
  - The archive itself is not changed.
- **Check:** deterministic

### AC-4 · The content is used as material

- **Given:** The state of AC-1.
- **When:** The system drafts the outline.
- **Then:**
  - The outline uses the content of the archive as material.
  - The system does not say that it converted the earlier deck.
- **Check:** judged
