---
id: FR-109
title: "Leave design setup without saving"
---

## Requirement

- **Statement:** When the user leaves the design-rule setup before saving, the system applies no unsaved change. It saves no new design system and no new visual style. Every saved definition stays as it was. Leaving sends no request.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A new definition is not saved

- **Given:** The user proposed a custom visual style named "Report" and has not saved it. No visual style is named "Report".
- **When:** The user leaves the design-rule setup before saving.
- **Then:**
  - No visual style named "Report" is offered.
  - Every saved design system and visual style is as it was.
  - No request starts.
- **Check:** deterministic

### AC-2 · A changed design system is not saved

- **Given:** The design system "Acme" is saved with a brand colour.
- **When:** The user changes the brand colour of "Acme" and leaves the design-rule setup before saving.
- **Then:**
  - "Acme" holds the earlier brand colour.
  - The design systems the user can choose are as they were.
- **Check:** deterministic

### AC-3 · A changed custom visual style is not saved

- **Given:** The custom visual style "Report" is saved with density rules.
- **When:** The user changes the density rules of "Report" and leaves the design-rule setup before saving.
- **Then:**
  - "Report" holds the earlier density rules.
  - The visual styles the user can choose are as they were.
- **Check:** deterministic

## Notes

- FR-044 covers leaving the model setup without unsaved changes. This requirement covers the design-rule setup, for a design system or a custom visual style.
