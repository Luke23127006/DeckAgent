id: FR-055
title: "Choose the selected model of a chat"
---

## Requirement

- **Statement:** The user can choose the selected model of the current chat among the selectable models of every provider configuration, and a reasoning level of the model they chose [BR-005] [BR-?: reasoning levels]. The system shows the selectable models grouped by provider configuration. Each group is named by the display name of its provider configuration. It shows the reasoning levels of each model only where the model has them. A model with no reasoning levels shows none, and the request of the chat runs with none. When the user chooses a model that does not have the level the chat had chosen, the chat keeps no chosen level until the user chooses one that the model has. The chosen model and level stay selected in that chat until the user chooses another, or until the model is removed. A removed model leaves the chat with no selected model, as FR-065 says. The user can choose also while a request is active. Choosing sends, starts and stops no request, and changes no attachment.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Selectable models, grouped and named

- **Given:** Two provider configurations are saved. "DeepSeek" connects to provider Q and has the added models Q1 and Q2. "Work AI" connects to provider P and has the added model P1. Chat X has the selected model Q1.
- **When:** The user chooses to change the model in chat X.
- **Then:**
  - The system shows two groups, named "DeepSeek" and "Work AI".
  - The group "DeepSeek" holds Q1 and Q2. The group "Work AI" holds P1.
  - The system shows no model in either group that the user did not add.
  - The system shows Q1 of "DeepSeek" as the selected model.
- **Check:** deterministic

### AC-2 · The choice belongs to the chat

- **Given:** The state of AC-1. Chat Y also has the selected model Q1. No request is active. The request area of chat X holds the request text "a talk on our pilot results". It also holds the ready attachment "notes.docx" and the rejected attachment "big.pdf".
- **When:** The user chooses Q2 in chat X.
- **Then:**
  - Chat X shows Q2 as its selected model.
  - Chat Y still has Q1 as its selected model.
  - No request starts, and the conversation shows no new message.
  - The request area holds the same request text. "notes.docx" is still ready, and "big.pdf" is still rejected.
- **Check:** deterministic

### AC-3 · Choosing while a request is active

- **Given:** The state of AC-1. Chat X has an active request, in two separate runs. In one run, the system works on it. In the other, the system waits for the user's answer.
- **When:** In each run, the user chooses Q2 in chat X.
- **Then:**
  - In each run, chat X shows Q2 as its selected model.
  - The request is still active. The system did not stop it or start it again.
  - No other request starts.
- **Check:** deterministic

### AC-4 · A model of another provider configuration

- **Given:** The state of AC-1. No request is active.
- **When:** The user chooses P1 of "Work AI" in chat X.
- **Then:**
  - Chat X shows P1 of "Work AI" as its selected model.
  - No request starts.
- **Check:** deterministic

### AC-5 · Levels are shown only where the model has them

- **Given:** The state of AC-1. In this example Q1 has the reasoning levels L1 and L2, and P1 has none [BR-?: reasoning levels]. Chat X has Q1 with L1 chosen.
- **When:** The user opens the choice of model in chat X.
- **Then:**
  - The group "DeepSeek" shows Q1 with the levels L1 and L2, and L1 as chosen.
  - The group "Work AI" shows P1 with no levels.
- **Check:** deterministic

### AC-6 · A level the new model does not have is not kept

- **Given:** The state of AC-5. Q1 has the levels L1 and L2; P1 has none.
- **When:** The user chooses P1 in chat X.
- **Then:**
  - Chat X shows P1 as its selected model and no chosen reasoning level.
  - No request starts.
- **Check:** deterministic

### AC-7 · A model without levels runs with none

- **Given:** The state after AC-6. Chat X has P1 as its selected model and no chosen level. A test account with provider P records each request it receives, including what the request names of reasoning.
- **When:** The user sends a request in chat X.
- **Then:**
  - P receives the request for model P1. It names no reasoning level as chosen in the chat.
- **Check:** deterministic

## Notes

- Which model runs a request is covered by FR-042. Choosing a model changes no attachment, as FR-017 also says. A removed model and a deleted provider configuration are covered by FR-059 and FR-063.
- A chat whose selected model was removed shows no selected model, as FR-065 says.
- A request keeps the model and the reasoning level it started with (FR-042).
- The levels and their API values per provider wait for evidence [BR-?: reasoning levels].
