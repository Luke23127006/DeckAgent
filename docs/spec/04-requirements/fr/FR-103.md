---
id: FR-103
title: "Derive reusable visual rules from a source"
---

## Requirement

- **Statement:** The user can create a custom visual style from a built-in or custom visual style, from the current deck, or from a reference presentation. The system takes reusable visual rules, and copies no content, figures or fixed slide order. It names brand-specific rules and slide-specific exceptions, and keeps them out of the global rules unless the user chooses them. It names the material it cannot interpret. The source stays unchanged.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A new style starts from an existing one

- **Given:** The built-in visual style "Editorial" is saved. A chat holds a deck.
- **When:** The user starts a custom visual style from "Editorial" and saves it as "Report".
- **Then:**
  - "Report" holds the reusable rules of "Editorial".
  - "Editorial" holds the same rules as before.
  - No deck changed.
- **Check:** deterministic

### AC-2 · A deck gives rules and no content

- **Given:** A chat holds a deck of five slides. Its text names a client, its figures give the results of a pilot, and its slides follow a fixed order.
- **When:** The user creates a custom visual style from that deck.
- **Then:**
  - The proposed rules cover the layout, density and heading treatment of the deck.
  - The proposal holds no text and no figure of the deck.
  - The proposal holds no fixed slide order.
  - Every slide of the deck is as it was.
- **Check:** deterministic

### AC-3 · Brand-specific rules and exceptions are named

- **Given:** A deck follows a client brand in a client-specific colour, and one slide has a layout that no other slide uses.
- **When:** The user creates a custom visual style from that deck.
- **Then:**
  - The system names the client-specific colour as a brand-specific rule.
  - The system names the one-slide layout as a slide-specific exception.
  - Neither becomes a rule of the proposed visual style without the user's choice.
  - Nothing is saved before the user decides.
- **Check:** judged

### AC-4 · Unreadable reference material is named

- **Given:** The user gives a reference presentation whose charts the system cannot interpret.
- **When:** The system has read the reference presentation.
- **Then:**
  - The system names the charts it cannot interpret.
  - The proposed visual style holds no chart rule taken from them.
- **Check:** judged
