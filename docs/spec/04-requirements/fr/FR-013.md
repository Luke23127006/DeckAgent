---
id: FR-013
title: "Send an instruction through a suggested option"
---

## Requirement

- **Statement:** Choosing a suggested option sends its instruction at once, as the user's message. The result is the same as for the same instruction typed and sent. Unsent request text and attachments stay in the request area. The system does not accept an option whose instruction no longer fits the chat. It then keeps the chat as it was and says that the option no longer applies.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: a suggested option is a shortcut for an instruction; owner decision, 2026-10-13: an option that no longer applies runs no outdated action; the current state stays and the user is told
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Option sends its instruction at once

- **Given:** The system shows an outline proposal and offers suggested options for it. The request area is empty. No request is active.
- **When:** The user chooses the option to confirm the outline and does nothing else.
- **Then:**
  - The instruction of the option shows in the conversation as the user's message.
  - The request area never shows the instruction.
  - The system starts to work on the instruction without a further action of the user.
- **Check:** deterministic

### AC-2 · Unsent text and attachments stay

- **Given:** The system shows an outline proposal and offers suggested options for it. No request is active. The request area holds the unsent request text "use a darker theme" and a ready attachment "budget.docx".
- **When:** The user chooses the option to confirm the outline.
- **Then:**
  - The user's message in the conversation has the instruction of the option only.
  - It has neither "use a darker theme" nor "budget.docx".
  - The request area still holds "use a darker theme" and "budget.docx", unchanged.
- **Check:** deterministic

### AC-3 · Same instruction as the typed one

- **Given:** Two chats in the same state. Each offers a suggested option whose instruction is "add a slide on costs". No request is active.
- **When:** In the first chat, the user types "add a slide on costs" and sends it. In the second chat, the user chooses the option.
- **Then:**
  - In both chats, the conversation shows "add a slide on costs" as the user's message.
  - In both chats, the system starts to work on that message.
- **Check:** deterministic

### AC-4 · Option that no longer fits is not accepted

- **Given:** The system showed proposal A with an option to confirm it. The user then asked for a revision. Proposal B is now the current outline. No request is active.
- **When:** The user chooses the option to confirm that was offered with proposal A.
- **Then:**
  - No outline proposal is confirmed.
  - The conversation shows no new user's message.
  - No request starts.
  - Proposals A and B are the same as before.
- **Check:** deterministic

### AC-5 · Way of sending does not change the meaning

- **Given:** The state after AC-3. The system has responded in both chats.
- **When:** A person compares the two responses.
- **Then:**
  - Both responses follow the same instruction, "add a slide on costs".
  - Neither response treats the instruction from the option as a different or wider instruction than the typed one.
- **Check:** judged

### AC-6 · The user is told the option no longer applies

- **Given:** The state of AC-4.
- **When:** The user chooses the option to confirm that was offered with proposal A.
- **Then:**
  - The system says that the option no longer applies.
- **Check:** judged

## Notes

- A suggested option chosen while the system waits for an answer is that answer. FR-020 covers it.
- This requirement does not say which request the instruction belongs to. The requirements of the action say it, for example FR-003 for a confirmation.
