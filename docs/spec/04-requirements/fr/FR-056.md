---
id: FR-056
title: "Send no request without a selectable selected model"
---

## Requirement

- **Statement:** A chat can have no selected model. It never had one, or its selected model was removed [BR-005]. Other models are selectable. When the user tries to send a request there, the system does not send it and starts no work. It says that the user must choose a model, and why. It chooses no model by itself and does not open the model setup. The request text and the attachments stay in the request area, and no earlier request is sent again.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: the system never replaces a selected model by itself, and the user chooses a selectable model before a new request starts; owner decision, 2026-10-12: a removed model, a deleted provider configuration or a restore that removes the selected model leaves the chat with no selected model; a provider ID never changes
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · The selected model was removed

- **Given:** The provider configuration "Work AI" has the key K1 and the added models M1 and M2. Chat X has the selected model M1. Earlier request R1 in chat X ended. The user then removed M1 from "Work AI". The request area of chat X holds "a talk on our pilot results".
- **When:** The user tries to send the request in chat X.
- **Then:**
  - No request starts, and the conversation shows no new user's message.
  - R1 shows once in the conversation, and it is not sent again.
  - The request area still holds "a talk on our pilot results".
  - The system has selected no other model in chat X.
  - The model setup is not opened.
- **Check:** deterministic

### AC-2 · The user is told what to do

- **Given:** The state after AC-1.
- **When:** The user reads the response.
- **Then:**
  - The response says that the selected model of the chat was removed.
  - The response says that the user must choose another model.
- **Check:** judged

### AC-3 · Sending after a choice

- **Given:** The state after AC-1. A test account with the provider of "Work AI" records each request it receives.
- **When:** The user chooses M2 and sends the request.
- **Then:**
  - The conversation shows "a talk on our pilot results" as a new user's message.
  - The provider receives the request for model M2 with the key K1.
- **Check:** deterministic

### AC-4 · A new chat with no model selected before

- **Given:** The user saved the first provider configuration and added the models M1 and M2. No model was selected in any chat. The user starts a new chat.
- **When:** The user writes "a talk on our pilot results" and tries to send it.
- **Then:**
  - No request starts.
  - The request area still holds "a talk on our pilot results".
  - The system has selected no model in the new chat.
- **Check:** deterministic

### AC-6 · The provider configuration of the selected model was deleted

- **Given:** "Work AI" connects to provider P with the added model M1. "Lab" is a custom model API at the base URL U1 with the added model M2. Chat X has M1 of "Work AI" as its selected model. The user deleted "Work AI". The request area of chat X holds "add a slide on costs". Test accounts with P and at U1 record each request they receive.
- **When:** The user tries to send the request in chat X.
- **Then:**
  - No request starts, and the conversation shows no new user's message.
  - P and U1 receive no request.
  - The request area still holds "add a slide on costs".
  - The system has selected no other model in chat X. M2 of "Lab" is not its selected model.
- **Check:** deterministic

## Notes

- No selectable model at all is covered by FR-046. Choosing a model is covered by FR-055. Deleting a provider configuration is covered by FR-063.
- A failed request, a refused key or model, or a reached limit while a request runs is covered by FR-019.
- Until 2026-10-12, AC-1 made the selected model unavailable through a new key. Under the owner decision of 2026-10-12 on added models, a new key keeps the models. So AC-1 now uses a removed model.
- AC-5, "A selected model kept from an earlier provider", was removed on 12-10-2026. The owner decision of 2026-10-12 on provider IDs allows no change of provider. AC IDs are not renumbered.
- How the chat shows a removed selected model before any request is covered by FR-065.
- Until 2026-10-12, the Source said that a removed model or a deleted provider configuration kept the selection as it was. The owner decision of 2026-10-12 on removed models replaced it: the chat then has no selected model.
