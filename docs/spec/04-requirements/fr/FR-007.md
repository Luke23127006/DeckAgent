---
id: FR-007
title: "Ask what the user means for the outline"
---

## Requirement

- **Statement:** A message about the current outline can have meanings that lead to very different results. The system then asks one focused question and changes nothing until the user answers. The answer then confirms, cancels or revises the outline, or uses an earlier proposal, within the same request.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Unclear confirmation is not acted on

- **Given:** The conversation shows proposal A, then proposal B. B is the current outline. Nothing after B shows whether the user wants to confirm or revise. No request is active. The deck has no slide.
- **When:** The user sends "OK?".
- **Then:**
  - No outline proposal is confirmed.
  - No new outline proposal appears.
  - Proposals A and B are the same as before the message.
  - The deck has no slide.
  - The system asks a question in the conversation.
- **Check:** deterministic

### AC-2 · Question about the intent is focused

- **Given:** The state of AC-1.
- **When:** The system asks its question.
- **Then:**
  - The question helps the user tell apart the actions that would lead to very different results in this conversation.
  - The question asks only what the user needs to settle before the system goes on.
  - Each suggested option offered with it stands for an intention that fits this conversation.
- **Check:** judged

### AC-3 · Unclear earlier reference changes nothing

- **Given:** The conversation shows proposals A, B and C. C is the current outline. No request is active.
- **When:** The user sends "use the earlier outline".
- **Then:**
  - No new outline proposal appears.
  - Proposals A, B and C are the same as before the message.
  - No outline proposal is confirmed.
  - The deck has no slide.
  - The system asks a question in the conversation.
- **Check:** deterministic

### AC-4 · Question about the earlier proposal is focused

- **Given:** The state of AC-3.
- **When:** The system asks its question.
- **Then:**
  - The question asks which earlier outline proposal the user means.
  - Each suggested option offered with it helps the user say which proposal they mean.
- **Check:** judged

### AC-5 · Answer in the user's own words

- **Given:** The system asked the question of AC-4 and offered suggested options.
- **When:** The user chooses no option and answers "go back to the very first one".
- **Then:**
  - The system takes the answer as a request to use proposal A again.
  - It goes on with that action, not with another one.
- **Check:** judged

### AC-6 · Clear message gets no question

- **Given:** The conversation shows proposal B as the current outline. No request is active.
- **When:** The user sends "Confirm this outline and create the slides".
- **Then:**
  - The system asks no question.
  - The system shows that proposal B is confirmed.
- **Check:** deterministic

## Notes

- Waiting for the answer, a reply that does not settle the question, and stopping while the system waits are shared request behavior. Later requirements cover them.
