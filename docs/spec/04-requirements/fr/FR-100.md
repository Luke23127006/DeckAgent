---
id: FR-100
title: "Create and preview a custom visual style"
---

## Requirement

- **Statement:** The system turns the presentation design the user describes into reusable visual rules. It shows the proposed rules and representative previews for different slide types. It lets the user revise the rules before saving. It names missing or contradictory rules. It saves no visual style before the user saves.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A description becomes reusable rules with previews

- **Given:** The user describes a dense editorial design with large headings and line charts. A chat holds a deck of five slides.
- **When:** The system shows the proposed visual style.
- **Then:**
  - The proposed rules cover layout, density, heading treatment, visual hierarchy and chart presentation.
  - The previews show the rules on more than one kind of slide.
  - Every slide of the deck is as it was.
- **Check:** judged

### AC-2 · The user revises the rules before saving

- **Given:** The state of AC-1. The proposed visual style is not saved.
- **When:** The user changes the heading treatment.
- **Then:**
  - The previews follow the changed heading treatment.
  - No visual style is saved yet.
- **Check:** deterministic

### AC-3 · Missing or contradictory rules are named

- **Given:** The user describes two layout preferences that cannot both hold.
- **When:** The system reviews the proposed visual style.
- **Then:**
  - The system names both preferences and the conflict.
  - The system saves nothing.
  - The user can correct the rules.
- **Check:** judged

### AC-4 · No deck changes before saving

- **Given:** A chat holds a deck of five slides.
- **When:** The user reviews and revises a proposed visual style.
- **Then:**
  - Every slide of the deck is as it was.
  - No slide is rebuilt.
- **Check:** deterministic
