---
id: FR-046
title: "Send no request when no model is selectable"
---

## Requirement

- **Statement:** No model is selectable [BR-005] when no provider configuration is saved, or none has an added model. When the user then tries to send a request, the system does not send it and starts no work. It says which of the two holds, and where models are set up. The request text and the attachments stay in the request area, and nothing moves into the conversation.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: a missing provider configuration, a missing model and a missing selection get different responses, and the system points to the model setup only when no model is selectable; owner decision, 2026-10-12: each added model of a saved provider configuration is selectable
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · The request stays unsent

- **Given:** No provider configuration is saved. A chat with no active request. The request area holds the request text "a talk on our pilot results" and the attachment "notes.docx".
- **When:** The user tries to send the request.
- **Then:**
  - The conversation shows no new user's message.
  - The request area still holds the request text and "notes.docx", unchanged.
  - The system does not show that it works.
  - No provider configuration is saved afterwards.
- **Check:** deterministic

### AC-2 · The user is told what is needed

- **Given:** The state after AC-1.
- **When:** The user reads the response.
- **Then:**
  - The response says that no provider configuration is saved.
  - The response says where the user sets up models.
- **Check:** judged

### AC-3 · The kept request can be sent later

- **Given:** The state after AC-1.
- **When:** The user saves a provider configuration and adds the model M to it. The user goes back to the chat, chooses M and sends the request.
- **Then:**
  - The conversation shows the request text and "notes.docx" as the user's message.
  - The system works on the request.
- **Check:** deterministic

### AC-4 · A provider configuration with no added model

- **Given:** The provider configuration "Work AI" is saved and has no added model. No other provider configuration is saved. The request area holds "a talk on our pilot results".
- **When:** The user tries to send the request.
- **Then:**
  - The conversation shows no new user's message.
  - The request area still holds "a talk on our pilot results".
  - The system does not show that it works.
- **Check:** deterministic

### AC-5 · The response tells the cases apart

- **Given:** The state after AC-4.
- **When:** The user reads the response.
- **Then:**
  - The response says that no model is added.
  - The response does not say that no provider configuration is saved.
  - The response says where the user sets up models.
- **Check:** judged

## Notes

- Opening the model setup keeps the chat, as FR-038 says. A chat with no selectable selected model, while other models are selectable, is covered by FR-056. Whether the system opens the setup by itself at the first start is not covered here.
- A provider that refuses a request is not covered here. FR-019 covers it.
- Until 2026-10-12, a third case was an added model that is not selectable. Under the owner decision of 2026-10-12 on provider IDs, each added model of a saved provider configuration is selectable.
