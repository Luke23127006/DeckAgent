---
id: FR-046
title: "Start no work when no model is set up"
---

## Requirement

- **Statement:** When the user tries to send a request and no model is set up, the system starts no work. It says that a model is needed and where models are set up. The request text and the attachments stay in the request area, and nothing moves into the conversation.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · The request stays unsent

- **Given:** No model is set up. A chat with no active request. The request area holds the request text "a talk on our pilot results" and the attachment "notes.docx".
- **When:** The user tries to send the request.
- **Then:**
  - The conversation shows no new user's message.
  - The request area still holds the request text and "notes.docx", unchanged.
  - The system does not show that it works.
  - No model is set up afterwards.
- **Check:** deterministic

### AC-2 · The user is told what is needed

- **Given:** The state after AC-1.
- **When:** The user reads the response.
- **Then:**
  - The response says that a model is needed to run the request.
  - The response says where the user sets up a model.
- **Check:** judged

### AC-3 · The kept request can be sent later

- **Given:** The state after AC-1. The model the user sets up can read the type of "notes.docx".
- **When:** The user sets up the model, goes back to the chat and sends the request.
- **Then:**
  - The conversation shows the request text and "notes.docx" as the user's message.
  - The system works on the request.
- **Check:** deterministic

## Notes

- Opening the model setup keeps the chat, as FR-038 says. Whether the system opens the setup by itself at the first start is not covered here.
