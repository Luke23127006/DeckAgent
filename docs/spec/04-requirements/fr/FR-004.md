id: FR-004
title: "Cancel the outline"
---

## Requirement

- **Statement:** The system offers to cancel an unconfirmed outline. A clear cancellation cancels the current outline and says so, in a new request or in the request that asked. The system keeps every outline proposal in the conversation, builds no slide and drafts no new outline by itself.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Cancellation is offered

- **Given:** The system has shown an outline proposal. It is the current outline and is not confirmed.
- **When:** The user reads the proposal.
- **Then:**
  - The system offers to cancel the outline as a suggested option.
- **Check:** deterministic

### AC-2 · Cancel keeps every proposal and builds nothing

- **Given:** The conversation shows proposal A, then proposal B after a revision. B is the current outline. The deck has no slide.
- **When:** The user sends "Cancel the outline" and sends nothing else.
- **Then:**
  - The cancellation shows in the conversation as the user's message.
  - Proposals A and B are still in the conversation, the same as before the cancel.
  - No outline proposal is confirmed.
  - The deck has no slide.
  - The system shows no deck canvas.
  - No new outline proposal appears.
- **Check:** deterministic

### AC-3 · Suggested option has the same result

- **Given:** The state of AC-2. The system offers to cancel the outline as a suggested option.
- **When:** The user chooses that option and sends nothing else.
- **Then:**
  - The outcomes are the same as in AC-2.
- **Check:** deterministic

### AC-4 · Notice says the user cancelled

- **Given:** An unconfirmed current outline.
- **When:** The user cancels the outline.
- **Then:**
  - The system shows a notice that says the user cancelled the outline.
- **Check:** judged

### AC-5 · Cancellation given as an answer

- **Given:** The conversation shows proposals A and B. B is the current outline. The system asked what the user wants to do with B, and waits for the answer.
- **When:** The user answers "Cancel it" and sends nothing else.
- **Then:**
  - Proposals A and B are still in the conversation, the same as before.
  - No outline proposal is confirmed.
  - The deck has no slide.
  - No new outline proposal appears.
  - The answer is part of the request that asked.
  - No second request starts.
- **Check:** deterministic

## Not specified

- What the system does when the user sends a new request after cancelling the outline, including whether it drafts a new outline or uses a cancelled proposal. Pending owner decision.
