---
id: FR-039
title: "Show the model setup and what a provider needs"
---

## Requirement

- **Statement:** The model setup shows each saved provider configuration with its display name, its provider ID and its added models. Or it says that none is saved. It shows the built-in providers the user can choose [BR-005], except each one that a saved provider configuration uses [BR-008]. It lets the user describe a custom model API instead, with the API protocols it can use [BR-005]. For a chosen provider, it says what the provider needs before its models can run [BR-006]. It says that the key comes from the user's own account with the provider. It says that each request run through the provider configuration goes to that provider.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: the user can save several provider configurations and adds models to each; owner decision, 2026-10-12: a provider configuration connects to a built-in provider or to a custom model API
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Nothing saved yet

- **Given:** No provider configuration is saved.
- **When:** The user opens the model setup.
- **Then:**
  - The setup says that no provider configuration is saved.
  - The setup lets the user add a provider configuration.
- **Check:** deterministic

### AC-2 · Each saved provider configuration

- **Given:** Two provider configurations are saved. "DeepSeek" connects to provider Q and has the added models Q1 and Q2. "Work AI" connects to provider P and has no added model.
- **When:** The user opens the model setup.
- **Then:**
  - The setup shows "DeepSeek" with provider Q and the added models Q1 and Q2.
  - The setup shows "Work AI" with provider P and no added model.
- **Check:** deterministic

### AC-3 · Needs of a chosen provider

- **Given:** The state of AC-1.
- **When:** The user chooses to add a provider configuration, and chooses provider P.
- **Then:**
  - The setup shows what P needs before its models can run [BR-006].
- **Check:** deterministic

### AC-4 · Whose key, and where requests go

- **Given:** The state after AC-3.
- **When:** The user reads the setup for provider P.
- **Then:**
  - The setup says that the key comes from the user's own account with P.
  - The setup says that each request run through this provider configuration goes to P.
- **Check:** judged

### AC-5 · Providers to choose from

- **Given:** The state of AC-2.
- **When:** The user chooses to add a provider configuration.
- **Then:**
  - The setup shows each built-in provider that the user can choose [BR-005], other than P and Q.
  - The setup still shows "DeepSeek" and "Work AI" as saved.
- **Check:** deterministic

### AC-6 · A custom model API

- **Given:** The state of AC-1.
- **When:** The user chooses to add a provider configuration, and chooses to describe a custom model API.
- **Then:**
  - The setup shows each API protocol that a custom model API can use [BR-005].
  - The setup asks for a provider ID, a base URL and an API protocol [BR-006].
- **Check:** deterministic

## Notes

- No provider or model is named here. The offered providers are values of BR-005.
- Until 2026-10-12, the setup showed the one model set up and the models of a chosen provider. Then it showed one provider configuration. The owner decisions of 2026-10-12 moved the choice of model to the chat (FR-055), and allowed several provider configurations.
