---
id: FR-115
title: "Confirm the generation format before building slides"
---

## Requirement

- **Statement:** After the outline is confirmed, the system asks the user to confirm the generation format, also when the request named one. The request that confirmed the outline stays active and waits for that answer. The system builds no slide before the user confirms an available generation format. A rejected or unavailable format returns the user to the choice. Stopping the request while it waits keeps the confirmed outline and builds no slide.
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · The confirmation joins the waiting request

- **Given:** The user confirmed an outline of four planned slides. The system proposed HTML and waits for the confirmation of the generation format.
- **When:** The user confirms HTML.
- **Then:**
  - The confirmation is part of the request that confirmed the outline.
  - No second request starts.
  - The system starts building the slides in HTML.
- **Check:** deterministic

### AC-2 · No confirmation, no slide

- **Given:** The state of AC-1, before the user confirms.
- **When:** The user sends no confirmation of the generation format.
- **Then:**
  - The deck has no slide.
  - The confirmed outline is the same as at its confirmation.
  - The request still waits for the answer.
- **Check:** deterministic

### AC-3 · A named format still needs the confirmation

- **Given:** The request said "make it in Slidev". The user confirmed the outline. Slidev is available.
- **When:** The system proposes Slidev.
- **Then:**
  - The system asks the user to confirm the generation format.
  - The deck has no slide before that confirmation.
- **Check:** deterministic

### AC-4 · Rejected or unavailable format returns to the choice

- **Given:** The system waits for the confirmation of the generation format. The user asks for a format that the system cannot build.
- **When:** The system responds.
- **Then:**
  - The system says why that format cannot be used.
  - The system shows the available formats and asks for a new confirmed choice.
  - The deck has no slide.
- **Check:** deterministic

### AC-5 · Stop while waiting keeps the confirmed outline

- **Given:** The state of AC-1, before the user confirms.
- **When:** The user stops the request.
- **Then:**
  - The request ends.
  - The confirmed outline stays in the conversation, confirmed and read-only.
  - The deck has no slide.
  - A later request in this chat asks for the confirmation of the generation format before any slide.
- **Check:** deterministic

## Notes

- The wait and the reply follow FR-020. The stop follows FR-018.
