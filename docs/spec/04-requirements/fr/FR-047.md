---
id: FR-047
title: "Report an outline that was not drafted"
---

## Requirement

- **Statement:** The work can fail while the system drafts a first outline or revises an outline that is not confirmed. The system then says that the outline was not drafted. Every outline proposal shown before the request stays as it was. The failed request confirms no outline proposal and builds no slide. An outline proposal that the system did not finish never becomes the current outline, and the user cannot confirm it. The system never presents it as a proposal to confirm. It says that the request did not finish. It offers no way to recover the unfinished outline.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: earlier outline proposals stay in the conversation as they were; owner decision, 2026-10-13: an unfinished outline is not the current outline that the user can confirm, and partial output is not a finished proposal; the user is told that the request did not finish; V1 has no special way to recover a partial outline
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Earlier proposals stay after a failed revision

- **Given:** The conversation shows proposal A, then proposal B. B is the current outline. Proposal B has not been confirmed. The user sent "add a slide on costs".
- **When:** The model provider returns an error before the system finishes the revised proposal.
- **Then:**
  - Proposals A and B are the same as before the request.
  - The failed request confirms no outline proposal.
  - The deck has no slide.
- **Check:** deterministic

### AC-2 · Failed revision is reported

- **Given:** The state after AC-1.
- **When:** The user reads the message about the failure.
- **Then:**
  - The message says that the revised outline was not drafted.
- **Check:** judged

### AC-3 · Failed first outline is reported

- **Given:** A chat with no deck. The user sent "a talk on our pilot results".
- **When:** The model provider returns an error before the system finishes the first outline proposal.
- **Then:**
  - The message says that the outline was not drafted.
- **Check:** judged

### AC-4 · An unfinished proposal is not the current outline

- **Given:** The state after AC-1. No request is active.
- **When:** The user sends "confirm the outline".
- **Then:**
  - The confirmed outline is proposal B, the same as before the failed request.
  - The confirmed outline holds nothing that only the unfinished revision had, such as a slide on costs.
- **Check:** deterministic

### AC-5 · No unfinished proposal to confirm

- **Given:** The state after AC-1, before the user sends anything.
- **When:** The user reads the conversation.
- **Then:**
  - The conversation says that the request did not finish.
  - No unfinished revision is offered for confirmation.
  - The system offers no way to recover the unfinished revision.
- **Check:** judged

## Notes

- Until 2026-10-13, whether the system shows an unfinished outline, and whether it can become current, were open. The owner decisions of 2026-10-13 settled both: it is never presented as a proposal to confirm, and never becomes current.
- The failure itself is covered by FR-019. Finished slides after a failure are covered by FR-025.
- A confirmed outline stays fixed, as FR-003 says. No outline work runs after the confirmation, so this requirement never changes a confirmed outline.
