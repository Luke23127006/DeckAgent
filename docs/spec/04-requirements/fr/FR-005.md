---
id: FR-005
title: "Revise the outline or use an earlier proposal"
---

## Requirement

- **Statement:** The system revises the current outline, or presents an earlier proposal again, as a clear instruction or an answer asks. It shows the result as a new response that becomes the current outline. Earlier outline responses stay unchanged, and the system builds no slide.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Revision is a new response

- **Given:** The conversation shows proposal A of four planned slides. A is the current outline.
- **When:** The user sends the instruction "add a slide on costs".
- **Then:**
  - A new outline response, proposal B, follows the instruction in the conversation.
  - Proposal A is still in the conversation, the same as before the instruction.
  - Proposal B is the latest outline response.
  - No outline proposal is confirmed.
  - The deck has no slide.
- **Check:** deterministic

### AC-2 · Revision follows the instruction

- **Given:** The state of AC-1.
- **When:** The user sends the instruction "add a slide on costs".
- **Then:**
  - Proposal B has a planned slide about costs.
- **Check:** judged

### AC-3 · Revision keeps what the instruction does not concern

- **Given:** The state of AC-1. Slide 2 of proposal A is about the pilot results.
- **When:** The user sends the instruction "add a slide on costs".
- **Then:**
  - Each planned slide of A that the instruction does not concern is still in B, with the same meaning.
  - Slide 2 of B is still about the pilot results.
- **Check:** judged

### AC-5 · Use an earlier proposal again

- **Given:** The conversation shows proposal A, then proposal B after the instruction "add a slide on costs". B is the current outline.
- **When:** The user sends "go back to the first outline".
- **Then:**
  - A new outline response follows the instruction.
  - It presents the planned slides of A again, in the order of A.
  - It has no planned slide about costs.
  - It is the latest outline response.
  - Proposals A and B are still in the conversation, the same as before.
  - The deck has no slide.
- **Check:** judged

### AC-6 · Revision given as an answer

- **Given:** The conversation shows proposals A, B and C. C is the current outline. The system asked which earlier proposal the user means, and waits for the answer.
- **When:** The user answers "the first one".
- **Then:**
  - A new outline response follows the answer.
  - It is the latest outline response.
  - Proposals A, B and C are still in the conversation, the same as before.
  - No outline proposal is confirmed.
  - The deck has no slide.
  - The answer is part of the request that asked. No second request starts.
- **Check:** deterministic

## Notes

- AC-5 does not require an exact copy of the earlier proposal. A person judges that the new response presents the same planned slides.
