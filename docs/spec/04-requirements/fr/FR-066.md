---
id: FR-066
title: "Use attached images and new images on slides"
---

## Requirement

- **Statement:** When it builds or changes slides, the system uses images. It places an image from an attachment of the chat on a slide that needs one. It also makes a new image for a slide that needs one [NFR-009]. It follows the request when it says which image or which kind of image to use. When the request does not say, and the choice changes the result a lot, it asks with suggested options. Otherwise it chooses within the request. It never changes the selected model, and never moves the work to another provider, to make an image [NFR-007]. The system cannot make an image when no valid way to make one is available, or when making it fails. A needed image is one the request asks for, or one without which the result does not meet the request. When the system cannot make a needed new image, the work cannot finish. The system leaves out a new image that it chose to add and cannot make. The closing message says that this image was not made.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-13: the agent can use images from the user's attachments on slides and can make new images for slides; how new images are made is not decided; no other model is chosen and no other provider is used to make an image; a capability that is missing follows the rules for a request that cannot finish; owner decision, 2026-10-13: the system follows a clear request for attached images or for new images; when the request does not say and the choice changes the result a lot, it asks with suggested options; otherwise it can choose within the request; owner decision, 2026-10-13: a new image the user asked for, or that the result cannot do without, that cannot be made ends the work as a request that cannot finish, with no other content in its place; a new image the agent chose to add that cannot be made is left out, and the closing message says so
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Attached image on the slide the request names

- **Given:** A chat with no deck. The request "a talk on our new ward, put my photo on the slide about the ward" has the attachment "ward.jpg". The user confirmed an outline with a planned slide about the ward.
- **When:** The system has built the slides.
- **Then:**
  - The slide about the ward shows the image of "ward.jpg".
  - The system asks no question about which kind of image to use.
- **Check:** deterministic

### AC-2 · New image on request

- **Given:** A chat with a deck of five slides. No request is active. No attachment of the chat holds an image.
- **When:** The user sends "add an illustration of a hospital ward to slide 2".
- **Then:**
  - Slide 2 shows an image that no attachment holds.
  - Slides 1, 3, 4 and 5 are the same as before the request.
  - The system asks no question about which kind of image to use.
- **Check:** deterministic

### AC-3 · New image fits the request

- **Given:** The state after AC-2.
- **When:** The user looks at slide 2.
- **Then:**
  - The new image shows a hospital ward.
- **Check:** judged

### AC-4 · Request that rules out new images

- **Given:** A chat with no deck. The request "a talk on our new ward, use only my photos, make no new images" has the attachments "ward.jpg" and "team.jpg". The user confirmed an outline.
- **When:** The system has built the slides.
- **Then:**
  - Each image on the slides comes from "ward.jpg" or "team.jpg".
- **Check:** deterministic

### AC-5 · Making the image the user asked for fails

- **Given:** Chat X has the selected model M1 of the provider configuration "Work AI". The provider configuration "Home AI" is also saved. Chat X has a deck of five slides. In this test, every attempt to make a new image fails.
- **When:** The user sends "add an illustration of a hospital ward to slide 2" in chat X.
- **Then:**
  - Chat X still has M1 as its selected model.
  - No request for this work goes to "Home AI".
  - The conversation shows that the work did not finish.
  - Slide 2 is the same as before the request. It holds no other content in place of the image.
- **Check:** deterministic

### AC-6 · No valid way to make the image the user asked for

- **Given:** A chat with a deck of five slides. In this test, no valid way to make a new image is available for the request.
- **When:** The user sends "add an illustration of a hospital ward to slide 2".
- **Then:**
  - The conversation shows that the work did not finish.
  - The conversation says that the new image was not made.
  - Slide 2 is the same as before the request. It holds no other content in place of the image.
  - No user content goes to a service other than the provider of the selected model.
- **Check:** judged

### AC-7 · Unclear kind of image that changes the result

- **Given:** A chat with a deck of five slides for the hospital board. The attachment "ward-photos.pdf" holds photos of the new ward. No request is active.
- **When:** The user sends "add a picture of the new ward to slide 2".
- **Then:**
  - Slide 2 is the same as before the request.
  - The system waits for the user's answer within the request.
  - The question offers suggested options.
- **Check:** deterministic

### AC-8 · The options name the two kinds of image

- **Given:** The state after AC-7.
- **When:** The user reads the question.
- **Then:**
  - One option uses a photo from "ward-photos.pdf".
  - One option makes a new image.
- **Check:** judged

### AC-9 · An image the system chose to add is left out

- **Given:** The user confirmed an outline of four planned slides. The request asked for no image. In this test, the system plans a new image for the first slide, and making it fails.
- **When:** The system has built the slides.
- **Then:**
  - The work finishes, and the deck has four slides.
  - The first slide shows no new image.
- **Check:** deterministic

### AC-10 · The closing message names the image not made

- **Given:** The state after AC-9.
- **When:** The user reads the closing message.
- **Then:**
  - The message says that the planned image for the first slide was not made.
  - The message does not say that this image was made.
- **Check:** judged

### AC-11 · The result cannot do without the image

- **Given:** A chat with a deck of five slides. No attachment of the chat holds an image. In this test, every attempt to make a new image fails.
- **When:** The user sends "add a gallery slide of hospital wards at the end".
- **Then:**
  - The conversation shows that the work did not finish.
  - The deck has five slides, the same as before the request.
- **Check:** deterministic

## Notes

- Reading images, making new images and placing an existing image on a slide are separate capabilities. A selected model that gives no image output does not by itself mean that the system cannot make an image.
- How the system makes a new image, and how it knows that a valid way is available, is an architecture matter. Any service other than the provider of the selected model needs an owner approval first [NFR-007].
- A work that cannot finish follows FR-019 for the message, and FR-025 for the slides already finished. A request that changes the deck keeps every slide outside its scope (FR-027).
- A new image is content that did not come from the user's material. FR-024 covers how the closing message of a first draft names such content. FR-029 covers the closing message of a change to the deck.
- The question about the kind of image waits within the request, as FR-020 says. A clear request gets no such question.
- Which files the system accepts as attachments is set by BR-001. Using images from attachments approves no file type.
- The number of conditions is more than the reading guide of seven. They share one purpose: the right image, or a clear account of the image that was not made.
