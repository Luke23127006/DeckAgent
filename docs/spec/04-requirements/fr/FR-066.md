---
id: FR-066
title: "Use attached images and new images on slides"
---

## Requirement

- **Statement:** When it builds or changes slides, the system uses images. It places an image from an attachment of the chat on a slide that needs one. It also makes a new image for a slide that needs one [NFR-009]. It follows the request when it says which image or which kind of image to use. It never changes the selected model, and never moves the work to another provider, to make an image [NFR-007]. An image the request asks for that the system cannot make is work that cannot finish.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-13: in V1 the agent can use images from the user's attachments on slides and can make new images for slides; how new images are made is not decided; no other model is chosen and no other provider is used to make an image; a capability that is missing follows the rules for a request that cannot finish
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Attached image on the slide the request names

- **Given:** A chat with no deck. The request "a talk on our new ward, put my photo on the slide about the ward" has the attachment "ward.jpg". The user confirmed an outline with a planned slide about the ward.
- **When:** The system has built the slides.
- **Then:**
  - The slide about the ward shows the image of "ward.jpg".
- **Check:** deterministic

### AC-2 · New image on request

- **Given:** A chat with a deck of five slides. No request is active. No attachment of the chat holds an image.
- **When:** The user sends "add an illustration of a hospital ward to slide 2".
- **Then:**
  - Slide 2 shows an image that no attachment holds.
  - Slides 1, 3, 4 and 5 are the same as before the request.
- **Check:** deterministic

### AC-3 · New image fits the request

- **Given:** The state after AC-2.
- **When:** The user looks at slide 2.
- **Then:**
  - The new image shows a hospital ward.
- **Check:** judged

### AC-4 · Request that rules out new images

- **Given:** A chat with no deck. The request "a talk on our new ward, use only my photos, make no new images" has the attachments "ward.jpg" and "team.jpg". The user confirmed an outline.
- **When:** The system has built the slides.
- **Then:**
  - Each image on the slides comes from "ward.jpg" or "team.jpg".
- **Check:** deterministic

### AC-5 · No other model or provider for an image

- **Given:** Chat X has the selected model M1 of the provider configuration "Work AI". The provider configuration "Home AI" is also saved. Chat X has a deck of five slides. In this test, every attempt to make a new image fails.
- **When:** The user sends "add an illustration of a hospital ward to slide 2" in chat X.
- **Then:**
  - Chat X still has M1 as its selected model.
  - No request for this work goes to "Home AI".
  - The conversation shows that the work did not finish.
  - Slide 2 is the same as before the request.
- **Check:** deterministic

## Not specified

- Whether the system asks first when the material holds images and the request does not say whether to use them or make new ones. Pending owner decision.
- What the system does when a new image that the request did not ask for cannot be made. Pending owner decision.

## Notes

- How the system makes a new image is an architecture matter. Any service other than the provider of the selected model needs an owner approval first [NFR-007].
- A new image is content that did not come from the user's material. FR-024 covers how the closing message of a first draft names such content.
- Which files the system accepts as attachments is set by BR-001. Using images from attachments approves no file type.
- A request that says nothing about images can still lead to a question, as FR-020 says, when the choice changes the result a lot.
