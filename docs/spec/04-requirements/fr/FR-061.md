---
id: FR-061
title: "Keep each provider ID to one provider configuration that never changes it"
---

## Requirement

- **Statement:** Each provider ID has at most one saved provider configuration [BR-008]. The system saves no second provider configuration with the provider ID of a saved one. This holds for a built-in provider and for a custom model API. It offers no built-in provider for a new provider configuration when a saved one uses it. When a save repeats a provider ID, it says that one is saved and gives its display name. It keeps the saved one as it was. For a custom model API, it keeps what the user gave. The provider ID of a saved provider configuration never changes. Custom model APIs with different provider IDs can share an API protocol and a base URL. A custom model API never takes the provider ID of a built-in provider [BR-008]. This holds also while that provider has no saved provider configuration. The system then saves nothing, says that the provider ID is reserved, and keeps what the user gave.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-12: each provider ID has one saved provider configuration at most, based on its identity and not on its API protocol or base URL; the provider ID is fixed after the provider configuration is created, and another provider needs a new provider configuration; owner decision, 2026-10-12: a built-in provider already configured is not offered for a new provider configuration, and the save still checks the provider ID; owner decision, 2026-10-13: the provider IDs of built-in providers stay reserved, also before their provider configuration is saved, and a custom model API cannot take one
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · A configured built-in provider is not offered again

- **Given:** "Work AI" for the built-in provider P is saved with the key K1. The built-in provider Q has no saved provider configuration.
- **When:** The user chooses to add a provider configuration.
- **Then:**
  - The user can choose Q.
  - The user cannot choose P for the new provider configuration.
  - The setup still shows "Work AI" with provider P, and lets the user change it.
- **Check:** deterministic

### AC-2 · The provider ID in use is named

- **Given:** The state after the first save of AC-3.
- **When:** The user reads the response.
- **Then:**
  - The response says that a saved provider configuration has the provider ID "lab".
  - The response names "Lab".
- **Check:** judged

### AC-3 · A custom provider ID in use

- **Given:** "Lab" is a custom model API with the provider ID "lab", the base URL U1 and the API protocol R.
- **When:** The user describes a custom model API. It has the provider ID "lab", the base URL U2 and the API protocol R. The user gives it the display name "Lab 2" and saves. The user then changes the provider ID to "lab2" and saves.
- **Then:**
  - After the first save, "Lab" is the only saved provider configuration with the provider ID "lab". It still has the base URL U1.
  - After the second save, "Lab 2" is saved with the provider ID "lab2" and the base URL U2.
  - The user did not give U2, R or "Lab 2" a second time.
- **Check:** deterministic

### AC-4 · Two custom model APIs share an API protocol

- **Given:** The state of AC-3 before the user acts.
- **When:** The user describes a custom model API. It has the provider ID "lab3", the base URL U1 and the API protocol R. The user gives it the display name "Lab 3" and saves.
- **Then:**
  - The model setup shows "Lab" and "Lab 3" as saved. Each has the API protocol R and the base URL U1.
  - "Lab" still has the provider ID "lab", and "Lab 3" has "lab3".
- **Check:** deterministic

### AC-5 · The provider ID does not change

- **Given:** "Work AI" for the built-in provider P and "Lab" with the provider ID "lab" are saved. Q is another built-in provider.
- **When:** The user chooses to change "Lab", then "Work AI". The user changes the display name of each and saves.
- **Then:**
  - The user cannot change the provider ID of either.
  - After each save, "Lab" still has the provider ID "lab", and "Work AI" still connects to P.
  - Each shows its new display name.
  - No provider configuration for Q is saved.
- **Check:** deterministic

### AC-6 · A deleted provider can be added again

- **Given:** "Work AI" for the built-in provider P was saved, then deleted. No provider configuration for P is saved.
- **When:** The user adds a provider configuration for P with the key K3 and the display name "Work AI", and saves.
- **Then:**
  - The model setup shows "Work AI" with provider P as saved.
- **Check:** deterministic

### AC-7 · A custom model API cannot take a built-in provider ID

- **Given:** The built-in provider Q has no saved provider configuration. Its provider ID is IDQ [BR-008].
- **When:** The user describes a custom model API with the provider ID IDQ, the base URL U2 and the display name "My Q", and saves. The user then changes the provider ID to "myq" and saves.
- **Then:**
  - After the first save, no provider configuration is saved with the provider ID IDQ.
  - After the second save, "My Q" is saved with the provider ID "myq" and the base URL U2.
  - The user did not give U2 or "My Q" a second time.
- **Check:** deterministic

### AC-8 · The reserved provider ID is named

- **Given:** The state after the first save of AC-7.
- **When:** The user reads the response.
- **Then:**
  - The response says that the provider ID IDQ is kept for a built-in provider.
- **Check:** judged

## Notes

- Saving a provider configuration is covered by FR-041. Changing its key or base URL is covered by FR-043. Deleting it is covered by FR-063.
- A retired requirement let the user change the provider of a saved provider configuration. That behavior is no longer approved.
- Until 2026-10-12, AC-1 let the user choose a configured built-in provider and try to save it again. The owner decision of 2026-10-12 on adding a provider stops that choice. AC-3 tests the check at saving.
- Until 2026-10-12, AC-5 required the key, the base URL and the display name of every provider configuration to be editable. Which settings a built-in provider lets the user change is a pending value of BR-006. AC-5 now changes the display name only.
