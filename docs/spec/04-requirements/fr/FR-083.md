---
id: FR-083
title: "Choose another project folder for a workspace"
---

## Requirement

- **Statement:** The user can choose another folder that exists on the computer as the project folder of a workspace whose folder moved. The system keeps the workspace, its chats, their conversations, their decks and their history, and changes only the project folder of that workspace. Choosing a folder reads nothing of it and sends nothing to a model. When the chosen folder is already the project folder of another workspace that is set up, the system changes neither workspace, says which workspace uses that folder, and lets the user switch to it. When the chosen folder cannot be read, the system keeps the earlier project folder of the workspace and says that the chosen folder cannot be read. While a request in a chat of the workspace is active, also one that waits for the user's answer, the system changes no project folder: it says that the request must end first, and it stops no request. The system never changes the project folder of a workspace by itself, and it never treats a different folder at the old place as the earlier one when it can tell them apart. A folder the system can read is no project folder of the workspace unless the user chose it: the system reads no file of a folder that is not the project folder of the workspace of the chat, also not when its name matches the name of a file a request holds. After the choice, the system checks each reference of the chats of the workspace against the folder the workspace has now (FR-082).
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Another folder keeps the workspace and its chats

- **Given:** The workspace "Alpha" is set up for the folder "C:\ projects\alpha" and holds two chats with decks. The folder was moved to "C:\ projects\beta". "Beta" is the project folder of no workspace.
- **When:** The user chooses "C:\ projects\beta" as the project folder of "Alpha".
- **Then:**
  - "Alpha" is still set up and still holds its two chats, each with its conversation and its deck.
  - The project folder of "Alpha" is "C:\ projects\beta".
  - The files of "C:\ projects\beta" are as they were.
- **Check:** deterministic

### AC-2 · Choosing a folder reads nothing and sends nothing

- **Given:** The state before AC-1. A test account with the selected model's provider records every request it receives and every content it carries. "C:\ projects\beta" holds a file with a distinct marker text.
- **When:** The user chooses "C:\ projects\beta" as the project folder of "Alpha".
- **Then:**
  - The test account receives no request whose content holds the marker.
  - The system starts no request.
- **Check:** deterministic

### AC-3 · The folder of another workspace is refused

- **Given:** The workspace "Beta" is set up for the folder "C:\ projects\beta" and holds one chat. The workspace "Alpha" is set up for a folder that moved.
- **When:** The user chooses "C:\ projects\beta" as the project folder of "Alpha".
- **Then:**
  - "Alpha" keeps the folder it had, and "Beta" keeps "C:\ projects\beta".
  - The response says which workspace uses "C:\ projects\beta", and lets the user switch to it.
  - The chat of "Beta" stays with "Beta", and no chat moves between the workspaces.
- **Check:** deterministic

### AC-4 · A folder that cannot be read changes nothing

- **Given:** The workspace "Alpha" is set up for a folder that moved. The computer holds no readable folder "C:\ projects\gamma".
- **When:** The user chooses "C:\ projects\gamma" as the project folder of "Alpha".
- **Then:**
  - "Alpha" keeps the earlier project folder.
  - The response says that the chosen folder cannot be read.
  - The two chats of "Alpha" are still there, with their conversations and their decks.
- **Check:** deterministic

### AC-5 · A request that runs stops the choice

- **Given:** The workspace "Alpha" holds one chat. A request in it is active; in one run the system works on it, in another run it waits for the user's answer.
- **When:** The user chooses another folder for "Alpha".
- **Then:**
  - The project folder of "Alpha" is unchanged.
  - The response says that the request must end first.
  - In each run, the request keeps running or keeps waiting, and the system moves no chat.
- **Check:** deterministic

### AC-6 · A different folder at the old place is not used by itself

- **Given:** The workspace "Alpha" is set up for "C:\ projects\alpha", and a chat of "Alpha" holds a reference to "report.pdf" there. Another folder now sits at that place, the system can tell it apart from the earlier one, it can be read, and it holds a file named "report.pdf".
- **When:** The user works in DeckAgent and sends no choice of another folder.
- **Then:**
  - The project folder of "Alpha" is unchanged.
  - The system does not treat the folder at that place as the earlier one, and says that the files of the project folder cannot be read (FR-074).
  - The system reads nothing of the folder at that place, although that place can be read, and uses no file of it in the request.
  - The reference shows a state that says its file cannot be read, and the system does not say that it read "report.pdf".
- **Check:** deterministic

### AC-7 · The workspace keeps its identity

- **Given:** The state before AC-1. The chat "C1" belongs to "Alpha" and holds a deck of five slides.
- **When:** The user chooses "C:\ projects\beta" as the project folder of "Alpha", then switches the workspace in use away and back again.
- **Then:**
  - "C1" is still a chat of "Alpha", with the same conversation and the same five slides.
  - A new chat started in "Alpha" joins "Alpha".
  - No second workspace stands for "C:\ projects\beta".
- **Check:** deterministic

### AC-8 · A reference is checked again against the new folder

- **Given:** The workspace "Alpha" is set up for "C:\ projects\alpha", which holds "budget.xlsx". The request area of a chat of "Alpha" holds a reference to "budget.xlsx" in a state that does not block sending. The folder "C:\ projects\alpha" then moved away, and the user chooses "C:\ projects\beta" as the project folder of "Alpha". "C:\ projects\beta" holds a different file named "budget.xlsx".
- **When:** The user sends the request with that reference.
- **Then:**
  - The system reads no file of "C:\ projects\beta" for that reference, and sends no file in place of the one the user named.
  - The request area shows the reference in a state that says its file is not in the project folder, and the request text stays as the user wrote it.
  - The request is not sent as if the file can be read.
  - The user can name the file of the new folder instead, or remove the reference.
- **Check:** deterministic

## Notes

- The system can tell some folders apart and not all. When it cannot tell that a folder at the old place is a different one, it promises nothing it cannot know. How it decides is an architecture matter.
- Which workspace stands for a folder is decided by the workspaces that are set up. Two workspaces never stand for the same folder (FR-071).
- A folder that comes back at the old place needs no choice: the workspace uses it again when it is the folder the user chose for that workspace (FR-074).
- A folder the system can read is no project folder of the workspace on that ground alone. The workspace reaches the files of the folder the user chose for it, and no other folder, also not through the name of a file.
- A reference belongs to the project folder the workspace has. Choosing another folder carries no reference over to a file of the same name there: the reference is checked again, and the user names the file in the new folder or removes the reference (FR-082).
