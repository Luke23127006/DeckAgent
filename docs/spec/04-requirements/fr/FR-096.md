---
id: FR-096
title: "Review and validate design system rules"
---

## Requirement

- **Statement:** The system shows each rule of a proposed design system in words, and marks it as a Required Rule or a Preferred Rule. It shows a representative slide made with the design system. It names every rule it cannot use and every missing or contradictory rule. It changes no deck.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Each rule appears with its kind

- **Given:** The user gives a brand colour, a heading font and a logo, and says that the logo must appear on every slide. A chat holds a deck of five slides.
- **When:** The system shows the proposed design system.
- **Then:**
  - Each rule appears in words.
  - Each rule is marked as a Required Rule or a Preferred Rule.
  - A representative slide shows the rules.
  - Every slide of the deck is as it was.
- **Check:** judged

### AC-2 · Missing rules are named

- **Given:** The user gives only a main brand colour.
- **When:** The system reviews the proposed design system.
- **Then:**
  - The system names the rules it still needs.
  - The system saves no design system.
  - The user can add the missing rules.
- **Check:** judged

### AC-3 · Contradictory rules are not resolved silently

- **Given:** Two files of the user give two different main brand colours.
- **When:** The system reviews the proposed design system.
- **Then:**
  - The system names both rules and the file each one came from.
  - The system chooses neither colour.
  - The system saves nothing.
- **Check:** judged

### AC-4 · Review changes no deck

- **Given:** A chat holds a deck of five slides. The user sent "make the headings smaller on slide 3" in an earlier request that finished.
- **When:** The user reviews a proposed design system.
- **Then:**
  - Every slide is as it was before the review.
  - No slide is rebuilt.
- **Check:** deterministic
