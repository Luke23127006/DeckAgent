---
id: FR-120
title: "Preserve deck content and layout during export"
---

## Requirement

- **Statement:** An export keeps the meaning, the important facts and figures, the slide order, and the visuals and layout of each slide as the deck canvas shows them [NFR-015]. It never redesigns, reflows or resizes a slide, and never changes the deck, to make the export work. The system names each material limitation of the chosen output before it gives any file. The user can accept a stated limitation only when the file still keeps all important information. When the output cannot keep important information, the system gives no file, offers no acceptance of that loss, and does not call the output equivalent. In either case the user can choose another output kind or end the export.
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · Slides keep their content and layout

- **Given:** A deck of five finished slides with text, a chart and two images.
- **When:** The user exports it as PDF.
- **Then:**
  - Each page shows the text, the chart and the images of its slide, in the same places relative to each other [NFR-015].
  - The slide order is the same.
- **Check:** judged

### AC-2 · The deck does not change

- **Given:** The state of AC-1.
- **When:** The export ends.
- **Then:**
  - Each slide of the deck is the same as before the export.
  - The native source of the deck is the same as before the export.
- **Check:** deterministic

### AC-3 · A loss of important information gives no file

- **Given:** A deck whose slide 3 shows its last two points only through an animation. No static view of the slide shows them.
- **When:** The user chooses a PDF export.
- **Then:**
  - Before any file is given, the system names slide 3 and says that the points shown by the animation would be lost.
  - The system does not say that the PDF would be equivalent to the deck.
  - No file is given.
  - The system lets the user choose another output kind or end the export.
  - The deck is the same as before.
- **Check:** deterministic

### AC-4 · An accepted limitation is reported

- **Given:** A deck whose slide 4 plays a video. In a static file the video shows as one picture. The text of slide 4 states the point of the video.
- **When:** The user chooses a PDF export, and accepts the stated limitation.
- **Then:**
  - Before any file is given, the system names slide 4 and the limitation.
  - After the user accepts, the system gives the file.
  - The file keeps the text of slide 4.
  - The conversation names the limitation the user accepted.
- **Check:** deterministic

### AC-5 · A limitation that is not accepted gives no file

- **Given:** The state of AC-4. The destination holds "notes.txt".
- **When:** The user does not accept the limitation.
- **Then:**
  - No file is written.
  - "notes.txt" is the same as before.
  - The deck is the same as before.
  - The system does not say that the export finished.
- **Check:** deterministic

### AC-6 · A decorative animation needs no decision

- **Given:** A deck whose slide 2 has a fade-in effect that carries no information.
- **When:** The user exports it as PDF.
- **Then:**
  - The system gives the file without asking the user to accept a limitation for slide 2.
  - The page of slide 2 shows all the content of slide 2.
- **Check:** deterministic

### AC-7 · A fidelity limit is named, and the slide is not redesigned

- **Given:** A deck whose slide 5 uses a font that the static file cannot hold. Another font would cut off the title of slide 5. The destination holds "notes.txt".
- **When:** The user chooses a PNG export.
- **Then:**
  - Before any file is given, the system names slide 5 and the font limit, and says that the title would be cut off.
  - The system does not say that the image matches the slide exactly.
  - The system offers no acceptance of this limitation, because the cut title loses important information.
  - No image and no archive is written. "notes.txt" is the same as before.
  - The system lets the user choose another output kind or end the export.
  - Slide 5 in the deck is the same as before: no text is moved, resized or reworded.
- **Check:** deterministic

### AC-8 · Another output kind after a stated limitation

- **Given:** The state of AC-4, before the user accepts.
- **When:** The user chooses a source export instead of the PDF.
- **Then:**
  - No PDF is written.
  - The source export uses the current stable deck state.
  - The system does not ask again about the limitation of the PDF.
  - The deck is the same as before.
- **Check:** deterministic

## Notes

- The quality target for fidelity is NFR-015. This requirement covers what the system does when the target cannot be met.
