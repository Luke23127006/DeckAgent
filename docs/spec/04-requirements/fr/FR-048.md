---
id: FR-048
title: "Show the earlier chats"
---

## Requirement

- **Statement:** When the user asks for earlier work, the system shows the earlier chats the user can open [BR-004]. The earlier chats it shows are those of the workspace in use. These include chats from before DeckAgent was last closed. The system names each chat from its content, and says when it last changed and whether it has slides. The user can also find the chats that belonged to removed workspaces, together, as the ungrouped chats. The system shows none of those chats as a chat of a workspace that is set up, and shows it as a chat of no workspace. A chat whose saved work cannot be read stays in the set the system shows, among the chats of its workspace or among the ungrouped chats, and the system says there that it cannot be opened (FR-050). With no earlier chat, it says so and lets the user start a new chat. The current chat stays as it was.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Earlier chats from before a restart

- **Given:** Chat X has a deck of five slides. Chat Y has an outline proposal and no slides. Both belong to the workspace in use and were made before DeckAgent was closed and opened again. The user is in chat Z, with no active request.
- **When:** The user asks for earlier work.
- **Then:**
  - The system shows chat X and chat Y.
  - For each of them, it says when the chat last changed.
  - It shows that chat X has slides and that chat Y has none.
- **Check:** deterministic

### AC-2 · Each chat is named from its content

- **Given:** The state of AC-1. Chat X is about the results of a hospital pilot. Chat Y is about a staff survey.
- **When:** The user reads the names of the chats.
- **Then:**
  - The name of chat X tells that it is about the pilot results.
  - The name of chat Y tells that it is about the staff survey.
- **Check:** judged

### AC-3 · The current chat stays as it was

- **Given:** The state of AC-1. The request area of chat Z holds the unsent request text "draft notes" and the ready attachment "notes.docx".
- **When:** The user asks for earlier work.
- **Then:**
  - The conversation and the deck of chat Z are the same as before.
  - The request area of chat Z still holds "draft notes" and "notes.docx".
- **Check:** deterministic

### AC-4 · No earlier chat

- **Given:** The user is in chat Z. There is no earlier chat the user can open.
- **When:** The user asks for earlier work.
- **Then:**
  - The system shows no earlier chat.
  - Chat Z is the same as before.
  - The user can start a new chat.
- **Check:** deterministic

### AC-5 · The user is told there is none

- **Given:** The state of AC-4.
- **When:** The user reads the response.
- **Then:**
  - The response says that there is no earlier chat.
- **Check:** judged

### AC-6 · Earlier chats belong to the workspace in use

- **Given:** The workspaces "Alpha" and "Beta" are set up. "Alpha" holds two chats and "Beta" holds one. "Beta" is the workspace in use.
- **When:** The user asks for earlier work.
- **Then:**
  - The chat of "Beta" is among the earlier chats shown.
  - Neither chat of "Alpha" appears among the chats of "Beta".
- **Check:** deterministic

### AC-7 · Chats of a removed workspace are found apart

- **Given:** The workspace "Alpha" held two chats and was removed. Both chats stay readable. The user is in the default workspace, which holds one chat.
- **When:** The user asks for earlier work and then looks for the chats that belonged to removed workspaces.
- **Then:**
  - The earlier chats of the workspace in use are shown, and the two chats of "Alpha" are not among them.
  - The two chats of "Alpha" are found together as the ungrouped chats, each with its conversation and its deck.
  - Neither chat is shown as a chat of the default workspace.
- **Check:** deterministic

## Notes

- AC-4 and AC-5 are the boundary case of the same behavior: the set of earlier chats is empty.
- Starting a new chat is covered by FR-053. Changing chats while a request runs is covered by FR-054. Removing a workspace and the chats it leaves reachable are covered by FR-073.
- A project folder that cannot be read is a different failure. It leaves the earlier chats readable and is reported for its workspace (FR-074).
- A chat whose saved work cannot be read keeps its workspace. It stays among the chats of that workspace when the workspace is set up, and among the ungrouped chats when the workspace was removed. The system says there that it cannot be opened, and no empty chat takes its place (FR-050).
