---
id: FR-026
title: "Say how far the work on slides got"
---

## Requirement

- **Statement:** The system says how far the work on slides got in these cases. When the user stops a first draft, it gives the number of slides finished. It gives that number too when a model call of the first draft fails or returns something unusable. It does the same when the usage limit is reached. When a change to the deck stops, it gives the number of slides changed. When a change fails, it says which slides it changed and which it did not. The slides changed include the new slides it built. When the system does not know a number, or which slides changed, it says so. It never gives a number it does not know.
- **Status:** confirmed
- **Source:** use case flow; owner decision, 2026-10-13: the counts of finished and changed slides include new slides; when the real count is not known, the system says so and invents no number
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Number of slides finished in a first draft

- **Given:** The user confirmed an outline of four planned slides. The system finished slides 1 and 2 and builds slide 3.
- **When:** The work ends, in three separate runs. The user stops the request. The model provider returns an error. The provider reports that the usage limit is reached.
- **Then:**
  - In each run, the conversation gives two as the number of slides finished.
- **Check:** deterministic

### AC-2 · Number of slides changed after a stop

- **Given:** A deck of five slides. The user sent "make slides 2, 3 and 4 shorter". The system finished changing slide 2 and is changing slide 3.
- **When:** The user stops the request.
- **Then:**
  - The notice gives one as the number of slides changed.
- **Check:** deterministic

### AC-3 · Which slides changed after a failure

- **Given:** The state of AC-2 before the stop. The system knows which slides it finished changing.
- **When:** The model provider returns an error, and the work cannot finish.
- **Then:**
  - The message names slide 2 as changed.
  - The message names slides 3 and 4 as not changed.
  - Each slide that the message names as changed differs from its state before the request.
- **Check:** deterministic

### AC-4 · New slides count as changed

- **Given:** A deck of five slides. The user sent "make slides 2 and 3 shorter, and add a slide on costs at the end". The system finished changing slide 2 and finished the slide on costs. It is changing slide 3.
- **When:** The user stops the request.
- **Then:**
  - The notice gives two as the number of slides changed.
- **Check:** deterministic

### AC-5 · Count not known

- **Given:** The state of AC-2 before the stop. The system cannot tell which slides it finished changing.
- **When:** The model provider returns an error, and the work cannot finish.
- **Then:**
  - The message says that the system cannot tell which slides it changed.
  - The message gives no number of slides changed.
  - The message names no slide as changed.
- **Check:** judged

## Notes

- This requirement sets no report of progress for one case. That case is a first draft that ends because the provider refused the user's key.
- AC-3 is checked by comparing the slides the message names with the deck before and after the request.
- Which slides the system keeps is covered by FR-025. The stop notice and the failure message themselves are covered by FR-018 and FR-019.
