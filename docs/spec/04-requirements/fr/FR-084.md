---
id: FR-084
title: "Keep the files of the project folder unchanged during slide work"
---

## Requirement

- **Statement:** When the system builds slides, changes a slide or shows a deck, it creates, changes, moves and deletes no file in the project folder of the workspace of the chat. That holds for a file no request names, for a file the request reads, and for a hidden file that the folder does not show by default. A file the user gave as an attachment or named as a reference stays as the user gave it. A file appears in the project folder only through an export the user chooses (FR-085).
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Building a first deck leaves the project folder as it was

- **Given:** The workspace of the chat has the project folder "C:\ projects\alpha". The folder holds "report.pdf", "brand-guide.docx", a folder named "photos" with two images, and no file that DeckAgent writes. The chat has a confirmed outline of four planned slides and no deck.
- **When:** The system builds the four slides.
- **Then:**
  - The folder holds the same entries as before the request, with the same content.
  - No file appears in the folder, including a hidden file.
  - The deck canvas shows the four finished slides.
- **Check:** deterministic

### AC-2 · Changing a slide leaves the project folder as it was

- **Given:** The state after AC-1. The request "make slide 2 shorter, and use the figures of report.pdf" names a file of the folder.
- **When:** The system changes slide 2.
- **Then:**
  - The folder holds the same entries as before the request, with the same content.
  - No file appears in the folder, including a hidden file, and no entry moved.
  - Slide 2 shows the change.
- **Check:** deterministic

### AC-3 · A stop, a failure and a preview leave the project folder as it was

- **Given:** The state after AC-1. In one run the user stops the work while slide 3 is built. In another run a model call fails. In a third run the user looks through the deck slide by slide.
- **When:** Each run ends.
- **Then:**
  - In each run, the folder holds the same entries as before the run, with the same content.
  - In each run, no file appears in the folder, including a hidden file.
- **Check:** deterministic

### AC-4 · A file the user gave stays as the user gave it

- **Given:** The folder of the chat holds "report.pdf", which the request reads. The request area holds the attachment "notes.docx" and a reference to "report.pdf".
- **When:** The system finishes the deck.
- **Then:**
  - "report.pdf" and "notes.docx" are the same as before the request.
  - The deck uses content from both of them.
- **Check:** deterministic

## Notes

- Where an exported file goes, and what it holds, is FR-085. What the agent can reach is FR-077 and NFR-003.
- A deck of a chat reopens with the chat after DeckAgent is closed and opened again, as FR-049 and NFR-008 say. That a chat of a workspace with a folder opens without that folder is FR-074.
