---
id: FR-110
title: "Protect built-in visual styles"
---

## Requirement

- **Statement:** A built-in visual style keeps the original definition DeckAgent gave it. The user cannot change or remove that definition. The user can choose it and can create a custom visual style from it.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A built-in visual style cannot be changed

- **Given:** The built-in visual style "Editorial" is offered with its original rules.
- **When:** The user tries to change the density rules of "Editorial".
- **Then:**
  - "Editorial" holds the same rules as before.
  - No saved definition changed.
  - The user can create a custom visual style from "Editorial".
- **Check:** deterministic

### AC-2 · A built-in visual style cannot be removed

- **Given:** A deck of five slides was built with "Editorial".
- **When:** The user tries to remove "Editorial".
- **Then:**
  - "Editorial" remains among the visual styles the user can choose.
  - Every slide of the deck is as it was.
- **Check:** deterministic

### AC-3 · A custom copy keeps the built-in definition safe

- **Given:** "Editorial" is offered with its original rules.
- **When:** The user starts a custom visual style from "Editorial", changes the density rules and saves it as "Report".
- **Then:**
  - "Report" holds the changed density rules.
  - "Editorial" holds its original rules.
- **Check:** deterministic
