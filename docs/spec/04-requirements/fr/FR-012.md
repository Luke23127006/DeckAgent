---
id: FR-012
title: "Send a request and show its work until it ends"
---

## Requirement

- **Statement:** The system moves a sent request into the conversation as the user's message and removes it from the request area. It shows that it received the request and works on it [NFR-001]. The status message says what it is doing. At the end, it says that the work is done and lets the user send a new request.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Sent request moves into the conversation

- **Given:** A chat with no active request. The request area holds the request text "a talk on our pilot results" and one ready attachment "notes.docx".
- **When:** The user sends the request.
- **Then:**
  - The conversation shows the request text and "notes.docx" as the user's message.
  - The request area holds no request text and no attachment.
  - The system shows that it received the request and works on it.
- **Check:** deterministic

### AC-2 · Status while the system works

- **Given:** The state after AC-1. The system works on the request.
- **When:** The user waits.
- **Then:**
  - The conversation shows a status message.
  - The status message shows the time elapsed on the work.
  - The user's message is the same as when it was sent.
- **Check:** deterministic

### AC-3 · Status says what the system does

- **Given:** The state of AC-2. The system drafts an outline.
- **When:** The user reads the status message.
- **Then:**
  - The status message says in plain words which part of the work is running, for example drafting the outline.
  - It says more than that the system is busy.
- **Check:** judged

### AC-4 · End of the work

- **Given:** The system works on a request.
- **When:** The system finishes its work on it.
- **Then:**
  - The conversation shows that the work on the request is done.
  - The system no longer shows that it works on the request.
  - The user's message is still in the conversation, the same as when it was sent.
  - The user can send a new request.
- **Check:** deterministic

### AC-5 · Next request is separate

- **Given:** The state of AC-4. The user writes "add a slide on costs" in the request area.
- **When:** The user sends it.
- **Then:**
  - The conversation shows it as a new user's message, after the earlier request and its response.
  - The earlier request and its response are the same as before.
  - The system shows that it received the new request and works on it.
- **Check:** deterministic

## Notes

- Three separate requirements cover a stop, a failure and the wait for an answer: FR-018, FR-019 and FR-020. What the work produces is described by the requirements of that work.
