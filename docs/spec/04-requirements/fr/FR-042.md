title: "Run requests with the one model set up"
---

## Requirement

- **Statement:** With one model set up, the system runs each later request with that model and its current key. This holds in every chat, for drafting the outline, building the slides and changing the deck. The user chooses no model for a request.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-11: V1 needs only one working model, set up with the user's own key, and that model runs every request of the journey; owner decision, 2026-10-12: V1 has no switching between models
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · The request goes to the model set up

- **Given:** Model M of provider P is set up with the key K1. A test account with P records each request it receives. A chat has no active request.
- **When:** The user sends the request "a talk on our pilot results".
- **Then:**
  - P receives the request for model M with the key K1.
  - The system asks the user to choose no model.
- **Check:** deterministic

### AC-2 · Each kind of work uses the same model

- **Given:** The state of AC-1. The system has shown an outline proposal.
- **When:** The user confirms the outline. After the slides are built, the user sends "make slide 2 shorter".
- **Then:**
  - P receives the confirmation for model M with the key K1.
  - P receives the change request for model M with the key K1.
- **Check:** deterministic

### AC-3 · A replaced key is used next

- **Given:** The state of AC-1. The user then replaced the key of P with K2.
- **When:** The user sends a new request in any chat.
- **Then:**
  - P receives the request for model M with the key K2.
  - No later request uses K1.
- **Check:** deterministic

## Notes

- Choosing another model for a chat or a request is not part of V1.
