---
id: FR-068
title: "Keep the work going when the interface is reloaded or closed"
---

## Requirement

- **Statement:** While DeckAgent runs, reloading or closing its Local Web interface does not stop an active request. When the user opens the interface again, the system shows the chat of that request as it is now. It shows the conversation, the deck and what the system is doing now. It shows no notice that the work was interrupted while the work goes on. A request that waits for the user's answer still waits.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Reload while slides are built

- **Given:** The user confirmed an outline of four planned slides. Slides 1 and 2 are finished. The system builds slide 3.
- **When:** The user reloads the Local Web interface.
- **Then:**
  - The conversation is the same as before the reload.
  - The deck canvas shows slides 1 and 2, and each slide finished since.
  - The system shows that it works on the request.
  - No notice says that the work was interrupted.
  - The request shows once in the conversation. It is not sent again.
- **Check:** deterministic

### AC-2 · Closed and opened again

- **Given:** A deck of five slides. The user sent "make slides 2 and 3 shorter". The system changes slide 2.
- **When:** The user closes the Local Web interface, waits until the work ends, and opens the interface again.
- **Then:**
  - The deck canvas shows the changed slides 2 and 3.
  - The conversation says that the work on the request is done.
  - The user can send a new request.
- **Check:** deterministic

### AC-3 · A question still waits

- **Given:** The request is "a talk on our pilot". The system asked who the audience is and waits for the answer.
- **When:** The user reloads the Local Web interface.
- **Then:**
  - The question is still in the conversation.
  - The system still waits for the answer.
  - The reply the user sends next joins the same request.
- **Check:** deterministic

## Notes

- When DeckAgent itself ends during a request, the request does not go on. FR-052 covers what the chat shows when it is opened again.
- Several open views of the interface at once are not covered here. Their handling is an architecture matter.
