---
id: FR-052
title: "Open a chat whose last request did not finish"
---

## Requirement

- **Statement:** An opened chat can hold a last request that did not finish, on which the system no longer works. The system then shows the conversation and the finished slides that the chat kept. It says that the work on the last request did not finish. It keeps that request in the conversation and does not start it again by itself. The user can send a new request in the chat.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-11: work that was running when DeckAgent closed is not resumed, and the user sends a new request to go on
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Finished slides, no work

- **Given:** Chat X holds a confirmed outline of four planned slides. DeckAgent was closed while it built slide 3, after slides 1 and 2 were finished. DeckAgent was then opened again.
- **When:** The user opens chat X.
- **Then:**
  - The deck canvas shows slides 1 and 2.
  - The deck canvas shows no unfinished slide.
  - The request shows once in the conversation, the same as when it was sent.
  - The system does not show that it works.
  - No request starts.
- **Check:** deterministic

### AC-2 · The user is told the work did not finish

- **Given:** The state after AC-1.
- **When:** The user reads the chat.
- **Then:**
  - The system says that the work on the last request did not finish.
  - The system does not say that more slides will come.
- **Check:** judged

### AC-3 · A new request goes on

- **Given:** The state after AC-1.
- **When:** The user sends "build the remaining slides".
- **Then:**
  - The conversation shows it as a new user's message.
  - The earlier request still shows once. It is not sent again.
  - The system works on the new request.
- **Check:** deterministic

## Notes

- Closing DeckAgent is not a stop. This requirement sets no notice of a stop.
- How the new request builds on the confirmed outline is covered by FR-051.
