---
id: FR-097
title: "Save and revise a design system"
---

## Requirement

- **Statement:** The system saves a design system that the user finishes, and adds it to the design systems the user can choose. It can start a new design system from rules in words or from an existing design system. It can change a saved design system and keep its name. Saving or changing one changes no deck, no visual style and no other design system.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A new design system is saved

- **Given:** The user reviewed a proposed design system named "Acme" with four rules. A chat holds a deck of five slides.
- **When:** The user saves "Acme".
- **Then:**
  - "Acme" is among the design systems the user can choose.
  - Every slide of the deck is as it was.
  - No visual style changed.
- **Check:** deterministic

### AC-2 · A design system can start from another one

- **Given:** "Acme" is saved with a heading font.
- **When:** The user starts from "Acme", changes the heading font, and saves the result as "Acme 2".
- **Then:**
  - "Acme" keeps its earlier heading font.
  - "Acme 2" holds the changed heading font.
- **Check:** deterministic

### AC-3 · A changed design system keeps its name

- **Given:** "Acme" is saved with a brand colour. A deck was built with "Acme".
- **When:** The user changes the brand colour of "Acme" and saves under the same name.
- **Then:**
  - "Acme" shows the new brand colour.
  - Every slide of the deck is as it was.
  - No visual style changed.
- **Check:** deterministic
