---
id: FR-065
title: "Show that the selected model of a chat was removed"
---

## Requirement

- **Statement:** The selected model of a chat can be removed [BR-005]. The user removes it or deletes its provider configuration. Or a restore of default models that the user confirms removes it. The chat then has no selected model. When the user comes back to the chat or reopens it, the system shows that it has no selected model. It says which model was removed. It asks the user to choose a selectable model before the user tries to send. It never shows the removed model as selected or as a choice, and it chooses no model by itself. The conversation, the deck, the request text and the attachments stay as they were.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-12: a chat whose selected model was removed shows no selected model and says why when the user comes back to it or reopens it; the system never chooses another model, also when only one is selectable, and the user chooses before a new request
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Back to the chat after a removal

- **Given:** "Work AI" has the added models M1 and M2. "Lab" has the added model L1. Chat X has M1 of "Work AI" as its selected model and no active request. The request area of chat X holds "a talk on our pilot results" and the attachment "notes.docx". Chat X has a conversation of four messages and a deck of five slides.
- **When:** The user removes M1 from "Work AI", saves, and goes back to chat X. The user sends nothing.
- **Then:**
  - Chat X has no selected model. M1 is not shown as its selected model or as a choice.
  - The system has selected neither M2 nor L1.
  - The request area holds the same request text and "notes.docx".
  - The conversation shows the same four messages, and the five slides are the same.
  - No request starts.
- **Check:** deterministic

### AC-2 · The user is told at once

- **Given:** The state after AC-1, before the user does anything else.
- **When:** The user reads chat X.
- **Then:**
  - The chat says that its selected model M1 was removed.
  - The chat asks the user to choose another model.
- **Check:** judged

### AC-3 · Reopening a chat after a deletion

- **Given:** "Work AI" connects to provider P and has the added model M1. "Lab" has the added model L1. Earlier chat Y has M1 of "Work AI" as its selected model. The user is in chat X, and no request is active.
- **When:** The user deletes "Work AI", then opens chat Y.
- **Then:**
  - Chat Y has no selected model. The system did not select L1.
  - The conversation and the deck of chat Y are the same as before.
- **Check:** deterministic

### AC-4 · After a restore of default models

- **Given:** "Work AI" for the built-in provider P has the added models D1 and M9. The default models of P are D1 and D2 [BR-005]. Chat Z has M9 of "Work AI" as its selected model.
- **When:** The user restores the default models of "Work AI", confirms, and goes back to chat Z.
- **Then:**
  - Chat Z has no selected model. The system selected neither D1 nor D2.
- **Check:** deterministic

### AC-5 · The only selectable model is not chosen

- **Given:** "Work AI" has the added models M1 and M2. No other provider configuration has an added model. Chat X has M1 as its selected model.
- **When:** The user removes M1 and goes back to chat X.
- **Then:**
  - Chat X has no selected model.
  - The system did not select M2, the only selectable model.
- **Check:** deterministic

### AC-6 · Choosing a model ends the state

- **Given:** The state after AC-1. A test account with the provider of "Work AI" records each request it receives.
- **When:** The user chooses M2 of "Work AI" in chat X and sends the request.
- **Then:**
  - Chat X shows M2 of "Work AI" as its selected model.
  - The provider receives the request for model M2.
  - The conversation shows "a talk on our pilot results" as a new user's message.
- **Check:** deterministic

## Notes

- A request the user tries to send before choosing is covered by FR-056. Removing a model, deleting a provider configuration and restoring default models are covered by FR-059, FR-063 and FR-062.
- A provider that refuses a model while a request runs removes no model and no selection, as FR-019 says. This requirement does not apply then.
