---
id: FR-049
title: "Open an earlier chat"
---

## Requirement

- **Statement:** When the user chooses an earlier chat, the system opens it and starts no work. It shows the conversation of that chat in order. It shows the slides as they were when the user last left the chat. It changes no slide, and the user can send a new request in that chat. The chat the user left stays as it was. Unsent request text stays with the chat in which the user wrote it. Opening another chat does not send, delete or move it. While DeckAgent runs, reopening that chat shows the text again. Unsent attachments leave the request area when the user opens another chat. Reopening the chat does not bring them back. The files on the user's computer do not change. Attachments sent with a request stay with that request.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-11: earlier chats and their decks stay available after DeckAgent is closed and opened again; owner decision, 2026-10-13: unsent request text stays with its own chat; changing chats does not send, delete or move it; reopening the chat while DeckAgent runs shows it again; unsent attachments are removed from the request area when the user changes chats and do not come back; the files on the computer are not deleted; sent attachments stay with their requests
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · The chat opens as it was left

- **Given:** Earlier chat X has a conversation of four messages and a deck of five slides. The user is in chat Z, which has a deck of three slides and no active request.
- **When:** The user opens chat X.
- **Then:**
  - No request starts.
  - The conversation shows the four messages of chat X, in the same order.
  - The deck canvas shows the five slides of chat X, the same as when the user last left it.
- **Check:** deterministic

### AC-2 · Also after a restart

- **Given:** The state of AC-1 before chat X was opened. DeckAgent was then closed and opened again.
- **When:** The user opens chat X.
- **Then:**
  - The outcomes are the same as in AC-1.
- **Check:** deterministic

### AC-3 · The chat the user left stays

- **Given:** The state after AC-1.
- **When:** The user opens chat Z again.
- **Then:**
  - The conversation of chat Z is the same as before chat X was opened.
  - The three slides of chat Z are the same as before.
- **Check:** deterministic

### AC-4 · A new request in the opened chat

- **Given:** The state after AC-1.
- **When:** The user sends "make slide 2 shorter".
- **Then:**
  - The conversation of chat X shows it as a new user's message, after the four earlier messages.
  - The system works on it in chat X.
  - The deck of chat Z is the same as before.
- **Check:** deterministic

### AC-5 · Unsent text stays with its chat

- **Given:** The user is in chat Z, with no active request. The request area of chat Z holds the unsent request text "draft notes". The request area of earlier chat X is empty.
- **When:** The user opens chat X, then opens chat Z again. DeckAgent runs the whole time.
- **Then:**
  - While chat X is open, its request area does not hold "draft notes".
  - The conversation of chat X and of chat Z shows no new user's message.
  - After chat Z opens again, its request area holds "draft notes", unchanged.
- **Check:** deterministic

### AC-6 · Unsent attachments do not come back

- **Given:** The user is in chat Z, with no active request. An earlier request of chat Z sent the attachment "notes.docx". The request area of chat Z holds the unsent request text "draft notes" and the ready attachment "chart.png". "chart.png" comes from a file on the user's computer.
- **When:** The user opens chat X, then opens chat Z again.
- **Then:**
  - The request area of chat Z holds "draft notes" and no attachment.
  - The conversation of chat Z still shows "notes.docx" with its request, unchanged.
  - The file of "chart.png" on the user's computer is unchanged.
  - The user can add "chart.png" again before sending.
- **Check:** deterministic

## Notes

- Unsent request text after DeckAgent ends is not covered. NFR-008 does not cover it either.
- A request is active only in the current chat, and the user cannot change chats then (FR-054). So changing chats never changes an active request.
- Asking to see earlier work without opening another chat keeps the request area as it was (FR-048).
- The change the new request makes is covered by FR-027. Changing chats during an active request is covered by FR-054.
