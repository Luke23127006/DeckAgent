---
id: FR-040
title: "Never show any part of a saved key"
---

## Requirement

- **Statement:** After the user saves a key in the model setup, the system never shows any part of it again. This covers the whole key, and any prefix, suffix or masked part taken from it. The system shows only whether a key is saved. The user can replace the key. The system never copies a key from the model setup into the conversation. When the user replaces a key, the system shows no part of the old key or of the new one.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · No part of a saved key is shown

- **Given:** The user gave the key K1 for provider P and saved the setup. K1 is long enough that its first and last four characters are each unique to it.
- **When:** The user opens the model setup again.
- **Then:**
  - The setup does not show K1.
  - The setup shows neither the first four nor the last four characters of K1.
  - The setup shows that the provider configuration for P has a saved key.
- **Check:** deterministic

### AC-2 · Key never in the conversation

- **Given:** The state of AC-1. The user sent requests in a chat, and typed no key in them. Provider P refused K1 for one of them.
- **When:** The user reads the whole conversation of the chat.
- **Then:**
  - The conversation does not contain K1.
- **Check:** deterministic

### AC-3 · Replacing a key shows neither key

- **Given:** The state of AC-1.
- **When:** The user gives the new key K2 for P, saves, and opens the model setup again.
- **Then:**
  - The setup does not show K1, in full or in part.
  - The setup does not show K2, in full or in part.
  - The setup shows that the provider configuration for P has a saved key.
- **Check:** deterministic

## Notes

- A mask that shows no character taken from the key, such as a fixed sign that a key is saved, is allowed. A mask that shows characters of the key is not.
- How and where the system keeps a key is an architecture matter. This requirement sets only what the user can see.
- This requirement covers what the system shows from the model setup. Text that the user types or pastes into a request is not covered here.
