id: FR-040
title: "Never show a key in full"
---

## Requirement

- **Statement:** After the user gives a key in the model setup, the system never shows the whole key again [BR-?: how a saved key is shown]. The system never copies a key from the model setup into the conversation. When the user replaces a key, the system shows neither the old key nor the whole new key.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Saved key is not shown in full

- **Given:** The user gave the key K1 for provider P and saved the setup.
- **When:** The user opens the model setup again.
- **Then:**
  - The setup does not show K1 in full.
- **Check:** deterministic

### AC-2 · Key never in the conversation

- **Given:** The state of AC-1. The user sent requests in a chat, and typed no key in them. Provider P refused K1 for one of them.
- **When:** The user reads the whole conversation of the chat.
- **Then:**
  - The conversation does not contain K1.
- **Check:** deterministic

### AC-3 · Replacing a key shows neither key

- **Given:** The state of AC-1.
- **When:** The user gives the new key K2 for P, saves, and opens the model setup again.
- **Then:**
  - The setup does not show K1, in full or in part.
  - The setup does not show K2 in full.
- **Check:** deterministic

## Not specified

- Whether the system shows any part of a saved key, and which part. Pending owner decision.

## Notes

- How and where the system keeps a key is an architecture matter. This requirement sets only what the user can see.
- This requirement covers what the system shows from the model setup. Text that the user types or pastes into a request is not covered here.
