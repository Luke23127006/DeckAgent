---
id: FR-016
title: "Show each attachment and its state"
---

## Requirement

- **Statement:** The system shows each file the user adds as an attachment in the request area. Each attachment shows its name or a preview, and its type. It also shows its state: being prepared, ready, or rejected with the reason. The user can preview an attachment [NFR-004], remove it, and add request text to the request.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Each added file is an attachment

- **Given:** A chat with no active request. The request area holds the request text "a talk from these notes".
- **When:** The user adds two files at once, "notes.docx" and "chart.png".
- **Then:**
  - The request area shows two attachments, one for each file.
  - Each attachment shows its name or a preview, and its type.
  - Each attachment shows its own state: being prepared, ready or rejected.
  - The request text is unchanged.
- **Check:** deterministic

### AC-2 · Being prepared, then ready

- **Given:** The request area shows the attachment "notes.docx" in the state being prepared.
- **When:** The system has prepared the file.
- **Then:**
  - The attachment shows the state ready.
  - The request text and the other attachments are unchanged.
- **Check:** deterministic

### AC-3 · Remove an attachment

- **Given:** The request area holds the request text "a talk from these notes" and the attachments "notes.docx" and "chart.png".
- **When:** The user removes "chart.png".
- **Then:**
  - The request area no longer shows "chart.png".
  - "notes.docx" and the request text are unchanged.
  - The conversation shows nothing new.
- **Check:** deterministic

### AC-4 · Preview, or say that none is available

- **Given:** The request area holds a ready photo and a ready file of a type with no preview.
- **When:** The user asks to preview each of them.
- **Then:**
  - The system shows a preview of the photo.
  - For the other file, the system says that no preview is available for its type.
  - Both attachments stay in the request area, unchanged.
- **Check:** deterministic

## Notes

- Why and when an attachment is rejected is a separate requirement, FR-017. FR-015 says when a request with attachments can be sent.
