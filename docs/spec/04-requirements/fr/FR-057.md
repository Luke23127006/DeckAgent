---
id: FR-057
title: "Keep a valid display name apart from the provider ID"
---

## Requirement

- **Statement:** The user gives a display name when saving a provider configuration, and can change it later. The system saves only a valid display name [BR-008]. For an empty display name, or one that another saved provider configuration has, it saves nothing of that change. It says why and keeps what the user gave. The system shows the name as the user gave it and never changes it by itself. The display name never sets the provider ID, the key, the added models or a selected model.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: the display name is the user's own text and does not identify the provider; owner decision, 2026-10-12: a display name is not empty and is unique among saved provider configurations, and an invalid one is not saved while the other input stays
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · The name does not set the provider

- **Given:** The user saved a provider configuration for provider Q, with the display name "DeepSeek" and the key K1. A test account with Q records each request it receives. Chat X has the selected model Q1.
- **When:** The user sends "a talk on our pilot results" in chat X.
- **Then:**
  - Q receives the request for model Q1 with the key K1.
  - The model setup still shows the display name "DeepSeek".
- **Check:** deterministic

### AC-2 · Changing the name changes nothing else

- **Given:** The state after AC-1. The added models of this provider configuration are Q1 and Q2.
- **When:** The user changes the display name to "Test AI" and saves. The user then sends a new request in chat X.
- **Then:**
  - The model setup shows the display name "Test AI", with provider Q.
  - The group of its models is named "Test AI" and holds Q1 and Q2.
  - Chat X still has Q1 as its selected model.
  - Q receives the new request for model Q1 with the key K1.
- **Check:** deterministic

### AC-3 · An empty display name is not saved

- **Given:** No provider configuration is saved.
- **When:** The user chooses provider P, gives the key K1 and no display name, and saves. The user then gives the display name "Work AI" and saves.
- **Then:**
  - After the first save, no provider configuration is saved.
  - After the second save, the model setup shows "Work AI" with provider P as saved.
  - The user did not give provider P or the key K1 a second time.
- **Check:** deterministic

### AC-4 · A display name in use is not saved

- **Given:** "Work AI" connects to provider P. "DeepSeek" connects to provider Q with the key KQ and the added model Q1. Chat X has Q1 of "DeepSeek" as its selected model. A test account with Q records each request and its key.
- **When:** The user changes the display name of "DeepSeek" to "Work AI" and its key to KQ2, and saves. The user then sends a request in chat X.
- **Then:**
  - The model setup shows "Work AI" with provider P and "DeepSeek" with provider Q.
  - Q receives the request with the key KQ, not KQ2.
- **Check:** deterministic

### AC-5 · The other input stays

- **Given:** The state of AC-4, after the save and before the request.
- **When:** The user changes the display name to "Research" and saves, without giving KQ2 again. The user then sends a request in chat X.
- **Then:**
  - The model setup shows "Research" with provider Q.
  - Q receives the request with the key KQ2.
- **Check:** deterministic

### AC-6 · The reason is given

- **Given:** The states after the first save of AC-3 and after the save of AC-4.
- **When:** The user reads each response.
- **Then:**
  - After AC-3, the response says that a display name is needed.
  - After AC-4, the response says that another saved provider configuration has the display name "Work AI".
- **Check:** judged

## Not specified

- How capital letters and spaces count when display names are compared or checked for being empty. Pending owner decision.

## Notes

- Until 2026-10-12, this requirement kept the display name through a change of provider. It did not decide an empty or a shared display name. The owner decisions of 2026-10-12 on provider IDs and display names replaced both.
