id: FR-038
title: "Keep the chat while the model setup is open"
---

## Requirement

- **Statement:** The user can open the model setup from the chat. Opening it adds nothing to the request text and sends nothing. When the user goes back to the chat, the conversation, the request text and the attachments are as they were. This holds whether or not the user saved.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Opening the setup changes nothing in the chat

- **Given:** No model is set up. A chat with no active request. The request area holds the request text "a talk on our pilot results" and the attachment "notes.docx".
- **When:** The user opens the model setup.
- **Then:**
  - The system opens the model setup.
  - The request text is still "a talk on our pilot results". Nothing was added to it.
  - "notes.docx" is still in the request area, unchanged.
  - The conversation shows no new message.
  - No request starts.
- **Check:** deterministic

### AC-2 · Back to the chat after saving

- **Given:** The state after AC-1. The model the user sets up can read the type of "notes.docx".
- **When:** The user saves a complete setup and goes back to the chat.
- **Then:**
  - The conversation is the same as before the setup was opened.
  - The request area holds the same request text and "notes.docx", ready.
- **Check:** deterministic

### AC-3 · Back to the chat without saving

- **Given:** The state after AC-1.
- **When:** The user leaves the model setup without saving and goes back to the chat.
- **Then:**
  - The conversation is the same as before the setup was opened.
  - The request area holds the same request text and "notes.docx", unchanged.
- **Check:** deterministic

## Notes

- What the setup itself keeps after saving or leaving is covered by FR-041 and FR-044.
