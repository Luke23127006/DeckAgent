---
id: FR-045
title: "Refuse to save a setup that lacks what the provider needs"
---

## Requirement

- **Statement:** A setup can lack something the provider needs [BR-006]. When the user saves it, the system does not save the provider configuration. It says what is missing and keeps what the user gave. The user can then complete the setup and save it.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Nothing is saved

- **Given:** No provider configuration is saved. Provider P needs a key [BR-006].
- **When:** The user chooses provider P, gives the display name "Work AI" and no key, and saves.
- **Then:**
  - No provider configuration is saved.
  - The setup still holds provider P and the display name "Work AI" as the user gave them.
- **Check:** deterministic

### AC-2 · What is missing is named

- **Given:** The state after AC-1.
- **When:** The user reads the response to the save.
- **Then:**
  - The response says that the key for P is missing.
- **Check:** judged

### AC-3 · Completing the setup

- **Given:** The state after AC-1.
- **When:** The user gives the key K1 and saves.
- **Then:**
  - The model setup shows "Work AI" with provider P as saved.
- **Check:** deterministic
