id: FR-045
title: "Refuse to save a setup that lacks what the provider needs"
---

## Requirement

- **Statement:** A setup can lack something the provider needs [BR-006]. When the user saves it, the system does not set up the model. It says what is missing and keeps what the user gave. The user can then complete the setup and save it.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · No model is set up

- **Given:** No model is set up. Provider P needs a key [BR-006].
- **When:** The user chooses provider P and its model M, gives no key, and saves.
- **Then:**
  - No model is set up.
  - The setup still holds provider P and model M as the user's choice.
- **Check:** deterministic

### AC-2 · What is missing is named

- **Given:** The state after AC-1.
- **When:** The user reads the response to the save.
- **Then:**
  - The response says that the key for P is missing.
- **Check:** judged

### AC-3 · Completing the setup

- **Given:** The state after AC-1.
- **When:** The user gives the key K1 and saves.
- **Then:**
  - The model setup shows model M with provider P as set up.
- **Check:** deterministic
