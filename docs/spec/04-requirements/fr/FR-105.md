---
id: FR-105
title: "Resolve design rule conflicts and exceptions"
---

## Requirement

- **Statement:** When a required rule of the chosen design system conflicts with the chosen visual style, and no clear user instruction covers the conflict, the system names the conflicting rules and asks the user to resolve them before it makes the conflicting design change. When the user resolves the conflict, the system applies that resolution. When a clear instruction asks for an exception to a required rule, the system applies it within the requested scope, says which rule it overrides and what changes, and asks for no further approval. It changes no saved definition.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A conflict stops the conflicting change

- **Given:** The design system "Acme" requires its own heading treatment on every slide. The visual style "Editorial" sets a different heading treatment. A deck of five slides exists. The user sends "use Editorial on slide 3".
- **When:** The system works on the request.
- **Then:**
  - The system names the required heading rule of "Acme" and the heading rule of "Editorial".
  - No slide changes before the user answers.
  - "Acme" and "Editorial" hold the same rules as before.
- **Check:** deterministic

### AC-2 · An explicit exception stays in its scope

- **Given:** The design system "Acme" requires the brand logo on every slide. A deck has five slides. The user sends "use Editorial on slides 4 and 5 and leave the logo off them".
- **When:** The system has changed the slides.
- **Then:**
  - Slides 4 and 5 follow "Editorial" and show no logo.
  - Slides 1, 2 and 3 keep their design and their logo.
  - The conversation says that the logo rule is overridden for slides 4 and 5.
  - "Acme" holds the same rules as before.
- **Check:** deterministic

### AC-3 · The system asks for no extra approval

- **Given:** The design system "Acme" requires the brand logo on every slide. A deck has five slides. The user sends "use Editorial on slides 4 and 5 and leave the logo off them".
- **When:** The system applies the exception.
- **Then:**
  - The system asks no further question before it changes the slides.
  - No approval step appears beside the request.
- **Check:** deterministic

### AC-4 · An unrequested violation is not made

- **Given:** The design system "Acme" requires a brand footer on every slide. The layout of "Editorial" has no room for that footer. A deck has five slides. The user sends "make slide 2 use the airy layout of Editorial", and asks for no exception to the footer rule.
- **When:** The system works on the request.
- **Then:**
  - The system names the footer rule and asks the user to resolve the conflict.
  - Slide 2 is not changed in the conflicting way before the answer.
  - The other slides are as they were.
- **Check:** deterministic

### AC-5 · A Preferred Rule is not treated as a blocking rule

- **Given:** The design system "Acme" holds a Preferred Rule for dense slides. The visual style "Editorial" sets an airy layout. The user sends "use Editorial on slide 2".
- **When:** The system has changed the slide.
- **Then:**
  - The system applies "Editorial" without asking the user to resolve a conflict.
  - Slide 2 shows all of its content.
- **Check:** deterministic

### AC-6 · The resolution the user chooses is applied

- **Given:** The design system "Acme" requires its own heading treatment. The visual style "Editorial" sets a different heading treatment. A deck has five slides. The system named the conflict for a request to apply "Editorial" to slide 3.
- **When:** The user chooses the heading treatment of "Acme".
- **Then:**
  - Slide 3 follows the heading treatment of "Acme".
  - The system applies no exception.
  - Slides 1, 2, 4 and 5 are as they were.
  - "Acme" and "Editorial" hold the same rules as before.
- **Check:** deterministic
