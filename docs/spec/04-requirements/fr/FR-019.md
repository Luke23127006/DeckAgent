---
id: FR-019
title: "Report a request that cannot finish"
---

## Requirement

- **Statement:** When the work on a request cannot finish, the system ends the work and says that it did not finish. It says why when it knows the reason, such as a refused key or a reached usage limit. It keeps the request in the conversation and does not start the work again by itself.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-11: a failed request is reported, and the system offers no try-again action
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Failure ends the work

- **Given:** The system works on the request "a talk on our pilot results".
- **When:** The work cannot finish, in three separate runs. The model provider returns an error. The provider refuses access with the user's key. The provider reports that the usage limit is reached.
- **Then:**
  - In each run, the system no longer shows that it works on the request.
  - In each run, the conversation shows that the work did not finish.
  - In each run, the user's message is still in the conversation, the same as when it was sent.
  - In each run, the system never starts the work on the failed request again by itself.
  - In each run, any later work starts only from a request the user sends.
- **Check:** deterministic

### AC-2 · Known reason is given

- **Given:** The system works on a request. The model provider cannot be reached.
- **When:** The system says that the work did not finish.
- **Then:**
  - The message says that the system cannot reach the model provider.
  - The message names no other cause.
- **Check:** judged

### AC-3 · Refused key

- **Given:** The system works on a request. The provider refuses access because the user's key was revoked.
- **When:** The system says that the work did not finish.
- **Then:**
  - The message says that access to the model was refused.
  - The message says where the user fixes the key.
- **Check:** judged

### AC-4 · Usage limit reached

- **Given:** The system works on a request. The provider reports that the usage limit of the model account is reached.
- **When:** The system says that the work did not finish.
- **Then:**
  - The message says that the limit of the model account was reached.
- **Check:** judged

### AC-5 · New request after a failure

- **Given:** The state of AC-4.
- **When:** The user sends the new request "a talk on our pilot results, shorter".
- **Then:**
  - The conversation shows it as a new user's message.
  - The failed request shows once in the conversation. It is not sent again.
  - The system works on the new request.
- **Check:** deterministic

## Not specified

- Which causes of a failure keep the user from sending a new request. Pending owner decision.

## Notes

- What the work finished before the failure, such as finished slides, is not covered here. The requirements of that work cover it.
- Fixing the key is part of the model setup. This requirement covers only what the system says about the refused key.
- AC-1 holds with no time limit. A test observes the chat for a finite time, which checks the condition but does not limit it.
- The system does not always know the cause of a failure. AC-2 to AC-4 apply only when it knows the cause.
