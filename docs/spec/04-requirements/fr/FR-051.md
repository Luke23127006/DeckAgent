---
id: FR-051
title: "Open a chat that has no slides yet"
---

## Requirement

- **Statement:** An opened chat can have no slides yet. The system then shows its conversation in order and says that the chat has no slides yet. An outline that waits for confirmation still waits. With a confirmed outline, a new request builds on it and shows no second outline. With no finished outline, the user can send a new request in the chat. That request gets a new outline proposal. The system does not resume the earlier request, and uses no unfinished outline.
- **Status:** confirmed
- **Source:** use case flow; owner decision, 2026-10-13: after a request that ended before any outline was finished, a later request in the chat starts a new outline proposal; the earlier request is not resumed, and no unfinished outline is reused
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · An outline still waits for confirmation

- **Given:** Earlier chat X holds a request and outline proposal B, which the user has not confirmed. The deck of chat X has no slide.
- **When:** The user opens chat X.
- **Then:**
  - The conversation shows the request and proposal B, in order.
  - Proposal B is not confirmed. It is the current outline.
  - The system offers to confirm proposal B.
  - The deck has no slide.
- **Check:** deterministic

### AC-2 · The user is told there are no slides

- **Given:** The state after AC-1.
- **When:** The user reads the chat.
- **Then:**
  - The system says that chat X has no slides yet.
- **Check:** judged

### AC-3 · Confirmed outline and no slide

- **Given:** Earlier chat Y holds a confirmed outline of four planned slides. DeckAgent was closed before any slide was finished. The deck of chat Y has no slide.
- **When:** The user opens chat Y and sends "build the slides".
- **Then:**
  - No outline proposal appears.
  - The confirmed outline is the same as at the confirmation.
  - The system builds slides for the request.
- **Check:** deterministic

### AC-4 · No outline

- **Given:** Earlier chat W holds only the request "a talk on our pilot results". It ended before any outline was shown.
- **When:** The user opens chat W and sends "a talk on our pilot results".
- **Then:**
  - The conversation shows the new request as a new user's message.
  - The earlier request shows once, unchanged.
  - The system works on the new request.
  - The system shows a new outline proposal before it builds any slide.
- **Check:** deterministic

### AC-5 · The earlier request is not resumed

- **Given:** Earlier chat V holds the request "a talk on our pilot results". The work on it failed while the system drafted the outline, before the outline was finished.
- **When:** The user opens chat V and sends "a talk on our staff survey".
- **Then:**
  - The new outline proposal is about the staff survey.
  - It is not the unfinished outline of the earlier request.
  - The system does not run the earlier request again.
- **Check:** judged

## Notes

- A new request is not a try-again or a resume of the earlier request.
- Until 2026-10-13, whether such a new request gets an outline proposal was open. The owner decision of 2026-10-13 settled it.
- Opening the chat itself is covered by FR-049. A chat whose last request did not finish is covered by FR-052.
