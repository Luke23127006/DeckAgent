---
id: FR-075
title: "See and change the permission of a chat"
---

## Requirement

- **Statement:** The user can see the permission of a chat in plain words: what the agent of the chat can reach, and where it must ask the user first. The user can choose another permission for the chat and save it. The system makes the saved permission the permission of the chat and says what changed. Taking back a permission that lasts is such a saved change. A request that runs keeps the permission it started with; a saved change applies from the next request (FR-042). Opening the permission of the chat and changing it change no conversation, no request text and no attachment (FR-038). The system offers the named permission presets in [BR-009]. It shows each continuing approval of the chat with its named scope, and lets the user revoke it.

## Acceptance conditions

### AC-1 · The permission is shown in plain words

- **Given:** A chat with the default permission (FR-077). The request area holds request text and one ready attachment.
- **When:** The user opens the permission of the chat.
- **Then:**
  - The response says in words the user can read what the agent can reach and where it must ask first.
  - The conversation, the request text and the attachment are unchanged.
- **Check:** judged

### AC-2 · A saved change becomes the permission of the chat

- **Given:** The state after AC-1.
- **When:** The user saves another permission for the chat.
- **Then:**
  - The system makes the saved permission the permission of the chat and says what changed.
  - The next request of the chat runs with the saved permission (FR-042).
- **Check:** deterministic

### AC-3 · A running request keeps its permission

- **Given:** The state after AC-2. A request R1 of the chat started before the saved change and still runs.
- **When:** The system continues the work of R1.
- **Then:**
  - R1 keeps working within the permission it started with. The system did not stop R1 or start it again.
- **Check:** deterministic

### AC-4 · Revoke a continuing approval

- **Given:** Chat X has an approved continuing read scope for an outside file. Chat Y is a different chat.
- **When:** The user revokes that approval in Chat X.
- **Then:**
  - Chat X no longer has that continuing read scope for future requests.
  - A later request in Chat X needs another approval to read that outside file.
  - Chat Y is unchanged.
- **Check:** deterministic

## Notes

- The named permissions and the default permission are defined by [BR-009]. The permission of a request is captured when that request starts [FR-042].
- The default reach of the agent of a chat is covered by FR-077. The boundary of what the agent reaches is NFR-003.
