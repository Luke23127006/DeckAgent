id: FR-001
title: "Outline before any slide"
---

## Requirement

- **Statement:** For the first request of a chat, the system responds with an outline proposal before it builds any slide. That proposal becomes the current outline. Until the user confirms it, the system builds no slide, shows no deck canvas, and says so.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Outline proposal shown, no slide

- **Given:** A chat with no deck. The user sent a request with a topic and notes, for example "a talk on our pilot results, from these notes".
- **When:** The system has drafted the outline.
- **Then:**
  - The conversation shows an outline proposal as a response of the system.
  - That proposal is the latest outline response in the conversation.
  - The outline is not confirmed.
  - The deck has no slide.
  - The system shows no deck canvas.
- **Check:** deterministic

### AC-2 · Says that slides wait for confirmation

- **Given:** The state of AC-1.
- **When:** The system shows the outline proposal.
- **Then:**
  - The system tells the user that it builds no slide until the user confirms the outline.
- **Check:** judged

### AC-3 · No slide before confirmation

- **Given:** An unconfirmed current outline is shown. The deck has no slide.
- **When:** The user sends an instruction to revise the outline, or does nothing, for example for ten minutes.
- **Then:**
  - No outline proposal is confirmed.
  - The deck still has no slide.
  - The system shows no deck canvas.
- **Check:** deterministic
