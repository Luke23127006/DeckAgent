---
id: FR-074
title: "Reach a workspace folder that cannot be read"
---

## Requirement

- **Statement:** When the project folder of a workspace cannot be read, for example it was moved, deleted or access was taken away, the system says that the files of that folder cannot be read, and says which workspace it belongs to. It says what the user can do, for example put the folder back, give access again, or choose another folder for the workspace (FR-083). The workspace stays set up. Its chats, their conversations, their decks and their history stay readable, because they do not depend on that folder. The system deletes no chat, no conversation and no deck. The agent reads no file of that folder while it cannot be read, and never says that it read one. The system invents no reason and claims no cause it does not know: it names no cause when it cannot tell a deleted folder from a moved one or from access that was taken away. The system promises no return of a file the user put in that folder.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · The unavailable project folder is reported with its workspace

- **Given:** The workspace "Alpha" is set up for the folder "C:\ projects\alpha", which holds files, and holds one chat with a deck.
- **When:** The folder is moved away outside DeckAgent, and the user works in DeckAgent again.
- **Then:**
  - The system says that the files of the project folder of "Alpha" cannot be read, and names "Alpha".
  - The chat of "Alpha" still opens, with its conversation and its deck.
- **Check:** deterministic

### AC-2 · The workspace and its saved work stay

- **Given:** The state after AC-1.
- **When:** The user looks at the workspaces that are set up, then opens the earlier chat of "Alpha".
- **Then:**
  - While the folder was away, "Alpha" was still set up, and the system still said that the files of its folder cannot be read.
  - The chat of "Alpha" opened, with its conversation and its deck, the same as before the folder moved.
  - No chat, conversation or deck was deleted.
- **Check:** deterministic

### AC-3 · The files can be read again with the folder

- **Given:** The state after AC-1. The folder holds the file "report.pdf".
- **When:** The user puts the folder back where it was, and sends a request that uses "report.pdf".
- **Then:**
  - The system can read the files of the folder again, and "report.pdf" is part of the data of the request.
  - The chat keeps the conversation and the deck it had.
- **Check:** deterministic

### AC-4 · The user is told what to do next

- **Given:** The state after AC-1.
- **When:** The user reads the response of the system.
- **Then:**
  - The response says what the user can do, for example put the folder back, give access again, or choose another folder for the workspace.
- **Check:** judged

### AC-5 · No cause the system does not know

- **Given:** The project folder of "Alpha" cannot be read. The system cannot tell whether the folder was deleted, moved, or its access was taken away.
- **When:** The user reads the response of the system.
- **Then:**
  - The response says that the files of the folder cannot be read.
  - The response names no cause, and does not say that the folder was deleted.
  - It says no chat was deleted.
- **Check:** judged

### AC-6 · No claim to have read a file of a folder that is away

- **Given:** The state after AC-1. The request text says "summarize report.pdf", and the request holds no attachment.
- **When:** The request runs.
- **Then:**
  - The system reads no file of that folder and uses no content of one.
  - The response says that the file cannot be read.
- **Check:** deterministic

## Notes

- A file of the project folder that a request needs while the folder is away is FR-067 and FR-086.
- BR-004 sets that the system keeps every chat without a time limit, and that a loss DeckAgent did not cause stays outside its promise. The project folder holds the files of the user; removing it takes none of the work DeckAgent saved for the chats of its workspace.
- Choosing another folder for a workspace is FR-083. The system never treats a different folder at the old place as the earlier one when it can tell them apart (FR-083).
