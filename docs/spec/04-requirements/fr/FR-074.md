---
id: FR-074
title: "Reach a workspace folder that cannot be read"
---

## Requirement

- **Statement:** When the folder of a set-up workspace cannot be read, for example it was moved or access was taken away, the system says so and says which workspace it belongs to. It says what the user can do, for example put the folder back or give access again. The workspace stays set up, and the system reads the chats of that workspace again when the folder is back, with their conversations and their decks. The system deletes no chat, no conversation and no deck. The chats of a workspace are kept in its folder, so when that folder and the data in it are gone for good, the system has no copy of them and promises none: it says that those chats cannot be read, and it offers no copy. The system invents no reason and claims no cause it does not know.

## Acceptance conditions

### AC-1 · The folder that cannot be read is reported with its workspace

- **Given:** The workspace "Alpha" is set up for the folder "C:\ projects\alpha" and holds one chat with a deck.
- **When:** The folder is moved away outside DeckAgent, and the user works in DeckAgent again.
- **Then:**
  - The system says that the folder of "Alpha" cannot be read, and names "Alpha".
- **Check:** deterministic

### AC-2 · The workspace stays set up, and its chats come back with the folder

- **Given:** The state after AC-1.
- **When:** The user looks at the workspaces that are set up, then puts the folder back where it was, and works in DeckAgent again.
- **Then:**
  - While the folder was away, "Alpha" was still set up, and the system still said that its folder cannot be read.
  - No chat of "Alpha" was readable while the folder was away.
  - After the folder is back, the chat of "Alpha" is readable, with its conversation and its deck.
- **Check:** deterministic

### AC-3 · No copy of a folder that is gone for good

- **Given:** The folder "C:\ projects\alpha" is deleted outside DeckAgent together with the data DeckAgent kept in it. The user has no other copy.
- **When:** The user asks for the chats of that workspace.
- **Then:**
  - The response says that the chats of "Alpha" cannot be read, because the folder that holds them is gone, and it names "Alpha".
  - It offers no copy of those chats, and it claims none.
- **Check:** judged

### AC-4 · The user is told what to do next

- **Given:** The state after AC-1.
- **When:** The user reads the response of the system.
- **Then:**
  - The response says what the user can do, for example put the folder back or give access again.
- **Check:** judged

## Notes

- Whether adding the same folder again binds the chats of the removed or unreachable workspace is an open question in the design backlog of the ideal spec.
- BR-004 sets that the system keeps every chat without a time limit, and that a loss DeckAgent did not cause stays outside its promise. When the folder of a workspace and the data in it are gone, the chats of that workspace are gone with them.
- Whether the product keeps a copy of the workspace data outside its folder, as a backup, is an open question in the design backlog of the ideal spec.
