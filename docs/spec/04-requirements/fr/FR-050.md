---
id: FR-050
title: "Report a chat whose saved work cannot be read"
---

## Requirement

- **Statement:** When the user chooses a chat whose saved work cannot be read, the system says that it cannot open that chat. It says why when it knows the reason. It shows no empty chat in its place, and no chat as one that never held a conversation. It removes no chat, and it claims no cause it does not know: it does not say that the chat was deleted. It changes no other chat, and the current chat stays as it was. A project folder that cannot be read is not this failure: the chats of that workspace still open, and the system reports the folder for its workspace (FR-074). When the saved work of a whole workspace cannot be read, the system says what it cannot open and gives a next action when it knows one.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · Other chats stay as they were

- **Given:** Earlier chats X and Y. The work DeckAgent saved for chat X cannot be read. The user is in chat Z, which has a deck of three slides.
- **When:** The user chooses to open chat X.
- **Then:**
  - Chat Z is still the current chat, with the same conversation, request area and deck.
  - The user can open chat Y. Its conversation and its slides are the same as before.
- **Check:** deterministic

### AC-2 · The user is told what cannot be read

- **Given:** The state after AC-1.
- **When:** The user reads the response.
- **Then:**
  - The response says that chat X cannot be opened.
  - The response says that the work saved for chat X cannot be read.
- **Check:** judged

### AC-3 · No empty chat in its place

- **Given:** The state after AC-1.
- **When:** The user chooses to open chat X, and then asks for earlier work again.
- **Then:**
  - No chat with an empty conversation appears as chat X.
  - The deck canvas shows no deck of chat X.
  - Chat X still appears among the chats the user can open.
- **Check:** deterministic

### AC-4 · No cause the system does not know

- **Given:** The work saved for chat X cannot be read. The system cannot tell why.
- **When:** The user reads the response.
- **Then:**
  - The response names no cause, and does not say that the chat was deleted.
  - The response says that no chat was removed.
- **Check:** judged

### AC-5 · A project folder that cannot be read is not this failure

- **Given:** The project folder of the workspace of chat X cannot be read. The work saved for chat X can be read.
- **When:** The user chooses to open chat X.
- **Then:**
  - Chat X opens, with its conversation and its deck, as FR-074 says.
  - The response says that the files of the project folder cannot be read, and reports it for the workspace.
  - The response does not say that chat X cannot be opened.
- **Check:** deterministic

## Notes

- This requirement sets no repair of a chat that cannot be read. A save that fails while the user works is FR-087.
- A project folder that cannot be read is FR-074. A missing file of the folder during a request is FR-086.
