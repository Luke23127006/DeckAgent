id: FR-014
title: "One active request at a time"
---

## Requirement

- **Statement:** The system works on one request at a time. While a request is active, the user can prepare the next request in the request area. The user can type, and add or remove attachments that were not sent. They stay there as a draft. The system accepts no new request until the work ends or the user stops it. A request that waits for the user's answer is still active. Preparing the next request changes no input of the active request, such as the attachments sent with it.
- **Status:** confirmed
- **Source:** use case flow; owner decision, 2026-10-13: while the agent works, the user can prepare text and attachments for the next request; sent attachments stay with their request; the next request still cannot be sent while the current one is active
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Draft kept, no second request

- **Given:** The system works on a request. The request area is empty.
- **When:** The user types "also add a summary slide" and tries to send it.
- **Then:**
  - The request area shows "also add a summary slide".
  - The conversation shows no new user's message.
  - No second request starts.
  - The system still shows that it works on the first request.
- **Check:** deterministic

### AC-2 · No new request through a suggested option

- **Given:** The system works on a request. An earlier response in the conversation offers a suggested option.
- **When:** The user chooses that option.
- **Then:**
  - The conversation shows no new user's message.
  - No second request starts.
  - The system still shows that it works on the first request.
- **Check:** deterministic

### AC-3 · Draft can be sent after the work ends

- **Given:** The state after AC-1.
- **When:** The work on the first request ends, because the system finished it or the user stopped it.
- **Then:**
  - The request area still shows "also add a summary slide", unchanged.
  - The user can send it.
  - Once sent, it shows in the conversation as a new user's message.
  - The system works on it as a new request.
- **Check:** deterministic

### AC-4 · Attachments for the next request

- **Given:** The user sent "a talk from these notes" with the attachment "notes.docx". The system works on that request. The request area is empty.
- **When:** The user adds the file "chart.png" and the file "budget.pdf" to the request area. The user then removes "budget.pdf".
- **Then:**
  - The request area holds "chart.png" and no "budget.pdf".
  - The sent message still shows "a talk from these notes" with "notes.docx", unchanged.
  - No second request starts.
  - The system still shows that it works on the first request.
- **Check:** deterministic

## Notes

- What the user sends while the system waits for an answer is the answer to that request, with its attachments. FR-020 covers it. Preparing the next request gives no way to send a second request at the same time.
- Until 2026-10-13, whether the user can add or remove attachments while a request is active was open. The owner decision of 2026-10-13 settled it.
