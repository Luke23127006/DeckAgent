---
id: FR-087
title: "Report work that a chat cannot save"
---

## Requirement

- **Statement:** When the system cannot save the current state of a chat, it says that the work was not saved, and it says which change it cannot keep. Two changes are told apart: a change to the deck or to the outline, and a message of the conversation that was not saved, such as the request the user just sent. It does not say that the outline, the deck or the conversation holds a change that it cannot save. It keeps the last state it saved. It promises nothing about a message it did not save: that message is gone when the chat is opened again, and the system never says that it will be there. It does not start or resume the request by itself. When the chat is opened again, it shows the last saved state, and it shows no message and no change that it never saved. A failed save changes no file of the project folder and no other chat.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · A failed save is reported, not hidden

- **Given:** A chat holds a deck of five slides, saved. The user sends "make slide 3 shorter", and the chat saves that request. The system then changes slide 3 and cannot save the change.
- **When:** The work on the request ends.
- **Then:**
  - The response says that the change to the deck was not saved.
  - The response does not say that the deck holds the change.
  - The request is in the conversation.
- **Check:** judged

### AC-2 · The last saved state stays

- **Given:** The state after AC-1. DeckAgent is then closed and opened again.
- **When:** The user opens the chat.
- **Then:**
  - The deck canvas shows the five slides as they were at the last save.
  - Slide 3 shows no unfinished change.
  - The conversation holds the request and the messages it held at the last save.
- **Check:** deterministic

### AC-3 · No request starts again

- **Given:** The state after AC-1.
- **When:** The user waits and takes no action.
- **Then:**
  - The system sends no request again and starts nothing.
  - Any later work starts only from a request the user sends.
- **Check:** deterministic

### AC-4 · A failed save changes no file of the project folder

- **Given:** The chat belongs to a workspace whose project folder holds "report.pdf", "brand-guide.docx" and a folder named "photos". The system cannot save a change to the deck.
- **When:** The failure is reported.
- **Then:**
  - The folder holds the same entries as before, with the same content.
  - No file appears in the folder, including a hidden file.
  - The deck of any other chat is as it was.
- **Check:** deterministic

### AC-5 · A message that was not saved is reported apart from a deck change

- **Given:** A chat holds a deck of five slides, saved. The user sends "make slide 3 shorter", and the chat cannot save that request either. The system changes slide 3.
- **When:** The work on the request ends.
- **Then:**
  - The response says that the request was not saved, and it says that the change to the deck was not saved.
  - The response does not say that the deck holds the change.
  - The response does not say that the request will be in the conversation when the chat is opened again.
- **Check:** judged

### AC-6 · A chat that cannot save the request shows the last saved state

- **Given:** A chat holds a saved deck of five slides. The user sends a request, the system changes slide 3, and the chat cannot save the request or the change. DeckAgent is then closed and opened again.
- **When:** The user opens the chat.
- **Then:**
  - The deck canvas shows the five slides as they were at the last save, and slide 3 shows no unfinished change.
  - The conversation shows the messages it held at the last save, and no message that it never saved.
  - The system presents no message as saved that it did not save.
- **Check:** deterministic

## Notes

- What the chat shows when its saved work cannot be read at all is FR-050. The last saved state after an unexpected end of DeckAgent is NFR-008, which makes no promise that a result shown just before the end was saved.
- Whether the user can start the same work again is the try-again question of the request that failed, not this requirement.
- How and when DeckAgent saves is an architecture matter.
