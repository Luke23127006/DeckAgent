---
id: FR-058
title: "Add models to a provider configuration"
---

## Requirement

- **Statement:** The user can add models to a saved provider configuration. The system gets the model catalog from the provider when the user asks for it. It lets the user choose models from it. Getting it adds, removes and changes no added model and no selected model, and runs no model. The user can also give a model ID by hand, also one the model catalog does not hold [BR-005]. For each model the user adds, the system saves the model settings that the user gives or the provider reports, and fills in no value of its own [BR-005] [BR-?: model settings and reasoning levels]. The system saves each chosen model as an added model of that provider configuration only. It does not ask the provider to run it first. When the system cannot get the model catalog, it says so, and adding a model ID by hand stays possible.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: models are added from the model catalog or by model ID; a model ID is saved without a check with the provider; a missing model catalog leaves adding by model ID possible and changes no saved model; owner decision, 2026-10-12: getting the model catalog only gets information, and adds, removes or selects nothing; owner decision, 2026-10-25: each added model holds the model settings the user gives or the provider reports, and a setting that no source gives stays unset
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Add models from the model catalog

- **Given:** The provider configuration "Work AI" for provider P is saved with the key K1 and has no added model. A test account with P returns the model catalog M1, M2 and M3.
- **When:** The user asks for the model catalog of "Work AI", chooses M1 and M3, and saves.
- **Then:**
  - "Work AI" has the added models M1 and M3.
  - M2 is not an added model.
  - The user can choose M1 and M3 for a chat.
- **Check:** deterministic

### AC-2 · Add a model ID by hand, with no check first

- **Given:** The state after AC-1. The test account with P records each request it receives.
- **When:** The user gives the model ID M9, which the model catalog does not hold, and saves.
- **Then:**
  - "Work AI" has the added models M1, M3 and M9.
  - P has received no request that runs M9.
  - The user can choose M9 for a chat.
- **Check:** deterministic

### AC-3 · Model catalog not available

- **Given:** The state after AC-1. The test account with P returns an error for every request for the model catalog.
- **When:** The user asks for the model catalog of "Work AI". The user then gives the model ID M9 and saves.
- **Then:**
  - "Work AI" has the added models M1, M3 and M9.
  - "Work AI" is still saved with provider P and the key K1.
  - The user can choose M1, M3 and M9 for a chat.
- **Check:** deterministic

### AC-4 · The missing model catalog is reported

- **Given:** The state of AC-3, before the user gives M9.
- **When:** The user reads the response.
- **Then:**
  - The response says that the system did not get the list of models.
  - The response does not say that P has no models.
  - The response does not say that the added models of "Work AI" cannot run.
- **Check:** judged

### AC-5 · The same model ID in two provider configurations

- **Given:** "Work AI" connects to provider P with the key K1. "Lab" is a custom model API with the provider ID "lab" and the key K2. Neither has an added model.
- **When:** The user adds the model ID M1 to "Work AI" and saves.
- **Then:**
  - "Work AI" has the added model M1.
  - "Lab" has no added model.
  - The user can choose M1 of "Work AI" for a chat, and no model of "Lab".
- **Check:** deterministic

### AC-6 · Getting the model catalog changes nothing

- **Given:** "Work AI" for provider P has the added models M1 and M9. M9 was given by hand. Chat X has M9 of "Work AI" as its selected model. A test account with P returns the model catalog M1, M2 and M3, and records each request it receives.
- **When:** The user asks for the model catalog of "Work AI", chooses no model, and leaves the model setup.
- **Then:**
  - "Work AI" has the added models M1 and M9. M9 stays, though the model catalog does not hold it.
  - M2 and M3 are not added models.
  - Chat X still has M9 of "Work AI" as its selected model.
  - P has received no request that runs a model.
- **Check:** deterministic

## Notes

- A model the provider refuses when a request runs is covered by FR-019. Leaving the model setup without saving is covered by FR-044.
- The model catalog shows what the provider returns. It does not show which models the key can run.
- Until 2026-10-12, the system asked for the model catalog when the user chose to add models. The owner decision of 2026-10-12 on getting the model catalog made it a request of the user. AC-5 used two provider configurations for one provider until the decision on provider IDs.
