---
id: FR-054
title: "Change of chat while a request runs"
---

## Requirement

- **Statement:** While a request is active in a chat, the user can still start a new chat or open an earlier chat. The request keeps running in the chat it belongs to. The system does not stop it, pause it or move its work to the chat the user opens. The same holds when the user switches the workspace in use: the request keeps running in its chat, and its work keeps being saved in the workspace of that chat (FR-071). A request that waits for the user's answer keeps waiting, and an answer given in its chat is still its answer. A chat holds at most one request that the system works on or waits an answer in (FR-014).
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · The work keeps running in its chat

- **Given:** The system works on a request in chat X. Earlier chat Y exists, with a deck of three slides.
- **When:** The user opens chat Y while the request of chat X runs.
- **Then:**
  - Chat Y is the current chat.
  - The system still works on the request in chat X.
  - The deck of chat Y did not change, and no request starts in chat Y.
- **Check:** deterministic

### AC-2 · A waiting request keeps waiting

- **Given:** The system asked a question in chat X and waits for the answer. Earlier chat Y exists.
- **When:** The user opens chat Y, then opens chat X again.
- **Then:**
  - The system was still waiting for the answer while chat Y was open.
  - When chat X opens again, the question is in the conversation and still waits.
  - A reply the user sends in chat X is the answer to that request.
- **Check:** deterministic

### AC-3 · A new chat while a request runs

- **Given:** The system works on a request in chat X.
- **When:** The user starts a new chat Z while the request runs.
- **Then:**
  - Chat Z is the current chat, with an empty conversation and no deck (FR-053).
  - The system still works on the request in chat X.
- **Check:** deterministic

### AC-4 · One request in each chat

- **Given:** The system works on a request in chat Y. Chat X also exists.
- **When:** The user tries to send a new request in chat Y before that request ends.
- **Then:**
  - No second request starts in chat Y, as FR-014 says.
  - The request in chat X, if any, is not affected.
- **Check:** deterministic

## Notes

- Unsent request text stays with the chat in which the user wrote it, and unsent attachments leave the request area on a change of chat, as FR-049 and FR-053 say.
- The work keeps running while the interface is reloaded or closed, as FR-068 says. Work that ran when DeckAgent itself ended is not resumed (FR-052).
