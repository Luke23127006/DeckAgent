---
id: FR-054
title: "No change of chat while a request is active"
---

## Requirement

- **Statement:** While a request is active, the user cannot start a new chat or open an earlier chat. A request that waits for the user's answer is active. The system does not stop the request or move it to the background to change chats. Once the request finished, stopped or failed, the user can change chats.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-11: the user cannot start a new chat or open an earlier chat while a request in the current chat is active
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · No new chat while the system works

- **Given:** The user is in chat X. The system works on a request in chat X.
- **When:** The user tries to start a new chat.
- **Then:**
  - Chat X is still the current chat.
  - No new chat starts.
  - The system still shows that it works on the request.
- **Check:** deterministic

### AC-2 · No earlier chat while the system waits for an answer

- **Given:** The user is in chat X. The system asked a question in chat X and waits for the answer. Earlier chat Y exists.
- **When:** The user tries to open chat Y.
- **Then:**
  - Chat X is still the current chat.
  - The system still waits for the answer.
  - The request in chat X is still active.
- **Check:** deterministic

### AC-3 · Chats can change after the request ends

- **Given:** The user is in chat X. Earlier chat Y exists. A request in chat X ended, in three separate runs. The system finished it. The user stopped it. It failed.
- **When:** In each run, the user opens chat Y.
- **Then:**
  - In each run, chat Y is the current chat.
- **Check:** deterministic
