---
id: FR-121
title: "Export the current stable deck state"
---

## Requirement

- **Statement:** The system offers a deck export only when no request is active in the chat and the deck has at least one finished slide. The last request can have completed, stopped or failed. The export uses one stable snapshot: every finished slide, in its last finished version, in deck order. It holds no unfinished slide and no unfinished change. It exports the whole current deck, never a part the user picks. A partial deck is named as partial.
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · No export while a request is active

- **Given:** A deck of three finished slides. A request in the chat is running in one run, and waits for the user's answer in another run.
- **When:** The user asks to export the deck.
- **Then:**
  - In each run, the system does not offer the export.
  - In each run, the system says that the export is available once the request ends.
- **Check:** deterministic

### AC-2 · A stopped first draft exports its finished slides

- **Given:** A confirmed outline of ten planned slides. The first draft stopped after six slides were finished.
- **When:** The user exports the deck.
- **Then:**
  - The file holds six slides, in order.
  - The conversation says that the deck is partial and that the file holds six slides.
- **Check:** deterministic

### AC-3 · No finished slide, no export

- **Given:** The first draft stopped before any slide was finished.
- **When:** The user asks to export the deck.
- **Then:**
  - The system does not offer the export.
  - The system says that the deck has no finished slide.
- **Check:** deterministic

### AC-4 · A partially edited deck exports every slide

- **Given:** A deck of ten finished slides. A request changed all ten. It failed after six changes were finished.
- **When:** The user exports the deck.
- **Then:**
  - The file holds ten slides.
  - Six slides are the new finished versions.
  - Four slides are the versions from before the request.
- **Check:** deterministic

### AC-5 · One coherent snapshot

- **Given:** A deck of four finished slides. No request is active.
- **When:** The user exports the deck.
- **Then:**
  - Every page or file of the export comes from the same deck state.
  - No new request starts during the export.
- **Check:** deterministic

### AC-6 · No subset of slides

- **Given:** A deck of four finished slides.
- **When:** The user asks to export only slide 2.
- **Then:**
  - The system does not give an export of slide 2 alone.
  - An export the user starts holds all four slides.
- **Check:** deterministic

## Notes

- Which slide versions count as finished after a stop or a failure is FR-025.
