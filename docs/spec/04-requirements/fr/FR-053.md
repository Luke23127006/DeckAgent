---
id: FR-053
title: "Start a new chat"
---

## Requirement

- **Statement:** Starting a new chat keeps the current chat as it was, with its conversation and its deck. The system makes a new chat the current chat, with an empty conversation, no deck and an empty request area. The new chat takes nothing from an earlier chat, and the system builds no deck by itself. The user can send a request for a first draft in it. The new chat starts with the most recently selected model that is still selectable [BR-005]. An earlier selection counts when a later one is no longer selectable. A selection of a model that was later removed does not count, also after the model is added again. With no such model, the new chat has no selected model. After that, it keeps its own selected model. Unsent request text stays with the chat in which the user wrote it. The new chat does not take it, and the system does not send or delete it. Unsent attachments leave the request area of the earlier chat, and do not come back when it opens again. No file of the user changes.
- **Updated at:** 26-10-2026

## Acceptance conditions

### AC-1 · The new chat is empty

- **Given:** The user is in chat X, with a conversation and a deck of five slides. No request is active.
- **When:** The user starts a new chat.
- **Then:**
  - A new chat is the current chat.
  - Its conversation has no message.
  - Its deck has no slide.
  - Its request area holds no request text and no attachment.
  - No request starts.
- **Check:** deterministic

### AC-2 · The earlier chat stays

- **Given:** The state after AC-1.
- **When:** The user opens chat X again.
- **Then:**
  - The conversation of chat X is the same as before the new chat started.
  - The five slides of chat X are the same as before.
- **Check:** deterministic

### AC-3 · A first draft starts in the new chat

- **Given:** The state after AC-1. The new chat has a selected model that is selectable [BR-005].
- **When:** The user sends "a talk on our staff survey".
- **Then:**
  - The system responds with an outline proposal before it builds any slide.
- **Check:** deterministic

### AC-4 · Nothing comes from the earlier chat

- **Given:** The state after AC-3. Chat X is about the results of a hospital pilot.
- **When:** The user reads the outline proposal of the new chat.
- **Then:**
  - The proposal uses no content of chat X, such as its pilot results.
- **Check:** judged

### AC-5 · The new chat starts with the latest selected model

- **Given:** The user is in chat X with no active request. The user last chose the model M2, in chat X. M2 is still selectable [BR-005].
- **When:** The user starts a new chat Z.
- **Then:**
  - Chat Z shows M2 as its selected model.
  - Chat Z has no message and no slide.
- **Check:** deterministic

### AC-6 · The new chat keeps its own selected model

- **Given:** The state after AC-5.
- **When:** The user opens chat X, chooses the model M3 there, and then opens chat Z again.
- **Then:**
  - Chat Z still shows M2 as its selected model.
- **Check:** deterministic

### AC-7 · An earlier selection counts

- **Given:** No request is active. The user selected M3 at 09:00, M1 at 10:00 and M2 at 11:00, in different chats. The user then removed M2. M1 and M3 are still selectable.
- **When:** The user starts a new chat.
- **Then:**
  - The new chat shows M1 as its selected model.
- **Check:** deterministic

### AC-8 · No earlier selection is selectable

- **Given:** No request is active. The user selected only M1 and M2 before. The user then removed both. The added model M4 is selectable.
- **When:** The user starts a new chat.
- **Then:**
  - The new chat has no selected model.
  - The system did not select M4.
- **Check:** deterministic

### AC-9 · A selection from a deleted provider configuration does not count

- **Given:** No request is active. The user selected M3 of "Lab" at 09:00 and M1 of "Work AI" at 10:00, in different chats. "Work AI" connects to provider P. The user then deleted "Work AI". The user added provider P again as "Work AI", with the added model M1.
- **When:** The user starts a new chat.
- **Then:**
  - The new chat shows M3 of "Lab" as its selected model.
  - M1 of the new "Work AI" is not its selected model.
- **Check:** deterministic

### AC-10 · A model added again does not count

- **Given:** No request is active. "Work AI" has the added models M1 and M3. The user selected M3 at 09:00 in chat Y and M1 at 10:00 in chat X. The user then removed M1, and later added M1 again to "Work AI".
- **When:** The user starts a new chat.
- **Then:**
  - The new chat shows M3 of "Work AI" as its selected model.
  - M1 is not its selected model.
- **Check:** deterministic

### AC-11 · Unsent text stays with the earlier chat

- **Given:** The user is in chat X, with no active request. The request area of chat X holds the unsent request text "draft notes".
- **When:** The user starts a new chat, then opens chat X again. DeckAgent runs the whole time.
- **Then:**
  - The request area of the new chat holds no request text.
  - The conversation of chat X shows no new user's message.
  - After chat X opens again, its request area holds "draft notes", unchanged.
- **Check:** deterministic

### AC-12 · Unsent attachments do not move or come back

- **Given:** The user is in chat X, with no active request. The request area of chat X holds the unsent request text "draft notes" and the ready attachment "chart.png". "chart.png" comes from a file on the user's computer.
- **When:** The user starts a new chat, then opens chat X again.
- **Then:**
  - The request area of the new chat holds no attachment.
  - After chat X opens again, its request area holds "draft notes" and no attachment.
  - The file of "chart.png" on the user's computer is unchanged.
- **Check:** deterministic

## Notes

- Starting a new chat while a request runs is covered by FR-054. A new chat with no selected model is covered by FR-056. Whether an empty new chat counts among earlier chats is a value of BR-004.
