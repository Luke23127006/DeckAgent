---
id: FR-044
title: "Leave the model setup without unsaved changes"
---

## Requirement

- **Statement:** When the user leaves the model setup, the system applies no change that the user did not save. It keeps no unsaved connection setting, display name, added model or removal of a model. No later request uses an unsaved key. Every change the user saved stays, also one saved earlier in the same visit. Leaving the model setup sends no request.
- **Status:** confirmed
- **Source:** use case flow, and owner decision, 2026-10-12: leaving the setup discards only unsaved changes, and saved changes stay
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Nothing is saved

- **Given:** No provider configuration is saved.
- **When:** The user chooses provider P, gives the key K1, and leaves the model setup without saving.
- **Then:**
  - No provider configuration is saved.
  - A request the user sends next starts no work, because no provider configuration is saved.
- **Check:** deterministic

### AC-2 · The earlier configuration stays

- **Given:** A provider configuration for provider P is saved with the key K1. Chat X has the selected model M, an added model of this provider configuration. A test account with P records each request and the key it comes with.
- **When:** The user gives the new key K2 for P and leaves the model setup without saving. The user then sends a request in chat X.
- **Then:**
  - The model setup still shows the provider configuration for P as the only one saved.
  - P receives the request for model M with the key K1.
- **Check:** deterministic

### AC-3 · The unsaved key is not kept

- **Given:** The state after AC-2.
- **When:** DeckAgent is closed and opened again. The user sends a request in chat X.
- **Then:**
  - P receives the request for model M with the key K1.
  - P has received no request with the key K2.
  - The model setup still shows the provider configuration for P as the only one saved.
- **Check:** deterministic

### AC-4 · A saved change stays

- **Given:** The state of AC-2 before the user gave K2.
- **When:** The user gives the new key K2 for P and saves. The user then leaves the model setup and sends a request in chat X.
- **Then:**
  - P receives the request for model M with the key K2.
  - No request starts when the user leaves the model setup.
- **Check:** deterministic

### AC-5 · An unsaved display name is not kept

- **Given:** A provider configuration with the display name "Work AI" is saved.
- **When:** The user changes the display name to "Test AI" and leaves the model setup without saving.
- **Then:**
  - The model setup shows the display name "Work AI".
- **Check:** deterministic

### AC-6 · Unsaved model changes are not kept

- **Given:** The provider configuration "Work AI" has the added models M1 and M2.
- **When:** The user gives the model ID M9 to add, removes M2, and leaves the model setup without saving.
- **Then:**
  - "Work AI" has the added models M1 and M2.
  - M9 is not an added model of "Work AI".
- **Check:** deterministic

## Notes

- The chat stays as it was, as FR-038 says. A request with no provider configuration saved is covered by FR-046.
- This requirement is checked through the requests the provider receives. It does not promise how the system erases a key it did not save.
