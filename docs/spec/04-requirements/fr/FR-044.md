id: FR-044
title: "Leave the model setup without saving"
---

## Requirement

- **Statement:** When the user leaves the model setup before saving, the system adds no model. It keeps no key the user gave in that setup: no later request uses such a key. The model set up before stays set up, with its key.
- **Status:** confirmed
- **Source:** use case flow
- **Updated at:** 12-10-2026

## Acceptance conditions

### AC-1 · Nothing is set up

- **Given:** No model is set up.
- **When:** The user chooses provider P and its model M, gives the key K1, and leaves the model setup without saving.
- **Then:**
  - No model is set up.
  - A request the user sends next starts no work, because no model is set up.
- **Check:** deterministic

### AC-2 · The earlier setup stays

- **Given:** Model M of provider P is set up with the key K1. A test account with P records each request and the key it comes with.
- **When:** The user gives the new key K2 for P, leaves the model setup without saving, and sends a request.
- **Then:**
  - The model setup still shows model M with provider P as the only model set up.
  - P receives the request for model M with the key K1.
- **Check:** deterministic

### AC-3 · The unsaved key is not kept

- **Given:** The state after AC-2.
- **When:** DeckAgent is closed and opened again. The user sends a request in another chat.
- **Then:**
  - P receives the request for model M with the key K1.
  - P has received no request with the key K2.
  - The model setup still shows model M with provider P as the only model set up.
- **Check:** deterministic

## Notes

- The chat stays as it was, as FR-038 says. A request with no model set up is covered by FR-046.
- This requirement is checked through the requests the provider receives. It does not promise how the system erases a key it did not save.
