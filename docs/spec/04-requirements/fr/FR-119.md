---
id: FR-119
title: "Export the current slides as static files"
---

## Requirement

- **Statement:** A static export gives the finished slides in the format the user chose [BR-012]. A PDF export gives one file with one page for each finished slide. A PNG or JPEG export gives one image for each finished slide, and puts several images into one archive. The pages and images keep the slide order. A static export holds no separate presenter notes. The system says that animations and interactions do not work in a static file.
- **Updated at:** 28-10-2026

## Acceptance conditions

### AC-1 · PDF is one file

- **Given:** A deck of six finished slides.
- **When:** The user exports it as PDF.
- **Then:**
  - The export gives exactly one PDF file.
  - The PDF has six pages, in the order of the slides.
- **Check:** deterministic

### AC-2 · Several images go into one archive

- **Given:** A deck of six finished slides.
- **When:** The user exports it as PNG, and in another run as JPEG.
- **Then:**
  - Each run gives exactly one archive.
  - Each archive holds six images, one for each slide.
  - The names of the images keep the order of the slides.
- **Check:** deterministic

### AC-3 · One slide gives one image

- **Given:** A deck of one finished slide.
- **When:** The user exports it as PNG.
- **Then:**
  - The export gives one PNG image and no archive.
- **Check:** deterministic

### AC-4 · No separate notes

- **Given:** A deck of four slides. Slides 1 and 2 have presenter notes.
- **When:** The user exports it as PDF.
- **Then:**
  - The PDF has four pages that show the slides.
  - The export gives no separate file of notes.
- **Check:** deterministic

### AC-5 · Static nature is explained

- **Given:** A deck whose slide 3 has an animation.
- **When:** The user chooses a static export.
- **Then:**
  - The system says that the animation does not play in the static file.
- **Check:** judged
