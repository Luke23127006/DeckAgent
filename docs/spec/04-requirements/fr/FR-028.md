---
id: FR-028
title: "Carry on a first draft that stopped or failed"
---

## Requirement

- **Statement:** A new request after a first draft that stopped or failed builds on that draft. The system uses the confirmed outline and the finished slides as context. It shows no second outline, also when no slide was finished.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · No second outline after a stop or a failure

- **Given:** The user confirmed an outline of four planned slides. The first draft ended after slides 1 and 2 were finished, in two separate runs. The user stopped it. The model provider returned an error.
- **When:** In each run, the user sends "build the remaining slides".
- **Then:**
  - In each run, no outline proposal appears.
  - In each run, the confirmed outline is the same as at the confirmation.
  - In each run, slides 1 and 2 are the same as before the request.
- **Check:** deterministic

### AC-2 · Remaining slides follow the confirmed outline

- **Given:** The state of AC-1.
- **When:** The system has finished the request.
- **Then:**
  - The slides it built cover planned slides 3 and 4 of the confirmed outline.
  - No slide it built repeats slide 1 or slide 2.
- **Check:** judged

### AC-3 · No slide was finished

- **Given:** The user confirmed an outline of four planned slides. The model provider returned an error before any slide was finished. The deck has no slide.
- **When:** The user sends "build the slides".
- **Then:**
  - No outline proposal appears.
  - The confirmed outline is the same as at the confirmation.
  - The system builds slides for the request.
- **Check:** deterministic

## Notes

- The change itself follows FR-027. The slides kept after the stop or the failure are covered by FR-025.
