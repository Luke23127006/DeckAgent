---
id: FR-071
title: "Add a workspace and switch workspaces"
---

## Requirement

- **Statement:** The user can add a workspace of the ideal product by choosing a folder on the computer, and can switch the workspace in use among the workspaces that are set up. The system shows each workspace, and says which one is in use. Switching asks for no folder again. When the folder the user chooses is already in use by a workspace, the system makes that workspace the workspace in use and adds no second workspace for the folder. Each workspace holds a display name. The system changes no file of the user when it adds a workspace or switches, and sends no file of the folder to a model. It keeps its own workspace data in that folder, and changes, overwrites or deletes nothing there that DeckAgent did not write. Switching stops no request: a request that is active keeps running in its chat, and its work keeps being saved in the workspace of that chat (FR-054). Adding a workspace or switching makes it the workspace in use: the chats of that workspace are the earlier work the user sees (FR-048), and a new chat joins it (FR-053).

## Acceptance conditions

### AC-1 · Add a workspace for a new folder

- **Given:** Only the default workspace is set up, and it is the workspace in use. The computer holds the folder "C:\ projects\alpha" with three files.
- **When:** The user chooses to add a workspace and chooses that folder.
- **Then:**
  - A workspace for that folder is set up, with a display name, and is the workspace in use.
  - The folder still holds the same three files, unchanged.
- **Check:** deterministic

### AC-2 · A folder already in use returns the workspace that uses it

- **Given:** The state after AC-1. The workspace for "C:\ projects\alpha" has the display name "Alpha" and holds two chats.
- **When:** The user adds a workspace again and chooses the same folder.
- **Then:**
  - The system makes the "Alpha" workspace the workspace in use. It adds no second workspace.
  - "Alpha" keeps its display name. Its two chats are the chats of the workspace in use.
- **Check:** deterministic

### AC-3 · Switching needs no folder again

- **Given:** The state after AC-2. The user is working in the default workspace.
- **When:** The user switches the workspace in use to "Alpha".
- **Then:**
  - The system makes "Alpha" the workspace in use. It asks for no folder.
  - The chats of "Alpha" are the earlier work the user can open. The system changes no file of the user in the folder of the workspace the user left, and stops no request.
- **Check:** deterministic

### AC-6 · A request that is active keeps saving in its own workspace

- **Given:** A request is active in a chat of "Beta", and "Beta" is the workspace in use. That chat gets slides from that request.
- **When:** The user switches the workspace in use to "Alpha", and the request ends.
- **Then:**
  - The request kept running during the switch.
  - The chat in "Beta" holds the slides the request made.
  - The files of the user in the folder of "Alpha" and in the folder of "Beta" are as they were.
- **Check:** deterministic

### AC-4 · No file of the folder reaches a model by adding

- **Given:** A test account with a provider configuration records every request it receives and every content it carries. A fresh folder holds a file with a distinct marker text.
- **When:** The user adds a workspace for that folder.
- **Then:**
  - The test account receives no request whose content holds the marker.
- **Check:** deterministic

### AC-5 · The workspaces are shown with the one in use

- **Given:** The state after AC-2. The default workspace and "Alpha" are set up, and the default workspace is in use.
- **When:** The user chooses to add a workspace or to switch the workspace in use.
- **Then:**
  - The response shows each workspace that is set up, and says which one is in use.
- **Check:** judged

## Notes

- What display name a new workspace gets, and whether the other setup workspaces exist besides the default workspace, are open questions in the design backlog of the ideal spec.
- Choosing a folder puts the files of the user in that folder inside the permission of the chats of that workspace, and gives no reach outside it. FR-077 and NFR-003 cover the boundary.
- The same folder holds the workspace data of the chats of that workspace, which DeckAgent writes. The files of the user there stay as they are, and so does content that DeckAgent did not write. What the system does when the place it uses for its data is already taken is an open question in the design backlog of the ideal spec.
- How the system keeps workspaces, and how a workspace names its folder, are architecture matters.
