---
id: FR-034
title: "Keep an unclear instruction for later slides"
---

## Requirement

- **Statement:** The user can choose to keep an unclear instruction for later. The system then changes no existing slide and builds no new slide now. It says in the conversation that it kept the instruction and changed no slide. Every slide it builds later in the chat follows the kept instruction. The kept instruction changes no existing slide by itself, also when a later request changes that slide. The user can replace or withdraw it in a later request. The user can also ask in a request to change existing slides in the same way.
- **Status:** confirmed
- **Source:** use case flow; owner decision, 2026-10-13: an instruction kept for later slides applies to slides built later; it does not change existing slides by itself; the user can replace or withdraw it through a later request
- **Updated at:** 13-10-2026

## Acceptance conditions

### AC-1 · Nothing changes now

- **Given:** A deck of five slides. The user sent "make it more formal and add a slide on costs". The system offered its outcomes and waits for the answer.
- **When:** The user chooses to keep the instruction and change no slide now.
- **Then:**
  - Slides 1 to 5 are the same as before the request.
  - The deck has five slides.
  - The system shows that its work on the request is done.
- **Check:** deterministic

### AC-2 · System says it kept the instruction

- **Given:** The state after AC-1.
- **When:** The user reads the conversation.
- **Then:**
  - The conversation says that the system kept the instruction.
  - The conversation says that the system changed no slide.
- **Check:** judged

### AC-3 · A later slide follows the kept instruction

- **Given:** The state after AC-1.
- **When:** The user sends "add a slide on next steps at the end".
- **Then:**
  - The new slide is about next steps.
  - Its wording is formal.
- **Check:** judged

### AC-4 · Existing slides stay

- **Given:** The state after AC-1.
- **When:** The user sends "add a slide on next steps at the end".
- **Then:**
  - Slides 1 to 5 are the same as before this request.
- **Check:** deterministic

### AC-5 · A change to an existing slide does not take the kept instruction

- **Given:** The state after AC-1. Slide 2 has an informal tone.
- **When:** The user sends "make slide 2 shorter".
- **Then:**
  - Slide 2 is shorter than before.
  - The wording of slide 2 is not made more formal.
  - Slides 1, 3, 4 and 5 are the same as before this request.
- **Check:** judged

### AC-6 · A withdrawn instruction no longer applies

- **Given:** The state after AC-1. Slides 1 to 5 have an informal tone.
- **When:** The user sends "stop using the formal style for new slides". The user then sends "add a slide on next steps at the end".
- **Then:**
  - The new slide is about next steps.
  - The new slide does not follow the withdrawn instruction. Its wording keeps the informal tone of the deck.
- **Check:** judged

## Notes

- Until 2026-10-13, whether the kept instruction applies to a change of an existing slide, and how the user stops it, were open. The owner decision of 2026-10-13 settled both.
