---
id: FR-077
title: "Limit the reach of the agent of a chat by default"
---

## Requirement

- **Statement:** A new chat holds a permission limited to the workspace of the chat, to the data of its requests, and to the files and folders the user names in them as references. Within that permission, the agent can find and read the files of the workspace that the work needs, as the read reach of the permission allows. The agent never reaches the data of another chat, also not when both chats share a workspace, and never a place that the permission does not give: that needs the approval of the user (FR-076). Full access to the computer is never a permission the system sets by itself, and no content of a request, an attachment, a file or a raised permission of another chat raises the permission of the chat. The agent never changes, overwrites or deletes the original file of an attachment or of a reference. What the work creates goes only to places the permission allows.

## Acceptance conditions

### AC-1 · A new chat holds the limited permission

- **Given:** A new chat in a workspace whose folder holds files.
- **When:** The user opens the permission of the chat (FR-075).
- **Then:**
  - The permission shown covers the workspace of the chat, the data of its requests, and the files and folders its requests name as references. It covers no other chat and not the whole computer.
- **Check:** judged

### AC-2 · Work can read what the permission gives

- **Given:** The state after AC-1. The workspace folder holds a file that the request asks the work to use.
- **When:** The system works on a request that names the file as a reference, within the default permission.
- **Then:**
  - The work reads the file and uses it in its result, without an approval for it.
- **Check:** deterministic

### AC-3 · Beyond the permission needs an approval

- **Given:** The state after AC-1. The work on a request reaches a step that reaches outside the permission, such as a file no request of the chat named and no approval given.
- **When:** The system needs the step.
- **Then:**
  - No step beyond the permission is done without an approval of the user (FR-076).
- **Check:** deterministic

### AC-4 · No reach into another chat

- **Given:** Two chats X and Y in the same workspace. Y holds a conversation and a deck. The user works on a request in X.
- **When:** The request, an attachment of it, or the work of X asks the system to read the conversation, the deck or the attachments of Y.
- **Then:**
  - The system reads nothing of Y without an approval of the user (FR-076). The step needs an approval like any step beyond the permission.
- **Check:** deterministic

### AC-5 · Originals are never overwritten and outputs stay inside

- **Given:** The state after AC-2. The work also creates output for its result, such as a changed deck and a prepared file.
- **When:** The work writes its results.
- **Then:**
  - The original file the user gave as an attachment or named as a reference is the same as before the work.
  - Everything the work created is in a place the permission of the chat allows.
- **Check:** deterministic

## Notes

- What a new chat holds by default beyond its workspace and its own data, and which named permissions exist, are open questions in the design backlog of the ideal spec. This requirement sets the boundary, not the names.
- That no run ever reaches beyond the permission is measured by NFR-003 and NFR-004. What the agent sends outside the computer is NFR-007.
