---
id: FR-003
title: "Confirm the current outline"
---

## Requirement

- **Statement:** The system offers to confirm a current outline that is not empty. A clear confirmation confirms only the current outline, in a new request or in the request that asked. The system prepares the slides from the confirmed outline, which stays fixed for the slides it builds.
- **Updated at:** 25-10-2026

## Acceptance conditions

### AC-1 · Confirmation is offered

- **Given:** The system has shown an outline proposal of four planned slides. It is the current outline.
- **When:** The user reads the proposal.
- **Then:**
  - The system offers to confirm the outline as a suggested option.
- **Check:** deterministic

### AC-2 · Confirm the current outline, not an earlier one

- **Given:** The conversation shows proposal A, then proposal B after a revision. B is the current outline. No request is active.
- **When:** The user sends "Confirm the outline".
- **Then:**
  - The confirmation shows in the conversation as the user's message.
  - The system works on the confirmation as a new request.
  - The system shows that proposal B is confirmed.
  - Proposal A is not confirmed.
  - The planned slides of B are the same as before the confirmation.
- **Check:** deterministic

### AC-3 · Suggested option has the same result

- **Given:** The state of AC-2. The system offers to confirm the outline as a suggested option.
- **When:** The user chooses that option.
- **Then:**
  - The outcomes are the same as in AC-2.
- **Check:** deterministic

### AC-4 · Positive message with a change is not a confirmation

- **Given:** An unconfirmed current outline. The deck has no slide.
- **When:** The user sends "Looks good, but add a slide on costs".
- **Then:**
  - No outline proposal is confirmed.
  - The deck has no slide.
- **Check:** deterministic

### AC-5 · Confirmed outline stays fixed

- **Given:** A confirmed outline of four planned slides. The system builds the slides.
- **When:** The user writes an instruction that asks to change the outline.
- **Then:**
  - The confirmed outline in the conversation is the same as at the confirmation.
  - No new outline proposal appears.
- **Check:** deterministic

### AC-6 · Slides are prepared from the confirmed outline

- **Given:** A current outline that is not empty.
- **When:** The user confirms the outline.
- **Then:**
  - The system shows that it is preparing the slides from the confirmed outline.
- **Check:** judged

### AC-7 · Confirmation given as an answer

- **Given:** The conversation shows proposals A and B. B is the current outline. The system asked whether the user wants to confirm B or keep revising it, and waits for the answer.
- **When:** The user answers "Confirm it".
- **Then:**
  - The system shows that proposal B is confirmed.
  - Proposal A is not confirmed.
  - The answer is part of the request that asked.
  - No second request starts.
- **Check:** deterministic

## Notes

- An unclear message about the outline gets a question first. FR-007 covers it.
