## Requirement

- **Quality attribute:** performance
- **Statement:** After the user sends a request, the system soon shows that it received the request and works on it. This first sign does not wait for a reply of the model provider.
- **Why:** A selected flow shows this sign after sending and marks that its speed needs a quality requirement. The boundary is the author's reading: the first sign is a response of DeckAgent, so provider time does not count. Trade-off: the target says nothing about how soon the model starts to answer.
- **Updated at:** 25-10-2026

## Verification

### M-1 · Time to the first sign of work

- **Conditions:** A chat with a model set up and no active request. The user sends a request with request text only and no attachment. Boundary: product-controlled, as the proposed statement says. The time ends at the first sign, which does not wait for any reply of the model provider. Provider-dependent conditions: the response time of the provider, and whether it can be reached. Runs are made with a provider that answers slowly and with one that cannot be reached. Every run uses the same computer, and the report names it.
- **Measure:** The time from sending the request to the first sign of work. The first sign is the moment the conversation shows that the system received the request and works on it.
- **Method:** Send the request many times under each provider condition. For each run, observe both moments as the user sees them, with one clock, and record the time between them. Report the times for each provider condition apart.
- **Target:** not set
- **Met when:** not set
- **Why:** No decision sets the time, or the share of runs that must meet it.
