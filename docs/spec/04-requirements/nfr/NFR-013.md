---
id: NFR-013
title: "Keyboard and screen reader use, slide text included"
---

## Requirement

- **Quality attribute:** accessibility
- **Statement:** A user can do every task in the Local Web interface with a keyboard alone. A user of a screen reader can do every task and gets what the system says. A screen reader reads the text of each slide in the deck canvas.
- **Updated at:** 25-10-2026

## Verification

### M-1 · Keyboard alone

- **Conditions:** The tasks are these. Prepare and send a request with an attachment, and answer a question. Confirm or cancel the outline, and stop a request. Review the slides, change the model setup and choose a model. Start a new chat, and open an earlier chat. A person uses a keyboard and no pointing device. Boundary: product-controlled. Provider-dependent conditions: none change the result. A model service returns fixed content.
- **Measure:** Whether each task can be done with a keyboard alone. Whether the user can always tell where the next key press goes.
- **Method:** A person does each task with a keyboard alone. The person records each step that cannot be done, and each moment where the next key press is unclear.
- **Target:** Every task can be done. The place of the next key press is always clear.
- **Met when:** Every task meets the target.

### M-2 · Screen reader

- **Conditions:** The tasks of M-1. A person uses a screen reader.
- **Measure:** Whether each task can be done with the screen reader. Whether the person gets each status message, notice and question when it appears.
- **Method:** A person who uses a screen reader does each task. The person records each step that cannot be done, and each message that the screen reader does not give.
- **Target:** Every task can be done. Every status message, notice and question reaches the person.
- **Met when:** Every task meets the target.

### M-3 · Text of slides

- **Conditions:** Finished slides with titles, points and tables, shown in the deck canvas. A person uses a screen reader. Boundary: product-controlled. Provider-dependent conditions: none change the result. A model service returns fixed slide content.
- **Measure:** Whether the screen reader gives all the text of each slide, in the order of the slide's content.
- **Method:** Compare the text that the screen reader gives with the text that each slide holds.
- **Target:** All the text of each slide is given, in that order.
- **Met when:** Every slide meets the target.

### M-4 · Conformance to a standard

- **Conditions:** The whole Local Web interface, with the tasks of M-1. Boundary: product-controlled. Provider-dependent conditions: none.
- **Measure:** Conformance to an accessibility standard at a chosen level.
- **Method:** Check the interface against each criterion of that standard at that level.
- **Target:** not set
- **Met when:** not set
- **Why:** The owner has not chosen the standard or its level.

## Notes

- This requirement applies to every part of the Local Web interface.
- Text that is part of an image on a slide is not covered. No reading of such text is promised.
- How slides are made readable by a screen reader is an architecture matter.
