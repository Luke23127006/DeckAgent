id: NFR-011
title: "Stop takes effect soon"
---

## Requirement

- **Quality attribute:** performance
- **Statement:** After the user stops a request, the system soon shows that the stop took effect. This holds also when the model provider sends nothing.
- **Why:** The sign of the stop does not wait for the provider. Trade-off: the target says nothing about work that goes on at the provider.
- **Updated at:** 25-10-2026

## Verification

### M-1 · Time to the sign of the stop

- **Conditions:** Requests are stopped while the outline is drafted, and while slides are built. Others are stopped while slides are changed, and while the system waits for an answer. Boundary: product-controlled, as the statement says. Provider-dependent conditions: the response time of the provider, and whether it sends anything. Runs are made with a provider that answers slowly and with one that sends nothing. Every run uses the same computer, and the report names it.
- **Measure:** The time from the stop to the moment the system shows that the stop took effect.
- **Method:** Stop many times under each condition. Observe both moments as the user sees them, with one clock. Report each condition apart.
- **Target:** not set
- **Met when:** not set
- **Why:** No decision sets the time, or the share of runs that must meet it.
