---
id: NFR-004
title: "Shown content does not run as code"
---

## Requirement

- **Quality attribute:** security
- **Statement:** Content that the model writes, or that comes from an attachment, is shown only as content. It never runs as code that can reach the data of DeckAgent, a key or the network. Code that the trusted parts of DeckAgent run to do the work and to show slides is not such content.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-13: content from the model or from attachments never runs code with access to data, keys or the network that it was not given; the trusted parts of DeckAgent still run the code that DeckAgent needs
- **Why:** Content shown to the user could reach the data that the agent cannot reach, if it ran as code. Loading a font, an image or another resource that a slide needs is not running code.
- **Updated at:** 13-10-2026

## Verification

### M-1 · Content that holds code

- **Conditions:** Attachments and model output hold code samples meant to run when they are shown. Examples are a script, markup that runs code on an event and a link that runs code. The samples are shown in the deck canvas, in the conversation and in an attachment preview. A provider configuration with the key K1 is saved. Boundary: product-controlled. Provider-dependent conditions: none change the result. A model service returns the samples on purpose.
- **Measure:** Whether any sample runs. Whether a sample reads or changes data of DeckAgent, reads K1 or opens a network connection.
- **Method:** Give each sample an effect that can be observed, such as a change to saved data or a connection to a test address. Show each sample in each zone. Check for each effect.
- **Target:** No sample runs. No effect is observed.
- **Met when:** Every sample meets the target in every zone.

## Notes

- Where a request to load a resource can go is a matter of user content egress, not of this requirement.
