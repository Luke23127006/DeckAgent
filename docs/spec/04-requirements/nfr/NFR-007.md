---
id: NFR-007
title: "Where user content goes"
---

## Requirement

- **Quality attribute:** privacy
- **Statement:** User content leaves the computer only in the requests that DeckAgent sends to the provider of the selected model. Another outside service receives user content only when the owner approved that service. Each other outside connection carries no user content. The project documentation lists each such connection with its scope and purpose.
- **Updated at:** 25-10-2026

## Verification

### M-1 · User content goes only to the provider

- **Conditions:** A chat with marker text in its request text, its attachments and its deck. The user runs a first draft and a change to the deck. One request fails, and the user stops another. A request asks for a new image on a slide. The selected model belongs to a provider configuration with the base URL U1. Model output holds references to outside addresses, such as the address of an image. Boundary: product-controlled. Provider-dependent conditions: none change the result. A model service at U1 returns that output on purpose. No outside service is approved.
- **Measure:** Which destinations receive the marker text, or any part of the attachments or the deck.
- **Method:** Record every outgoing connection during the runs, also while the content is shown. Search each connection for the markers and for the attachments.
- **Target:** Only U1 receives them, and only in the requests of that chat.
- **Met when:** Every run meets the target.

### M-2 · Other connections are listed and carry no content

- **Conditions:** As in M-1. DeckAgent also starts, stays idle, shows the earlier chats and opens the model setup.
- **Measure:** Whether each outgoing connection that does not go to U1 is in the list of the project documentation. Whether it carries user content.
- **Method:** Record every outgoing connection. Compare each one with the list, its scope and its purpose. Search each one for the markers.
- **Target:** Every such connection is in the list and carries no marker.
- **Met when:** Every run meets the target.

## Notes

- User content is the request text, the attachments, the conversation, the outline and the deck. Keys are covered by a separate requirement.
- A provider configuration of a custom model API sends user content to its own base URL. That is the provider of the selected model.
- Making a new image is work on user content. A service other than the provider of the selected model gets content for it only after an owner approval.
- Which connections the list holds is set during architecture work. A connection in the list still carries no user content.
- Writing the file of an export on the computer of the user is not an outside connection of this requirement. What an export holds is set by the behavior requirements of the export, and keys are covered by NFR-006.
