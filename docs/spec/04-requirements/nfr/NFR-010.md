---
id: NFR-010
title: "Robust intake of added files"
---

## Requirement

- **Quality attribute:** reliability
- **Statement:** A file the user adds affects only its own attachment, whatever the file holds. DeckAgent keeps responding while it prepares the file. Each added file ends as ready or as rejected.
- **Status:** confirmed
- **Source:** owner decision, 2026-10-13: a damaged, hostile or very large file never breaks DeckAgent and never changes data it does not concern; the limits on file types, numbers and sizes stay in the attachment rule
- **Why:** Trade-off: some valid but extreme files are rejected.
- **Updated at:** 13-10-2026

## Verification

### M-1 · Hostile and extreme files

- **Conditions:** A set of files of each accepted type [BR-001]. The set holds damaged files, protected files and files over the limits. It also holds files that grow very large when opened, and files nested many levels deep. Chat Y with a deck exists beside the current chat. Boundary: product-controlled. Provider-dependent conditions: none, because the files are prepared before any request.
- **Measure:** For each file: its final state. Whether DeckAgent kept responding while it prepared the file. Whether another attachment, request or chat changed.
- **Method:** Add each file in turn. While it is prepared, check that the user can remove it and type in the request area. Compare the other attachments and chat Y before and after.
- **Target:** Each file ends as ready or as rejected with a reason. DeckAgent keeps responding. Nothing else changes.
- **Met when:** Every file in the set meets the target.

### M-2 · Time to a final state

- **Conditions:** The set of M-1, and ordinary files of each accepted type at sizes up to the limit [BR-001]. Boundary: product-controlled. Provider-dependent conditions: none. Every run uses the same computer, and the report names it.
- **Measure:** The time from adding a file to the moment its attachment shows ready or rejected.
- **Method:** Add each file many times. Observe both moments with one clock. Report each kind of file apart.
- **Target:** not set
- **Met when:** not set
- **Status:** pending
- **Source:** evidence needed
- **Why:** The limits of the attachment rule are not set, and no prototype has measured the time.

## Notes

- Which files are accepted, and why one is rejected, is set by the attachment rule and by behavior requirements.
- What hidden instructions in a file can make the agent do is not a matter of this requirement.
