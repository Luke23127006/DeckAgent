## Situation and goal

The user has material for a presentation, such as rough ideas, notes, a document or photos, and an empty deck. They want a first draft of slides generated for them instead of building the deck slide by slide.

## Trigger and preconditions

- Trigger: the user starts a request in the request area of an empty presentation. `[observed: claude-slides-design start.png, napkin-ai start.png]`
- Preconditions: the presentation has no slides yet. `[observed: claude-slides-design start.png]`

## Main flow

The main flow takes the user's input without saying how it was entered. Each input method is an alternative flow (A1 to A4). The deck uses a default design system; choosing another is A5.

| Step | Actor action | System response | Requirements |
|---|---|---|---|
| S1 | Provides the material and instructions for the deck in the request area | Shows what the user provided in the request area | FR-? |
| S2 | Sends the request | Shows that the request was received and work has started [NFR-?: feedback after sending] | FR-? |
| S3 | Waits and watches the canvas | Shows slides appearing in the deck canvas in the default design system [BR-?: default design system], replacing the empty-state message [NFR-?: wait for first slides] | FR-? |
| S4 | Reviews the draft | Shows the full draft deck in the canvas, and a message in the chat that the draft is ready | FR-? |

## Postconditions and minimal guarantee

Proposals, to be confirmed against recordings.

- Postconditions: the presentation contains slides generated from the user's input, in the default design system, or in the chosen one when A5 was used. The empty-state message is gone.
- Minimal guarantee: whatever branch fails, the user's request text and attached material stay in the request area, so nothing has to be re-entered. `[assumed]`

## Notes

1. Design choice for an ADR proposal: the default design system is fixed in V1 (hardcoded). What it is, and how a later custom design system replaces it, is open.
2. Input type does not create a new use case. Text, voice, files and connectors are different ways to complete S1; the goal and the result are the same.
3. V1 accepts local files only (A3). Third-party sources (A4) are out of scope for V1.
4. Accessibility (keyboard operation, announcements to assistive technology, zoom) is not written into steps. A global NFR in `032-nfr/` applies to every part of the interface, so this use case does not cite it.
