### Changed

- **The workflow becomes direction, not a rulebook** (`WORKFLOW.md`): each phase says **why** and closes with a **"Done when"** list the team **checks itself**, instead of a **gate**; phases **may overlap** when the work allows it. The PO decides **what is costly to get wrong** (the **spec**, **technology choices**, **scope**, the **module and LLM boundaries**, **accepting a build**); the **team does and reviews the rest itself**. Phase 2 is renamed **"Tests before code"**.
- **Tests are not locked and need no PO approval**: a test PR is **reviewed like code**, and a later change to a test **says why in its PR**. Writing an FR's tests **preferably falls to someone other than its implementer**, no longer a rule. `tests/acceptance/` and `tests/eval/` leave **CODEOWNERS**, and WORKFLOW's "Enforcement" becomes **"Safety nets"**.
- **Ticket rules become "Good tickets"**: a ticket should be **doable without the context**, by a teammate or a small model. The **at most 3 files** cap, the **PO approval before assignment** and the hard **separation rule** are dropped.
- **The test strategy replaces its gates with checks** (`dev/development/test-strategy.md`); the skills `testing-plan`, `ticket-writer`, `flow-tracker-update`, `research-questions` and `equivalence-partitioning`, the plan templates, the issue and PR templates and the first build's testing records follow the new wording.
- **A build folder holds three groups**: `research/`, `testing/` (`analysis/`, `planning/`, `design/`, `execution/`) and `implementation/`. The **acceptance criteria move** from the testing plan to `testing/design/acceptance-criteria.md`; the **testing plan keeps planning decisions only**. The workflow, test strategy, spec criteria, templates, skills and issue templates **point to the new paths**.
- **Test strategy** gains **per-case records**, **four coverage statuses**, a **completion check** for closing test cases, and the rule that **design evidence is not execution evidence**; the universal "**at most one invalid value per case**" rule is **replaced by each technique's combination rule**.
- **Testing follows the STLC frame inside the existing phases**: Phase 2 has **Gate 1** (scope and approach, on the new **test analysis** record `test-analysis.md`) and **Gate 2** (test design); Phase 6 has **Gate 3** (build verdict, on the new **test summary** `test-summary.md`). Level, type, technique and coverage criterion are **kept apart**; AC, condition and test case are **separate concepts**; scope and its approval are **two attributes**; coverage has **five measures**, with `excluded` and `deferred` items reported **beside the ratio**.
- **Spec of the first build after its Gate 1 rulings**: **FR-143** refuses workspace and chat changes from **clients DeckAgent does not allow**; **BR-020** normalizes every name to **NFC** and **trims only names the user gives**; **FR-071**, **FR-083**, **FR-141** and **BR-019 V-1** follow these rulings.
- **Test analysis of the first build** passes **Gate 1**: 180 basis items (114 to test, 64 deferred, 2 excluded), all with an approved scope.
- **The review-flows view becomes the test design specification** `test-design.md` (template `dev/mvp/templates/test-design.md`), the **record of Gate 2**: **which techniques** apply and **why**, **how each was applied**, the **conditions** with their **basis items**, the **coverage items**, the **links to AC and test cases**, and the **gaps, deviations and design rulings**. Each technique keeps **its own form** (flows, state × event matrix, decision rules, partitions and boundaries, threat scenarios, injection points). The first build's `review-flows.md` is **renamed** with its content kept.
- **Testing plan** gains a **"Testing risks"** section (what could stop a test from running or make it pass without proof), names its coverage column **"Planned coverage"** so it does not read as a test result, and says which **29119-3 documents** it joins. **Phase 6**: a row that still fails is **fixed in a light build** or its behavior is **moved to the spec backlog**.
- **Phase 2 derives from the test strategy**: the `testing-plan` skill and template set a **risk level per item**, a **`Catches` line per criterion**, the **test driver and fixtures**, post-implementation tests and test-stub tickets. A CI test is an **expected failure** whose **implementation PR's first commit** shows it **fails on an assertion**.
- **FR-071**: a folder name **longer than the longest name is cut**; adding a folder that **was moved** gives its workspace **the new place**. **FR-141**: spaces at both ends are **dropped**, a **refused name changes nothing**. **DEC-012**: the **current chat is not shared** between interfaces.
- **Research checklist format "map first, questions after"** (template, skill `research-questions`, skill `ticket-writer`, research ticket template): a **map of the whole product** with the **build's blocks highlighted**, the **build's boundary**, then **questions per block**, each **triaged by how it gets answered** (no research needed, later build, existing evidence, small check, PO decides). **Only the last three get a ticket.** Prose in Vietnamese with English technical terms.
- **Phase 1 of the first build** (workspaces and new chat) **started**: research checklist and traceability matrix in `dev/mvp/builds/UC-013-workspaces-new-chat/`.
- **Phase 0 is closed.** The **walking skeleton is deferred** to the **first implementation ticket of the first build**: OpenCode **already ran on Windows** in the reference, **runtime questions** belong to the **Phase 1 research** of the build that touches them, and the **first build calls no runtime**. The **spike on check faults** moves to **Phase 1 of the slide build**.
- **Workspaces** (UC-013, UC-006): a new workspace **takes the name of its folder**, **two workspaces may share a name**, and the user **renames a workspace** (new FR-141). A **removed workspace's chats become ungrouped chats**, **apart from every workspace**, as DeepSeek Harness does; **adding the folder again gives an empty workspace**. The open question on workspace names is answered.
- **Markdown form** (AGENTS.md "Writing Markdown"): **no hard wrap**, each paragraph or list item **on one line**; each sentence **bolds its keywords**. Every Markdown file outside `dev/legacy/` was **unwrapped**; spec style rule 9 and research style rule 3 follow the new rule. Every living document **bolds its keywords**: the spec, the workflow, the templates, the skills, the issue and PR templates, `dev/development/`, `docs/`, README, AGENTS.md and CLAUDE.md, and every file of `dev/mvp/`, the decisions, research notes and evidence reports included.
- Living documents hold no history (AGENTS.md "Documents: current state, history in git"; spec style rule 12). The MVP spec lost every legacy reference, ruling date and "merged/retired/changed vs" note, its `updated` dates, its removed-ID lists (each kind now names its next free ID, each use case its next free flow ID) and the `Source`/`Decided` sections of backlog items. Accessibility is not an MVP question.
- **Every document records outcomes, not the conversation** (AGENTS.md "Documents", WORKFLOW "Document rules" rule 7, build style rule 14): a decision is written as its **result** or `pending`, **never who decided or when**, and a section that only records a review is not kept. The templates replace their "PO ruling (date)" columns with **Outcome** or **Đọc là**; **decided planning deltas and design rulings leave their table**. The first build's testing records, decision records DEC-001 to DEC-013 and research items are **cleaned of that trail**; a reading that lived only in a ruling log moves to the ambiguities (AM-9).
- **The test analysis splits into three files**: `test-analysis.md` keeps the **counts per spec**, quality risks, types, mechanisms and ambiguities; the register rows move to **`basis-register.md`** and the sentence map to **`sentence-map.md`** (new templates). **Scope rulings move** to the matrix section **"Items not tested"**, and the **cross-reference check records only a mismatch that changes something**.

- The spec, research, decisions, templates and workflow moved into `dev/mvp/`: the current spec is the MVP spec, with no target/version layers. `dev/mvp/README.md` holds the MVP status. `WORKFLOW.md` moved to `dev/mvp/WORKFLOW.md`.
- Acceptance criteria and NFR measures are written per build in its testing plan, after research, not in the spec. The FR and NFR templates lost those sections; the testing-plan template gained them.
- Phase 0 is MVP planning (build order, milestone `mvp`, walking skeleton); version close became MVP close, followed by a review of the workflow. A review of the workflow follows the first build.
- "Legacy source" became "Reference code": the legacy code and the OpenCode code on `feat/v2-opencode` are read at a pinned commit; the MVP code is written new, so port tickets and the `legacy:port` label are gone.
- The research of Claude Slide Design, Napkin AI and OpenDesign (EthanGuo2022) moved from `dev/legacy/` to `dev/mvp/research/evidence/`.
- The **use case interaction diagram is now the source** of each step's text: a **`U->>S` line** for the user and a **`Note over U,S` box** for the system, each **starting with its step ID** (`[S1]`), with a **wider, left-aligned layout**. The **Steps table keeps only Step, FR and Evidence**. The skill `use-case-sequence` that generated the diagram is **removed**; `spec-authoring` **checks that the diagram and the table hold the same steps**.

- The previous docs moved from `docs/` to `dev/legacy/` unchanged; `docs/AGENTS.md` became `dev/legacy/docs-rules.md`.
- `AGENTS.md`, `CLAUDE.md` and `README.md` replaced by the workflow versions. The README keeps the instructions to run the legacy app.
- The skills in `.agents/skills/` replaced by the workflow set (15 skills). The skill manifest now names `use-case-sequence` and lists `commit`.
- The `commit` and `commit-push` skills no longer add a `Co-Authored-By` trailer for an AI agent.
